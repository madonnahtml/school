Il linguaggio JSON

JSON è il modo più usato oggi per scrivere dei dati in forma di testo e mandarli da un programma all'altro. Vediamo com'è fatto, quali sono le sue regole e come si usa con JavaScript.

In una frase JSON (JavaScript Object Notation) è un formato di testo standard e aperto per rappresentare e scambiare dati strutturati. È leggero e si legge facilmente sia da una persona sia da un programma.

Perché serve un formato per i dati

Immagina che un'app sul telefono chieda a un server i dati di uno studente. Il server ha questi dati in memoria, ma non può spedire "la memoria": deve trasformarli in una sequenza di caratteri, mandarli in rete e l'app dall'altra parte deve saperli rimettere insieme. Per farlo, entrambi devono usare le stesse regole di scrittura. JSON è proprio questo insieme di regole.

{
  "nome": "Luca",
  "eta": 18,
  "studente": true
}

Anche senza sapere niente di JSON si capisce cosa c'è scritto: uno studente che si chiama Luca e ha 18 anni. È questo il suo punto di forza.

Testuale e leggero

È solo testo, senza parti inutili: occupa poco e viaggia veloce in rete.

Indipendente dal linguaggio

È nato con JavaScript, ma oggi lo usano Java, C#, Python, PHP, C e quasi tutti gli altri linguaggi. Qualsiasi linguaggio che sa analizzare una stringa può leggere JSON.

Fatto per lo scambio

È il formato tipico delle API e delle applicazioni web per passare dati tra client e server.

Un paragoneJSON è come un modulo prestampato che tutti gli uffici del mondo sanno leggere: chiunque lo compili, chiunque lo riceva sa dove trovare il nome, l'età e così via. Non importa che lingua parli l'ufficio (Java, Python, PHP…).

XML e JSON a confronto

Prima di JSON, per scambiare dati si usava soprattutto XML, un linguaggio a tag simile all'HTML. Ecco gli stessi dati scritti nei due modi:

XML

<studente>
  <nome>Luca</nome>
  <eta>18</eta>
  <studente>true</studente>
</studente>

Ogni dato ha un tag di apertura e uno di chiusura: il nome del campo si scrive due volte.

JSON

{
  "nome": "Luca",
  "eta": 18,
  "studente": true
}

Il nome del campo si scrive una volta sola. Meno caratteri, stessa informazione.

Le due strutture di JSON

Tutto JSON si costruisce con solo due strutture:

Oggetto { }

Un insieme di coppie (nome, valore). Ogni valore si ritrova tramite il suo nome.

Come una carta d'identità: "Nome: Maria", "Cognome: Rossi"…

Array [ ]

Una lista ordinata di valori. Ogni valore si ritrova tramite la sua posizione.

Come la lista della spesa: primo, secondo, terzo…

Avere solo queste due strutture è un vantaggio: praticamente tutti i linguaggi hanno già qualcosa di simile (record, struct, dizionari, mappe per le coppie; array e liste per le sequenze). Per questo JSON si traduce facilmente in qualsiasi linguaggio.

Com'è fatto un oggetto

{
  "nome": "Maria",
  "cognome": "Rossi",
  "eta": 18
}
{ }

Le parentesi graffe aprono e chiudono l'oggetto.

"chiave": valore

Ogni proprietà è una chiave e il suo valore, separati dai due punti.

,

Le proprietà sono separate da una virgola. Dopo l'ultima proprietà la virgola non si mette.

Le regole da non sbagliare

  • La chiave va sempre tra doppi apici: "nome", mai nome né 'nome'.
  • Le stringhe usano solo i doppi apici ", mai gli apici singoli '.
  • Niente virgola dopo l'ultimo elemento (né negli oggetti, né negli array).
  • Niente commenti: in JSON non esistono // o /* */.
  • Dentro uno stesso oggetto le chiavi dovrebbero essere tutte diverse.

Sbagliato

{
  nome: 'Maria',      // chiave senza apici, apici singoli, commento
  "eta": 18,          // virgola finale
}

Corretto

{
  "nome": "Maria",
  "eta": 18
}
Errore classicoUn solo carattere sbagliato (una virgola in più, un apice dimenticato) rende tutto il file non valido: il programma che lo legge si ferma con un errore. Per controllare si può incollare il testo in un validatore JSON online, o usare un editor come VS Code che segna l'errore in rosso.

Attenzione agli apici"18" e 18 non sono la stessa cosa: il primo è una stringa (testo), il secondo un numero. Lo stesso vale per "true" (stringa) e true (booleano). Un programma che fa "18" + 1 in JavaScript ottiene "181", non 19!
Cosa non c'è in JSONNon esistono un tipo "data" né un tipo "carattere". Le date si scrivono come stringhe, di solito nel formato ISO: "2026-10-08".

Gli array

{
  "materie": [
    "Informatica",
    "Matematica",
    "Inglese"
  ]
}
  • Un array è racchiuso tra parentesi quadre [ ].
  • I valori sono separati da virgole (e niente virgola dopo l'ultimo).
  • Può contenere stringhe, numeri, booleani, null, oggetti o altri array.
  • L'ordine conta: ["a", "b"] è diverso da ["b", "a"]. Il primo elemento ha posizione (indice) 0.
Graffe o quadre?Chiediti: "ogni valore ha un nome?" → oggetto { }. "È un elenco di cose dello stesso tipo?" → array [ ]. Lo studente (nome, età, classe) è un oggetto; le sue materie sono un array.

Oggetti annidati

Il valore di una proprietà può essere a sua volta un oggetto. Si dice che l'oggetto è annidato (uno dentro l'altro, come le matrioske).

{
  "studente": {
    "nome": "Luca",
    "classe": "5A",
    "indirizzo": {
      "via": "Roma",
      "citta": "Torino"
    }
  }
}

L'oggetto indirizzo sta dentro studente, che sta dentro l'oggetto principale. Si ottiene una struttura gerarchica, ad albero, che tiene insieme le informazioni collegate tra loro:

(radice)
└── studente
    ├── nome: "Luca"
    ├── classe: "5A"
    └── indirizzo
        ├── via: "Roma"
        └── citta: "Torino"
AttenzioneOgni livello deve rispettare la sintassi JSON: parentesi chiuse nell'ordine giusto, doppi apici, due punti e virgole. Indentare bene (rientrare ogni livello di due spazi) aiuta molto a non perdersi.

Array di oggetti

È la struttura che vedrai più spesso: un elenco di elementi, ognuno descritto da un oggetto con le stesse proprietà. È come una tabella: l'array sono le righe, le chiavi sono le colonne.

{
  "studenti": [
    { "nome": "Anna", "voto": 8 },
    { "nome": "Luca", "voto": 7 },
    { "nome": "Sara", "voto": 9 }
  ]
}
indicenomevoto
0Anna8
1Luca7
2Sara9
  • studenti è un array;
  • ogni elemento dell'array è un oggetto;
  • ogni oggetto ha le proprietà nome e voto.

Quando un server restituisce un elenco di record (i prodotti di un negozio, i risultati di una query sul database, i messaggi di una chat) usa quasi sempre questa forma.

JSON nelle applicazioni web

  1. Il client invia una richiesta al server.
  2. Il server elabora la richiesta e recupera o modifica i dati.
  3. Il server restituisce una risposta in formato JSON.
  4. JavaScript legge la risposta e aggiorna la pagina senza ricaricarla tutta.
  5. Lo stesso formato si può usare tra applicazioni diverse: la stessa API può servire il sito, l'app Android e quella iPhone.

JSON e JavaScript

Un dato JSON che arriva dalla rete è solo una stringa, un pezzo di testo: non si può scrivere dati.nome finché non lo si trasforma in un oggetto. JavaScript ha due funzioni per passare da una forma all'altra:

JSON.stringify()

Da oggetto JavaScript a stringa JSON. Si usa per spedire o salvare i dati.

Impacchetto il dato per spedirlo.

JSON.parse()

Da stringa JSON a oggetto JavaScript. Si usa quando i dati arrivano.

Spacchetto il dato per usarlo.

const studente = {
  nome: "Luca",
  eta: 18
};

// oggetto → stringa
const testo = JSON.stringify(studente);
console.log(testo);          // {"nome":"Luca","eta":18}
console.log(typeof testo);   // "string"

// stringa → oggetto
const oggetto = JSON.parse(testo);
console.log(oggetto.nome);   // Luca
console.log(oggetto.eta + 1); // 19

Per accedere ai dati annidati si concatenano punti e indici:

const dati = JSON.parse('{"studenti":[{"nome":"Anna","voto":8},{"nome":"Luca","voto":7}]}');

console.log(dati.studenti.length);    // 2
console.log(dati.studenti[1].nome);   // Luca

// media dei voti
let somma = 0;
for (const s of dati.studenti) somma += s.voto;
console.log(somma / dati.studenti.length); // 7.5

Esempio reale: chiedere dati a un server con fetch, che fa la richiesta HTTP e con .json() esegue il JSON.parse per noi.

const risposta = await fetch("/api/studenti");
const studenti = await risposta.json();   // come JSON.parse(testo della risposta)
console.log(studenti[0].nome);
Da ricordareJSON è un formato di dati, JavaScript è un linguaggio di programmazione: non sono la stessa cosa. Un oggetto JavaScript può contenere funzioni, chiavi senza apici, apici singoli e commenti; il JSON no. JSON ha preso in prestito da JavaScript solo il modo di scrivere gli oggetti.
Se il JSON è sbagliatoJSON.parse su una stringa non valida lancia un errore (SyntaxError). Nei programmi veri si mette dentro un try … catch: 
try {
  const obj = JSON.parse(testoRicevuto);
} catch (e) {
  console.log("JSON non valido:", e.message);
}

Mappa riassuntiva

  • JSON = formato di testo, standard e aperto, per rappresentare e scambiare dati strutturati; indipendente dal linguaggio.
  • Si usa per API, file di configurazione, microservizi, dati in tempo reale, preferenze utente.
  • Rispetto a XML è più piccolo, più semplice e più leggibile.
  • Due strutture: oggetto { "chiave": valore } e array [ valore, valore ].
  • Sei tipi: stringa, numero, booleano, null, oggetto, array.
  • Si possono annidare: oggetti dentro oggetti, array di oggetti → struttura ad albero.
  • In JavaScript: JSON.stringify() oggetto → stringa, JSON.parse() stringa → oggetto.

01Trova gli errori facile
{
  nome: "Giulia",
  'classe': "4B",
  "eta": "17",
  "promossa": True,
  "materie": ["TPSIT", "Sistemi",],
}

Questo testo non è JSON valido. Trova tutti gli errori (e un punto che è valido ma probabilmente sbagliato).

Soluzione
  • nome: la chiave deve stare tra doppi apici → "nome".
  • 'classe': apici singoli non ammessi → "classe".
  • True: i booleani sono minuscoli → true.
  • Virgola dopo "Sistemi" e dopo l'array: virgole finali non ammesse.
  • "17" è valido, ma è una stringa: se l'età è un numero va scritta 17.
{
  "nome": "Giulia",
  "classe": "4B",
  "eta": 17,
  "promossa": true,
  "materie": ["TPSIT", "Sistemi"]
}

06Da XML a JSON medio
<libro>
  <titolo>I promessi sposi</titolo>
  <autore>Alessandro Manzoni</autore>
  <anno>1840</anno>
  <capitoli>38</capitoli>
</libro>

Riscrivi gli stessi dati in JSON. Quanti caratteri risparmi, più o meno?

Soluzione
{
  "libro": {
    "titolo": "I promessi sposi",
    "autore": "Alessandro Manzoni",
    "anno": 1840,
    "capitoli": 38
  }
}

In XML ogni nome di campo compare due volte (tag di apertura e di chiusura); in JSON una volta sola. Qui si risparmiano circa 30 caratteri: su migliaia di record la differenza diventa grande.
