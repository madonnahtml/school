Il linguaggio XML

XML è un modo di scrivere dei dati in un file di testo, usando dei tag che ne spiegano il significato. Vediamo a cosa serve, come si scrive e quali regole rispettare perché un programma riesca a leggerlo.

In una frase XML (eXtensible Markup Language, "linguaggio di marcatura estensibile") è un insieme di regole per creare formati di testo facili da generare e facili da elaborare da un computer. Serve a descrivere e organizzare i dati, non a mostrarli.

Perché serve XML

I programmi, i database e i fogli elettronici di solito memorizzano i dati ognuno a modo suo, in formati incompatibili tra loro. Se due sistemi diversi devono scambiarsi delle informazioni, uno dei due dovrebbe capire il formato dell'altro.

La soluzione è mettersi d'accordo su un solo formato comune: ogni sistema converte i suoi dati in XML e legge gli XML degli altri. Così la comunicazione diventa molto più semplice.

Senza ambiguità

I dati sono scritti in modo strutturato e leggibile: si capisce sempre dove inizia e dove finisce ogni informazione.

Estendibile

I tag li inventa il programmatore, in base al significato dei dati. Si possono aggiungere nuovi campi o cambiare la struttura senza rompere i programmi che già leggono il file.

Indipendente dalla piattaforma

Non dipende né dall'hardware né dal software: serve per memorizzare, trasportare e scambiare informazioni tra programmi diversi.

Un paragoneXML è come una scheda con le etichette: accanto a ogni dato c'è scritto cos'è ("nome", "prezzo", "email"). Chi la riceve non deve indovinare, basta che legga le etichette.

Un metalinguaggio di markup

Cos'è un linguaggio di markup

Un linguaggio di markup è un insieme di convenzioni per decidere quali parti di un documento vanno trattate in modo diverso dalle altre. È come quando a scuola sottolinei i titoli e metti in evidenziatore le parole chiave: stai "marcando" il testo.

L'idea è di inserire nel testo dei codici speciali, detti markup tag o semplicemente tag, che permettono ai programmi di distinguere le varie parti del documento (per esempio per decidere come visualizzarlo).

E XML?

  • XML è un metalinguaggio di markup: un linguaggio che permette di definire altri linguaggi di markup.
  • Non ha tag predefiniti: i nomi dei tag li scegli tu.
  • Non serve né a programmare né a costruire pagine web: è un insieme standard di regole sintattiche per descrivere la struttura di documenti e dati.
  • Rappresenta contenuti testuali organizzati in modo gerarchico (uno dentro l'altro, ad albero).
  • Le specifiche ufficiali sono definite dal W3C (World Wide Web Consortium).
  • Un documento XML è un documento di testo: si legge e si modifica con qualsiasi editor di testo e ha estensione .xml.
Perché "meta"?HTML ha una lista fissa di tag (<p>, <h1>, <img>…). XML invece non ti dà nessun tag: ti dà solo le regole per scriverli. Con quelle regole puoi creare il tuo linguaggio, per esempio uno per le rubriche e uno per i libri di una biblioteca. Un linguaggio che serve a creare altri linguaggi è un "meta"linguaggio.

All'inizio XML nacque per risolvere un problema di standard sul Web, ma essendo molto generale venne subito usato nei contesti più diversi: dalla descrizione della struttura dei documenti allo scambio di informazioni tra sistemi diversi.

Cosa NON è XML

Per non confondersi, ecco quello che XML non è:

XML non è…Perché
Un linguaggio di presentazione come HTMLIl markup XML definisce il significato dei dati e non dice nulla sul loro stile.
Un linguaggio di programmazione come JavaUn documento XML non è in grado di eseguire calcoli.
Un protocollo di trasporto come HTTPXML non trasferisce i dati attraverso la rete: sono altri protocolli a farlo.
Un DBMS come Access o MySQLXML non memorizza e non recupera i dati: li descrive soltanto.
Collegamento con HTTPXML è puro testo, quindi può viaggiare dentro il corpo di una richiesta o di una risposta HTTP, con l'header Content-Type: application/xml. Ma è HTTP a fare il trasporto, XML è solo il "contenuto". Vedi Il protocollo HTTP.

XML e HTML a confronto

XML e HTML si assomigliano perché entrambi usano i tag, ma hanno scopi diversi.

XMLHTML
Descrive i datiPresenta i dati
Serve per descrivere e organizzare le informazioniServe per visualizzare le informazioni
Tag definiti dall'autoreElementi standard

HTML: come si vede

<p><b>Paolo Canagni</b></p>

<p> e <b> dicono al browser come mostrare il testo (paragrafo, grassetto). Non dicono cosa sia "Paolo Canagni".

XML: cosa significa

<persona>
  <nome>Paolo</nome>
  <cognome>Canagni</cognome>
</persona>

I tag dicono cosa sono i dati (un nome, un cognome), ma non come mostrarli.

Per questo con XML i dati sono separati dalla loro rappresentazione grafica: lo stesso file XML può essere mostrato in tanti modi diversi (o non mostrato affatto, ma solo elaborato da un programma).

I file XML: vantaggi e svantaggi

I file in formato XML:

  • permettono di separare i dati dalla rappresentazione grafica;
  • hanno un unico insieme di regole di sintassi, che permette di leggere e scrivere i contenuti nello stesso modo e con strumenti analoghi;
  • sono basati su tag del tipo <nome></nome>: i tag permettono di trovare le informazioni in base al loro nome e non per forza alla loro posizione;
  • possono avere associata una definizione della struttura, che li rende più leggibili e permette di verificare in fretta se sono scritti correttamente.
VantaggiSvantaggi
Si possono creare linguaggi ad hoc per ogni esigenzaMolto più ingombranti dei documenti in formato binario
Testuale: facile da leggere e da modificare
Strutture dati indipendenti dalla piattaformaPiù onerosi in termini di risorse: tempi di trasmissione, memoria e tempo di CPU per la codifica
Si trasporta con HTTP perché è puro testo
Il prezzo della chiarezzaOgni dato porta con sé la sua etichetta, due volte (apertura e chiusura). Il file è molto leggibile ma pesa di più di un formato compatto. Per questo oggi nelle applicazioni web si usa spesso JSON, che dice le stesse cose con meno caratteri.

La sintassi: prologo e corpo

Un documento XML è formato da due parti:

  1. Prologo (o dichiarazione): contiene la dichiarazione XML e, se serve, il riferimento ad altri documenti che ne definiscono la struttura o a direttive di elaborazione.
  2. Corpo: è il documento XML vero e proprio, cioè i dati.
<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
<rubrica>
    <persona>
        <nome>Paolo</nome>
        <cognome>Canagni</cognome>
        <email>paolo@canagni.it</email>
    </persona>
</rubrica>
Dichiarazione XML

La prima riga: indica la versione e la codifica dei caratteri del documento.

Elemento radice

<rubrica> contiene tutto il documento.

Elementi

<persona>, <nome>, <email>… rappresentano i dati.

Il prologo

<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
ParteCosa indica
versionLa versione di XML usata (di solito "1.0").
encodingLa codifica dei caratteri, cioè come sono salvate lettere e accenti. UTF-8 è la più comune; nell'esempio della rubrica si vede anche ISO-8859-1.
standaloneDice se il documento è autosufficiente ("yes") o se ha bisogno di una definizione esterna della struttura, cioè una DTD associata ("no").
Nota sulle slideNelle slide l'esempio mostra standalone=«yes/no» con le virgolette francesi: serve solo a dire "scegli uno dei due". Nel file vero si scrive "yes" oppure "no" con i normali doppi apici. L'attributo standalone è facoltativo e il prologo si può anche omettere, ma se c'è deve essere scritto bene e essere la primissima cosa del file.

Il corpo

Il corpo deve essere una gerarchia di tag non sovrapposti: i tag che si aprono per ultimi devono chiudersi per primi, e ogni tag deve avere la sua chiusura. Come le scatole dentro altre scatole: non puoi chiudere la scatola grande lasciando aperta quella piccola.

<catalogo>
    <libro>
        <titolo>Il nome della rosa</titolo>
        <autore>Umberto Eco</autore>
        <anno>1980</anno>
    </libro>
</catalogo>

Deve sempre esserci un solo tag che racchiude tutti gli altri: si chiama root (radice). Qui è <catalogo>.

I tag e gli elementi

<nome>Paolo</nome>

<persona>
    ...
</persona>
Tag di apertura

<nome> indica l'inizio dell'elemento.

Contenuto

Paolo è il valore contenuto nell'elemento.

Tag di chiusura

</nome> chiude l'elemento. Il nome deve corrispondere.

L'insieme di tag di apertura + contenuto + tag di chiusura si chiama elemento. Il contenuto di un elemento può essere un testo (Paolo) oppure altri elementi (come in <persona>).

Maiuscole e minuscoleI tag sono case sensitive: <Nome> e <nome> sono due tag diversi. Se apri con <Nome> devi chiudere con </Nome>.

Elementi vuoti

Se un elemento non ha contenuto si può scrivere in forma abbreviata, con una sola parte che si chiude da sola: <nometag/>.

<telefono_lavoro></telefono_lavoro>     <!-- forma estesa -->
<telefono_lavoro/>                          <!-- forma abbreviata, equivalente -->

Gli attributi

<prodotto codice="1234">
    <nome>Quaderno</nome>
    <prezzo>3.50</prezzo>
</prodotto>
Attributo

Fornisce informazioni aggiuntive associate al tag.

Sintassi

nome="valore": il valore è racchiuso tra virgolette (doppie o singole) nel tag di apertura.

Quando usarlo

Per le caratteristiche identificative o i metadati dell'elemento (un codice, un id, una lingua…).

Gli attributi si scrivono solo nel tag di apertura, mai in quello di chiusura. Un elemento può averne più di uno, separati da spazi: <libro id="7" lingua="it">.

Attributo o elemento figlio?

Lo stesso dato si può scrivere in due modi:

Come attributo

<prodotto codice="1234">
    <nome>Quaderno</nome>
</prodotto>

Come elemento figlio

<prodotto>
    <codice>1234</codice>
    <nome>Quaderno</nome>
</prodotto>
Regola praticaSe è il dato vero e proprio (nome, prezzo, descrizione) usa un elemento. Se è un'etichetta o un identificativo che descrive l'elemento (codice, id) puoi usare un attributo. Un attributo contiene solo testo semplice e non può avere figli, mentre un elemento può contenere altri elementi.

Commenti e caratteri speciali

I commenti si scrivono come in HTML e il programma li ignora:

<!-- Questo è un commento -->

I caratteri < e & hanno un significato speciale (iniziano un tag o un'entità), quindi non si possono scrivere direttamente nel testo. Si usano delle sequenze al loro posto, dette entità:

Documento ben formato e documento valido

In XML ci sono due tipi di regole:

  • le regole sintattiche: come bisogna scrivere le informazioni nei documenti. Sono obbligatorie;
  • le regole semantiche: cosa si può scrivere in un documento. Possono esserci, ma non è obbligatorio rispettarle.

Ben formato (well-formed)

Rispetta le regole sintattiche.

È scritto in modo corretto.

Valido

Rispetta le regole sintattiche e le regole semantiche.

È scritto in modo corretto e dice le cose giuste.

Da ricordareUn documento valido è per forza ben formato, ma un documento ben formato può non essere valido rispetto a una grammatica.

Le regole per un documento ben formato

  • Deve contenere una dichiarazione corretta.
  • Il corpo deve avere un unico elemento radice (esclusi eventuali commenti).
  • Ogni elemento deve avere un tag di apertura e uno di chiusura; se l'elemento è vuoto si può usare la forma abbreviata <nometag/>.
  • Gli elementi devono essere nidificati bene: i tag di chiusura seguono l'ordine inverso di quelli di apertura.
  • I nomi dei tag di apertura e chiusura devono coincidere, anche in maiuscole e minuscole.
  • I nomi dei tag non devono iniziare con il carattere underscore (_) o con un numero e non devono contenere spazi.
  • I valori degli attributi devono sempre essere racchiusi tra apici singoli o doppi.
Errore classicoSe un documento XML non è ben formato, il programma che lo legge (il parser) si ferma con un errore e non legge niente. XML è molto più severo di HTML: i browser perdonano molti errori nelle pagine web, un parser XML no.

Come si controlla la validità: DTD e XSD

Aggiunta alle slide. Le regole semantiche si scrivono in un file a parte, detto grammatica, associato al documento. Le due più usate sono:

  • la DTD (Document Type Definition): più antica e semplice, dice quali elementi esistono e come sono annidati; la studiamo nel capitolo Lo schema DTD;
  • l'XSD (XML Schema): più moderna e potente, può anche indicare i tipi dei dati (per esempio "anno deve essere un numero").

Un programma di validazione confronta il documento con la grammatica e dice se la rispetta. Se la rispetta, il documento è valido.

La gerarchia degli elementi

Gli elementi di un documento XML sono nodi di una struttura ad albero: c'è la radice, che ha dei figli, che a loro volta possono averne altri.

Radice
├── Figlio1
│   ├── Figlio1_1
│   └── Figlio1_2
├── Figlio2
│   ├── Figlio2_1
│   ├── Figlio2_2
│   └── Figlio2_3
└── Figlio3
    └── Figlio3_1
  • Il genitore (o padre) è l'elemento che ne contiene un altro: <persona> è genitore di <nome>.
  • I figli sono gli elementi contenuti direttamente: <nome> e <cognome> sono figli di <persona>.
  • Gli elementi con lo stesso genitore sono fratelli.
  • L'unico elemento senza genitore è la radice.
Come un albero di cartelleÈ la stessa idea delle cartelle del computer: una cartella principale, che contiene altre cartelle, che ne contengono altre. Se sai muoverti tra le cartelle, sai muoverti in un file XML. È la stessa struttura ad albero vista in JSON.

Un esempio completo

Supponiamo di voler scambiare informazioni di un database su internet, per esempio un questionario compilato dagli utenti, e inviarle al server. Serve un formato che si possa personalizzare per l'uso specifico: XML è la soluzione ideale, e la sua rappresentazione è molto semplice.

<?xml version="1.0" encoding="ISO-8859-1"?>
<rubrica>
    <persona>
        <nome>Paolo</nome>
        <cognome>Canagni</cognome>
        <telefono_casa>0288888888</telefono_casa>
        <telefono_lavoro>0299999999</telefono_lavoro>
        <indirizzo_email>paolo@canagni.it</indirizzo_email>
    </persona>
    <persona>
        <nome>Riccardo</nome>
        <cognome>Nikolasey</cognome>
        <telefono_casa>0277777777</telefono_casa>
        <telefono_lavoro>0299999999</telefono_lavoro>
        <indirizzo_email>riccardo@nikolasey.it</indirizzo_email>
    </persona>
</rubrica>
  1. La prima riga indica la versione di XML e il set di caratteri usato.
  2. La riga successiva descrive l'elemento radice del documento: rubrica.
  3. L'elemento rubrica ha come figlio persona (ripetuto una volta per ogni persona), che a sua volta si compone di altri elementi figli: nome, cognome, telefono_casa e così via.
Perché telefono_casa con il trattino basso?I nomi dei tag non possono contenere spazi: <telefono casa> sarebbe un errore. Per nomi di più parole si usa il trattino basso (telefono_casa) oppure si scrivono attaccate con le maiuscole (telefonoCasa). L'importante è scegliere un modo e usarlo sempre, ricordando che le maiuscole contano.

Come passare da un dato a XML? Un metodo semplice: 1) trova il contenitore principale (la radice); 2) cerca gli elementi che si ripetono (le "righe", come persona); 3) per ognuno elenca i campi (le "colonne") e dai a ciascuno un tag con il suo nome.

Mappa riassuntiva

  • XML = insieme di regole per creare formati di testo facili da generare e da elaborare; descrive i dati (HTML li presenta).
  • È un metalinguaggio di markup: non ha tag predefiniti, i tag li sceglie l'autore. Lo standard è del W3C; i file sono testo con estensione .xml.
  • Vantaggi: estendibile, testuale, indipendente dalla piattaforma, trasportabile con HTTP. Svantaggi: ingombrante e più costoso in risorse.
  • Non è un linguaggio di presentazione, di programmazione, un protocollo di trasporto né un DBMS.
  • Un documento ha un prologo (<?xml version="1.0" encoding="UTF-8"?>) e un corpo con un solo elemento radice.
  • Tag di apertura e chiusura che coincidono (case sensitive), nidificati nell'ordine giusto; i valori degli attributi sempre tra apici.
  • Ben formato = rispetta la sintassi. Valido = rispetta anche la grammatica (DTD/XSD). Valido ⇒ ben formato, ma non viceversa.
  • La struttura è un albero: radice, genitori, figli.

03Trova gli errori facile
<?xml version="1.0" encoding="UTF-8"?>
<Libreria>
    <libro>
        <titolo>Il nome della rosa</titolo>
        <autore>Umberto Eco<anno>1980</autore></anno>
    </libro>
    <libro codice=12>
        <1titolo>Se questo è un uomo</1titolo>
        <autore>Primo Levi</Autore>
    </libro>
</libreria>

Questo documento non è ben formato. Trova tutti gli errori.

Soluzione
  • <Libreria> si chiude con </libreria>: maiuscole diverse, i nomi non coincidono (case sensitive).
  • <autore>Umberto Eco<anno>1980</autore></anno>: i tag sono sovrapposti. Si chiude prima </anno> e poi </autore>. In più anno sta dentro autore ma non è un dato dell'autore: va messo accanto, come figlio di libro.
  • codice=12: il valore dell'attributo deve stare tra apici → codice="12".
  • <1titolo>: il nome di un tag non può iniziare con un numero → <titolo>.
  • </Autore>: maiuscola diversa dal tag di apertura <autore> → </autore>.
<?xml version="1.0" encoding="UTF-8"?>
<libreria>
    <libro>
        <titolo>Il nome della rosa</titolo>
        <autore>Umberto Eco</autore>
        <anno>1980</anno>
    </libro>
    <libro codice="12">
        <titolo>Se questo è un uomo</titolo>
        <autore>Primo Levi</autore>
    </libro>
</libreria>
04Ben formato o valido? facile

Per ogni affermazione dì se è vera o falsa: a) un documento valido è sempre ben formato; b) un documento ben formato è sempre valido; c) un documento con due elementi radice può essere ben formato; d) <Nome>Anna</nome> è un elemento corretto; e) XML serve per mostrare i dati a video.

Soluzione

a) Vera: per essere valido deve rispettare anche le regole sintattiche. b) Falsa: può rispettare la sintassi ma non la grammatica (DTD/XSD). c) Falsa: il corpo ha un unico elemento radice. d) Falsa: apertura e chiusura devono coincidere, anche nelle maiuscole. e) Falsa: XML descrive i dati; è HTML che li presenta.

05Attributi o elementi? medio

Scrivi in XML un prodotto con codice A-17, nome "Penna blu", prezzo 1.20 e disponibile (sì). Usa il codice come attributo e gli altri dati come elementi figli. Poi riscrivi tutto senza attributi.

Soluzione
<!-- con attributo -->
<prodotto codice="A-17">
    <nome>Penna blu</nome>
    <prezzo>1.20</prezzo>
    <disponibile>si</disponibile>
</prodotto>

<!-- senza attributi -->
<prodotto>
    <codice>A-17</codice>
    <nome>Penna blu</nome>
    <prezzo>1.20</prezzo>
    <disponibile>si</disponibile>
</prodotto>

Ricorda: in XML non esistono i tipi (tutto è testo), quindi true o si sono solo testo che i programmi devono interpretare.

06Da XML a JSON medio
<persona>
    <nome>Paolo</nome>
    <cognome>Canagni</cognome>
    <email>paolo@canagni.it</email>
</persona>

Riscrivi gli stessi dati nel formato JSON.

Soluzione
{
  "persona": {
    "nome": "Paolo",
    "cognome": "Canagni",
    "email": "paolo@canagni.it"
  }
}

Ogni elemento XML con figli diventa un oggetto JSON; ogni elemento con solo testo diventa una coppia "chiave": valore. Il nome del campo si scrive una volta sola invece di due.
