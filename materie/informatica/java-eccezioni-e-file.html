Prima di cominciareServono classi, oggetti e metodi: se non sono chiari, ripassa Java: programmazione a oggetti. Le eccezioni sono oggetti, quindi quella pagina è la base.

Cosa sono le eccezioni

In una frase Un'eccezione è un evento imprevisto che si verifica mentre il programma è in esecuzione e che interrompe il normale flusso delle istruzioni. Java permette di gestirla in modo ordinato, evitando che il programma si fermi di colpo.

Tre tipi di errore, da non confondere

TipoQuando si scopreEsempio
Errore di sintassiAlla compilazione: il programma nemmeno partepunto e virgola mancante, variabile non dichiarata
Errore di logicaMai, da solo: il programma gira ma dà un risultato sbagliatomedia calcolata dividendo per il numero sbagliato
EccezioneDurante l'esecuzione, a causa dei dati o dell'ambientedivisione per zero, file inesistente, testo al posto di un numero

Il codice di un'eccezione può essere perfettamente corretto: è il mondo esterno (l'utente, il disco, la rete) a creare il problema. Per questo non basta "scrivere bene il programma": bisogna anche prevedere cosa può andare storto.

L'esempio classico: la divisione per zero

int a = 10;
int b = 0;
int risultato = a / b;                       // qui nasce l'eccezione
System.out.println("Risultato: " + risultato);  // non viene mai eseguita

Eseguendo questo codice il programma si ferma alla riga della divisione e Java stampa:

Exception in thread "main" java.lang.ArithmeticException: / by zero
	at Main.main(Main.java:4)

Il messaggio dice che tipo di eccezione è (ArithmeticException), perché (/ by zero) e dove (Main.java, riga 4). Tutte le istruzioni dopo l'errore non vengono eseguite.

Solo con gli interiLa divisione per zero lancia l'eccezione solo con i numeri interi. Con i double non succede niente di drammatico: 10.0 / 0 dà Infinity e 0.0 / 0 dà NaN (Not a Number).

L'eccezione è un oggetto

In Java un'eccezione è un oggetto che viene "lanciato" (thrown) nel momento in cui si verifica una condizione anomala. Ogni tipo di errore ha la sua classe: ArithmeticException, NullPointerException, IOException…

L'oggetto lanciato risale i metodi, da quello in cui è nato a quello che lo ha chiamato, e così via, finché qualcuno lo cattura. Se nessuno lo fa, arriva in cima e il programma termina con il messaggio che hai visto sopra.

Un paragoneÈ come una patata bollente. L'errore nasce in un metodo che non sa cosa farne e la passa a chi lo ha chiamato, che la passa al suo chiamante… finché un metodo dice "ci penso io" (catch). Se nessuno la prende, la patata arriva fino al sistema e il programma si ferma.

La gerarchia delle eccezioni

Le classi di eccezione sono parenti tra loro: formano un albero. Ti serve per capire quale catch cattura cosa.

Throwable
├── Error                          ← guasti gravi: non si gestiscono
│   ├── OutOfMemoryError
│   └── StackOverflowError
└── Exception
    ├── RuntimeException           ← UNCHECKED (il compilatore non obbliga)
    │   ├── ArithmeticException
    │   ├── NullPointerException
    │   ├── ArrayIndexOutOfBoundsException
    │   └── IllegalArgumentException
    │       └── NumberFormatException
    ├── IOException                ← CHECKED (il compilatore obbliga)
    │   ├── FileNotFoundException
    │   └── FileSystemException
    │       ├── NoSuchFileException
    │       └── FileAlreadyExistsException
    └── SQLException               ← CHECKED
  • Throwable è la radice: tutto ciò che si può lanciare ne discende.
  • Error: guasti della macchina virtuale (memoria finita, ricorsione infinita). Non si cattura: non c'è niente di sensato da fare.
  • Exception: i problemi che un programma può e deve gestire. È la famiglia di cui parla questa pagina.
  • RuntimeException e tutte le sue figlie sono le eccezioni unchecked; le altre figlie di Exception sono checked (lo vediamo più avanti).
Regola della parentelaUna NumberFormatException è anche una IllegalArgumentException, una RuntimeException, una Exception e una Throwable. Perciò un catch (Exception e) cattura quasi tutto: quando prendi una classe, prendi anche tutte le sue figlie. Questa è la ragione per cui l'ordine dei catch conta.

try, catch e finally

Il meccanismo per gestire le eccezioni si basa su tre blocchi:

try

Contiene il codice rischioso, quello che potrebbe lanciare un'eccezione.

catch

Contiene il codice che gestisce l'errore, eseguito solo se l'eccezione si verifica.

finally

Contiene le operazioni finali (pulizie), eseguite sempre.

Struttura base

try {
    // codice rischioso
} catch (TipoEccezione e) {
    // gestione dell'errore
} finally {
    // operazioni finali
}

Un esempio completo

try {
    int r = 10 / 0;
    System.out.println(r);
} catch (ArithmeticException e) {
    System.out.println("Non puoi dividere per zero!");
} finally {
    System.out.println("Esecuzione terminata.");
}

Output:

Non puoi dividere per zero!
Esecuzione terminata.

Cosa succede, passo per passo

  1. Java entra nel blocco try ed esegue le istruzioni una alla volta.
  2. Alla riga 10 / 0 nasce un oggetto ArithmeticException e l'esecuzione del try si interrompe subito: la riga System.out.println(r) non viene eseguita.
  3. Java cerca un catch che accetti quel tipo di eccezione, lo trova ed esegue il suo blocco.
  4. Qualunque cosa sia successa, esegue il blocco finally.
  5. Il programma continua normalmente con le istruzioni dopo il try-catch-finally.
Un paragoneUn funambolo (try) cammina sul filo. Se cade, c'è la rete (catch) che lo raccoglie e lo spettacolo continua. Che sia caduto o no, alla fine l'assistente smonta il filo (finally).

I tre scenari

Cosa succede nel trytrycatchfinallyDopo
Nessuna eccezionetuttosaltatosìcontinua
Eccezione del tipo del catchfino all'erroresìsìcontinua
Eccezione di un altro tipofino all'erroresaltatosìil programma si ferma (l'eccezione risale)
A cosa serve finallySenza try-catch il programma si interromperebbe nel punto dell'errore. Con finally puoi rilasciare risorse, chiudere connessioni o fare pulizie, sia che sia andato tutto bene, sia che sia arrivata un'eccezione. Viene eseguito anche se nel try c'è un return.
AttenzioneUna variabile dichiarata dentro il try esiste solo lì dentro (è lo scope del blocco): non puoi usarla nel catch né dopo. Se serve fuori, dichiarala prima del try. E non scrivere mai un catch vuoto { }: l'errore sparirebbe in silenzio e sarebbe impossibile da trovare.

Approfondimento: try-with-resources

Cose come lo Scanner o i file vanno chiuse quando hai finito. Invece di scrivere la chiusura in un finally, si può mettere la risorsa tra parentesi dopo try: Java la chiude da solo, anche in caso di errore.

try (Scanner scanner = new Scanner(System.in)) {
    int n = Integer.parseInt(scanner.nextLine());
    System.out.println(n * 2);
}   // lo scanner viene chiuso qui automaticamente

L'oggetto Exception e più catch

L'oggetto eccezione

Nell'intestazione del catch, (ArithmeticException e) dichiara una variabile, di solito chiamata e, che contiene l'oggetto eccezione lanciato. Con questo oggetto si possono chiedere informazioni dettagliate:

try {
    int x = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println(e);                  // tipo + messaggio
    System.out.println(e.getMessage());     // solo il messaggio
    e.printStackTrace();                    // la "mappa" dell'errore (per il debug)
}
IstruzioneCosa produce
System.out.println(e)java.lang.ArithmeticException: / by zero
e.getMessage()/ by zero
e.getClass().getSimpleName()ArithmeticException
e.printStackTrace()tipo, messaggio e tutta la catena di chiamate (vedi sotto)

Leggere lo stack trace

printStackTrace() è prezioso durante il debug perché mostra esattamente dove si è verificato l'errore. Supponi che main chiami f1(), che chiama f2(), dove c'è la divisione per zero:

java.lang.ArithmeticException: / by zero
	at Main.f2(Main.java:11)     ← qui è successo l'errore
	at Main.f1(Main.java:8)      ← f1 aveva chiamato f2
	at Main.main(Main.java:4)    ← main aveva chiamato f1

Si legge dall'alto in basso: la prima riga dice dove è nato l'errore, le righe sotto dicono chi aveva chiamato chi, fino al main. È la strada che la "patata bollente" ha percorso al contrario.

Quando un programma si bloccaNon spaventarti davanti a un muro di righe rosse: cerca la prima riga (il tipo di errore e il messaggio) e la prima riga che contiene il nome di un tuo file. Quasi sempre il problema è lì.

Gestire più eccezioni

Un try può avere più blocchi catch, uno per ogni tipo di errore che vuoi trattare in modo diverso.

try {
    int[] n = {10, 20, 30};
    System.out.println(n[10]);
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Indice non valido!");
} catch (Exception e) {
    System.out.println("Errore generico.");
}
  • Java prova i catch dall'alto verso il basso e ne esegue uno solo: il primo che accetta il tipo dell'eccezione.
  • I catch più specifici vanno prima di quelli generici. Exception, che cattura quasi tutto, va per ultimo.
Se sbagli l'ordineMettere catch (Exception e) prima di catch (ArrayIndexOutOfBoundsException e) non è solo una cattiva idea: non compila. Il compilatore protesta con exception ArrayIndexOutOfBoundsException has already been caught, perché il secondo blocco non potrebbe mai essere raggiunto.

Un solo catch per più tipi

Se due tipi di errore si gestiscono allo stesso modo, si possono unire con la barra verticale |:

try {
    // ...
} catch (NumberFormatException | ArithmeticException e) {
    System.out.println("Dati non validi: " + e.getMessage());
}

Anche questa è un'aggiunta alle slide. I due tipi uniti non possono essere uno figlio dell'altro.

Checked e Unchecked Exceptions

Java divide le eccezioni in due grandi famiglie, che si comportano in modo diverso rispetto al compilatore.

Unchecked

Derivano da RuntimeException. Il compilatore non obbliga a gestirle.

  • ArithmeticException
  • NullPointerException
  • ArrayIndexOutOfBoundsException
  • NumberFormatException
String s = "abc";
int n = Integer.parseInt(s);
// NumberFormatException

Checked

Il compilatore obbliga a gestirle con try-catch, oppure a dichiararle con throws.

  • IOException (file)
  • FileNotFoundException
  • SQLException (database)
public static void leggi()
        throws IOException {
    // il chiamante deve gestire
}

Perché due famiglie?

  • Le unchecked sono quasi sempre errori del programmatore: un indice sbagliato, un null dimenticato. La soluzione è scrivere meglio il codice (controllare prima), non riempirlo di try-catch.
  • Le checked sono imprevisti del mondo esterno, che possono capitare anche se il codice è perfetto: il file non c'è, il disco è pieno, il database non risponde. Java ti costringe a pensarci, perché ignorarle sarebbe pericoloso.
Un paragoneUn'unchecked è come inciampare perché non guardavi dove mettevi i piedi: colpa tua, si evita facendo attenzione. Una checked è come trovare la strada chiusa per lavori: non è colpa tua, ma devi avere un piano B scritto prima di partire.

Cosa dice il compilatore

Se chiami un metodo che può lanciare una checked e non fai niente, il programma non compila:

String s = Files.readString(Path.of("x.txt"));
// error: unreported exception IOException; must be caught or declared to be thrown

L'errore dice proprio le due strade possibili: catturarla (try-catch) o dichiararla (throws). Al contrario, un catch di una checked che il try non può mai lanciare è un errore: exception IOException is never thrown in body of corresponding try statement.

Due parole quasi uguali, ma molto diverse:

throw: generare un'eccezione

La parola chiave throw permette di generare esplicitamente un'eccezione nel proprio codice, quando si accorge che una condizione non è accettabile.

public static void controllaEta(int eta) {
    if (eta < 0) {
        throw new IllegalArgumentException("Età non valida");
    }
    System.out.println("Età: " + eta);
}

controllaEta(-5);   // genera l'eccezione

throw interrompe subito il metodo, come un return di emergenza: la riga con la println non viene eseguita. Chi chiama il metodo può catturare l'eccezione:

try {
    controllaEta(-5);
} catch (IllegalArgumentException e) {
    System.out.println("Errore: " + e.getMessage());   // Errore: Età non valida
}
Perché lanciare e non stampare?Il metodo controllaEta non sa cosa fare di un'età sbagliata: chiedere di nuovo? uscire? ignorare? Lo decide chi lo ha chiamato. Il metodo si limita a segnalare il problema con throw, il chiamante lo gestisce con catch.

throws: dichiarare un'eccezione

throws si usa nella firma del metodo per avvisare chi lo chiama che può verificarsi un'eccezione checked.

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

public static void leggiFile() throws IOException {
    // codice che può generare IOException
    Path p = Path.of("dati.txt");
    String testo = Files.readString(p);
    System.out.println(testo);
}

Chi chiama leggiFile() deve gestire l'eccezione con try-catch oppure dichiararla a sua volta con throws:

// Strada 1: la gestisco io
public static void main(String[] args) {
    try {
        leggiFile();
    } catch (IOException e) {
        System.out.println("Non riesco a leggere il file: " + e.getMessage());
    }
}

// Strada 2: la passo al mio chiamante
public static void main(String[] args) throws IOException {
    leggiFile();
}
Occhio alla strada 2Se main stesso scrive throws, l'eccezione risale fino alla macchina virtuale e, se si verifica, il programma si ferma con lo stack trace. Va bene per fare prove veloci, ma in un programma vero conviene sempre gestire l'errore con un catch e dare all'utente un messaggio comprensibile.

Lavorare con i file: Path e Files

Il package java.nio.file offre le classi Path e Files per gestire i file in modo moderno e sicuro.

Path

Rappresenta il percorso (l'indirizzo) di un file o di una cartella. Non apre né crea niente: è solo un indirizzo.

Files

Contiene i metodi statici che fanno le operazioni: leggere, scrivere, cancellare, controllare… su un Path.

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardOpenOption;
import java.util.List;
NotaPath.of(...) e Files.readString(...) / Files.writeString(...) richiedono Java 11 o superiore.

Creare un Path

Path file = Path.of("dati.txt");
Path cartella = Path.of("dati", "file.txt");   // dati/file.txt

Con più argomenti Java mette da solo il separatore giusto (/ o \ a seconda del sistema). Un percorso come "dati.txt" è relativo: parte dalla cartella da cui lanci il programma (la working directory).

Scrivere un file

Files.writeString(file, "Ciao Java!");
// crea il file se non esiste
Attenzione: sovrascrive!Se il file esiste già, writeString cancella tutto il contenuto vecchio e scrive il nuovo. Se vuoi aggiungere in fondo, serve APPEND (vedi sotto).

Leggere un file

String testo = Files.readString(file);            // tutto il file in una stringa
List<String> righe = Files.readAllLines(file);    // una stringa per ogni riga

readString è comodo per un testo breve; readAllLines per elaborare riga per riga (con un for, o con righe.size() e righe.get(i)).

Operazioni aggiuntive

OperazioneIstruzione
Aggiungere testo in fondoFiles.writeString(file, "Nuova riga\n", StandardOpenOption.CREATE, StandardOpenOption.APPEND);
Controllare se esisteif (Files.exists(file)) { ... }
Eliminare un fileFiles.deleteIfExists(file);
Creare una cartellaFiles.createDirectory(Path.of("dati"));
Il trabocchetto di APPENDNelle slide l'esempio usa solo StandardOpenOption.APPEND. Ma APPEND da solo non crea il file: se non esiste ancora, Java lancia NoSuchFileException. Per "aggiungi in fondo, e se il file non c'è, crealo" servono entrambe: CREATE, APPEND.
  • Il \n alla fine del testo manda a capo: senza, la riga successiva si attacca alla precedente.
  • deleteIfExists restituisce true se ha cancellato, false se il file non c'era (e non lancia errore). Files.delete invece lancia NoSuchFileException se manca.
  • createDirectory lancia FileAlreadyExistsException se la cartella c'è già, e NoSuchFileException se manca la cartella "genitore". Per creare più livelli insieme esiste createDirectories.

Mini-progetto: Registro studenti

Un programma completo con menu interattivo che salva i dati su file e gestisce tutte le eccezioni. Le quattro voci del menu:

VoceCosa fa
1 · InserisciLegge un nome da tastiera e lo aggiunge al file studenti.txt (con CREATE, APPEND).
2 · VisualizzaLegge tutte le righe del file e le stampa numerate. Gestisce il caso di file assente.
3 · CancellaElimina il file con deleteIfExists() e gestisce eventuali errori di I/O.
4 · EsciTermina il programma chiudendo correttamente lo Scanner.

Le due idee chiave

do {
    System.out.println("1. Inserisci");
    System.out.println("2. Visualizza");
    System.out.println("3. Cancella");
    System.out.println("4. Esci");
    scelta = Integer.parseInt(scanner.nextLine());
    // switch sulle scelte
} while (scelta != 4);

Il menu è un ciclo do-while: mostra le opzioni almeno una volta e si ripete finché l'utente non sceglie 4. Se l'utente scrive "abc" al posto di un numero, parseInt lancia una NumberFormatException:

} catch (NumberFormatException e) {
    System.out.println("Devi inserire un numero.");
    scelta = 0;
}

Con scelta = 0 il ciclo non esce (0 è diverso da 4) e il menu ricompare. Inoltre ogni operazione sul file ha il suo try-catch, separato, per isolare gli errori: se la lettura fallisce, l'inserimento continua a funzionare.

Il programma completo

Per tenere il codice ordinato ho messo ogni voce del menu in un metodo a parte (inserisci, visualizza, cancella).

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardOpenOption;
import java.util.List;
import java.util.Scanner;

public class RegistroStudenti {

    static final Path FILE = Path.of("studenti.txt");

    static void inserisci(Scanner scanner) {
        System.out.print("Nome dello studente: ");
        String nome = scanner.nextLine().trim();
        if (nome.isEmpty()) {
            System.out.println("Il nome non può essere vuoto.");
            return;
        }
        try {
            Files.writeString(FILE, nome + "\n",
                    StandardOpenOption.CREATE, StandardOpenOption.APPEND);
            System.out.println("Studente aggiunto.");
        } catch (IOException e) {
            System.out.println("Impossibile scrivere il file: " + e.getMessage());
        }
    }

    static void visualizza() {
        try {
            List<String> righe = Files.readAllLines(FILE);
            if (righe.isEmpty()) {
                System.out.println("Il registro è vuoto.");
                return;
            }
            for (int i = 0; i < righe.size(); i++) {
                System.out.println((i + 1) + ". " + righe.get(i));
            }
        } catch (IOException e) {
            System.out.println("Nessun registro trovato: inserisci prima uno studente.");
        }
    }

    static void cancella() {
        try {
            boolean eliminato = Files.deleteIfExists(FILE);
            System.out.println(eliminato ? "Registro cancellato." : "Non c'era nessun registro.");
        } catch (IOException e) {
            System.out.println("Impossibile cancellare il file: " + e.getMessage());
        }
    }

    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int scelta = 0;

        do {
            System.out.println();
            System.out.println("1. Inserisci");
            System.out.println("2. Visualizza");
            System.out.println("3. Cancella");
            System.out.println("4. Esci");
            System.out.print("Scelta: ");

            try {
                scelta = Integer.parseInt(scanner.nextLine());
                switch (scelta) {
                    case 1: inserisci(scanner); break;
                    case 2: visualizza(); break;
                    case 3: cancella(); break;
                    case 4: System.out.println("Arrivederci!"); break;
                    default: System.out.println("Scelta non valida (1-4).");
                }
            } catch (NumberFormatException e) {
                System.out.println("Devi inserire un numero.");
                scelta = 0;
            }
        } while (scelta != 4);

        scanner.close();
    }
}

Concetto fondamentaleUn programma reale combina sempre eccezioni + file. Prevedere che qualcosa possa andare storto rende il software robusto e professionale.

Mappa riassuntiva

  • Eccezione = oggetto lanciato a runtime quando succede un imprevisto; interrompe il flusso e risale i metodi finché qualcuno la cattura.
  • Gerarchia: Throwable → Error (non si gestisce) e Exception; RuntimeException è la famiglia delle unchecked.
  • try (codice rischioso) · catch (gestione) · finally (eseguito sempre).
  • Più catch: dal più specifico al più generale; se ne esegue uno solo. Exception per ultimo.
  • Oggetto e: getMessage(), printStackTrace() (si legge dall'alto: dove è nato l'errore).
  • Unchecked (RuntimeException): errori del programmatore, il compilatore non obbliga. Checked (IOException, SQLException): il compilatore obbliga a gestirle o dichiararle.
  • throw genera un'eccezione; throws dichiara nella firma che il metodo può lanciarla.
  • Path = indirizzo; Files = operazioni: writeString, readString, readAllLines, exists, deleteIfExists, createDirectory.
  • writeString sovrascrive; per aggiungere in fondo: CREATE, APPEND.
  • I metodi di Files lanciano IOException (checked): sempre dentro try-catch o con throws.

try {

    int x = 5 / 0;
    System.out.println("B");
} catch (ArithmeticException e) {
    System.out.println("C");
} finally {
    System.out.println("D");
}
System.out.println("E");
Soluzione

Stampa A, C, D, E, una per riga. Dopo A la divisione lancia l'eccezione: B viene saltata, il catch stampa C, il finally stampa D e il programma prosegue con E.

02Il catch sbagliato medio
try {
    String s = null;
    System.out.println(s.length());
} catch (ArithmeticException e) {
    System.out.println("X");
} finally {
    System.out.println("Y");
}
System.out.println("Z");

Cosa stampa? Arriva fino a Z?

Soluzione

Stampa Y, poi il programma si ferma con un errore NullPointerException; X e Z non compaiono mai.

s.length() lancia una NullPointerException, ma l'unico catch accetta ArithmeticException: non corrisponde, quindi viene saltato. Il finally però gira sempre (stampa Y) e subito dopo l'eccezione, non catturata, risale e termina il programma: la riga con Z non viene raggiunta. È il terzo scenario della tabella.

03Trova l'errore facile
try {
    int[] v = new int[3];
    v[5] = 1;
} catch (Exception e) {
    System.out.println("Errore generico");
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Indice non valido");
}
Soluzione

Il programma non compila: catch (Exception e) cattura già tutto, quindi il secondo catch non sarebbe mai raggiungibile (exception ArrayIndexOutOfBoundsException has already been caught). Vanno scambiati: prima il più specifico, poi il generico.

} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Indice non valido");
} catch (Exception e) {
    System.out.println("Errore generico");
}
04Checked o unchecked? facile

Classifica ciascuna eccezione come checked o unchecked: NumberFormatException, FileNotFoundException, NullPointerException, IOException, ArithmeticException, SQLException.

Soluzione

Unchecked (figlie di RuntimeException): NumberFormatException, NullPointerException, ArithmeticException.

Checked: FileNotFoundException (figlia di IOException), IOException, SQLException.

Regola pratica: parlano di file, rete o database? Sono quasi sempre checked. Sono errori di programmazione (numero, riferimento nullo, indice)? Unchecked.

05Una divisione sicura medio

Scrivi un metodo static int dividi(int a, int b) che lancia una IllegalArgumentException con il messaggio "Il divisore non può essere zero" se b vale 0, altrimenti restituisce a / b. Nel main chiamalo con (10, 2) e con (1, 0), gestendo l'errore con un try-catch.

Soluzione
static int dividi(int a, int b) {
    if (b == 0) {
        throw new IllegalArgumentException("Il divisore non può essere zero");
    }
    return a / b;
}

public static void main(String[] args) {
    try {
        System.out.println(dividi(10, 2));   // 5
        System.out.println(dividi(1, 0));    // lancia l'eccezione
    } catch (IllegalArgumentException e) {
        System.out.println("Errore: " + e.getMessage());
    }
}

Output: 5 e poi Errore: Il divisore non può essere zero. Il metodo segnala il problema con throw, il main lo gestisce con catch. Non serve throws perché IllegalArgumentException è unchecked.

06Chiedi un numero finché è valido medio

Scrivi un metodo static int leggiIntero(Scanner scanner) che chiede un numero intero e, se l'utente scrive qualcosa che non lo è (come abc, o 4.5, o niente), lo richiede finché non è valido.

Soluzione
static int leggiIntero(Scanner scanner) {
    while (true) {
        System.out.print("Inserisci un numero intero: ");
        String testo = scanner.nextLine();
        try {
            return Integer.parseInt(testo);
        } catch (NumberFormatException e) {
            System.out.println("\"" + testo + "\" non è un numero valido, riprova.");
        }
    }
}

Il ciclo while (true) si ripete all'infinito: l'unico modo di uscire è il return, che viene raggiunto solo se parseInt non lancia l'eccezione. Se la lancia, il catch stampa il messaggio e il ciclo ricomincia. È lo stesso trucco del menu del mini-progetto.

07Il contatore di avvii ragionamento

Scrivi un metodo che, a ogni esecuzione, conta quante volte il programma è stato avviato. Il numero è salvato nel file contatore.txt: se il file non c'è si parte da 0; se contiene qualcosa che non è un numero, si riparte da 0 avvisando l'utente. Stampa "Questo programma è stato avviato N volte."

Soluzione
static void contatore() {
    Path file = Path.of("contatore.txt");
    int avvii = 0;
    try {
        if (Files.exists(file)) {
            avvii = Integer.parseInt(Files.readString(file).trim());
        }
    } catch (NumberFormatException e) {
        System.out.println("File rovinato, riparto da zero.");
    } catch (IOException e) {
        System.out.println("Non riesco a leggere il file: " + e.getMessage());
    }

    avvii++;

    try {
        Files.writeString(file, String.valueOf(avvii));
        System.out.println("Questo programma è stato avviato " + avvii + " volte.");
    } catch (IOException e) {
        System.out.println("Non riesco a scrivere il file: " + e.getMessage());
    }
}
  • Chiamandolo tre volte stampa 1, 2, 3 volte; se il file contiene la parola rotto, avvisa e riparte da 1.
  • Ci sono due try-catch separati, uno per la lettura e uno per la scrittura, come nel mini-progetto.
  • I due catch della lettura sono in questo ordine ma potrebbero stare anche al contrario: NumberFormatException e IOException non sono parenti.
  • .trim() toglie spazi e \n ai bordi del testo letto; String.valueOf(avvii) trasforma il numero in stringa, perché writeString scrive testo.
  • Qui writeString deve sovrascrivere (vogliamo sostituire il vecchio numero), quindi niente APPEND.
08Estendi il registro: cerca uno studente completo

Aggiungi al mini-progetto la voce 5 · Cerca: legge un nome da tastiera e dice se è presente nel registro (senza distinguere maiuscole e minuscole). Gestisci il caso di file assente.

Soluzione

Si aggiunge un metodo (qui il nome arriva come parametro, il main lo legge con lo scanner):

static void cerca(String nome) {
    try {
        List<String> righe = Files.readAllLines(FILE);
        boolean trovato = false;
        for (String riga : righe) {
            if (riga.equalsIgnoreCase(nome)) {
                trovato = true;
            }
        }
        System.out.println(trovato ? nome + " è nel registro." : nome + " non c'è.");
    } catch (IOException e) {
        System.out.println("Nessun registro trovato.");
    }
}

Nel menu si aggiungono la riga System.out.println("5. Cerca"); e il caso del switch:

case 5:
    System.out.print("Nome da cercare: ");
    cerca(scanner.nextLine().trim());
    break;

Il do-while continua a uscire solo con 4, quindi la condizione non cambia. equalsIgnoreCase confronta le stringhe ignorando maiuscole e minuscole: con un registro che contiene Luca, cercare luca trova lo studente.
