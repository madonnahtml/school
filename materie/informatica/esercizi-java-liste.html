Collections Framework e generics

Ripasso lampoIl Java Collections Framework è l'insieme di interfacce e classi di java.util per gestire gruppi di oggetti. Tra le parentesi angolari scrivi il tipo degli elementi: List<String>, List<Integer> (solo classi, mai <int>). A destra basta il diamante <>. Teoria: Il Java Collections Framework.
01La lista della spesa facile

Consegna. Crea una lista di String vuota e aggiungi, in quest'ordine, "latte", "pane", "mele" e di nuovo "latte". Stampa la lista intera, quante voci contiene, la prima e l'ultima voce, e se contiene "pane" e "uova". Infine aggiungi "uova" e stampa di nuovo il numero di voci.

Vincolo: per l'ultima voce non scrivere get(3): deve funzionare con liste di qualsiasi lunghezza.

Output atteso:

Lista: [latte, pane, mele, latte]
Voci: 4
Prima voce: latte
Ultima voce: latte
Serve il pane? true
Servono le uova? false
Dopo l'aggiunta: 5 voci
Soluzione spiegata

Ragionamento

  1. Non so quante voci avrà la spesa: un array (lunghezza fissa) non va bene, una lista sì, perché cresce da sola.
  2. Dichiaro List<String> spesa = new ArrayList<>();: a sinistra l'interfaccia List, a destra la classe vera ArrayList; tra < > il tipo degli elementi.
  3. Ogni add(e) aggiunge in fondo. "latte" due volte va bene: una List ammette i duplicati.
  4. Il numero di voci è size() (con le parentesi: è un metodo). La prima voce è get(0), l'ultima get(size() - 1), come length - 1 negli array.
  5. Per sapere se una voce c'è uso contains, che restituisce un boolean.

Codice

import java.util.ArrayList;
import java.util.List;

public class Spesa {
    public static void main(String[] args) {
        List<String> spesa = new ArrayList<>();
        spesa.add("latte");
        spesa.add("pane");
        spesa.add("mele");
        spesa.add("latte");

        System.out.println("Lista: " + spesa);
        System.out.println("Voci: " + spesa.size());
        System.out.println("Prima voce: " + spesa.get(0));
        System.out.println("Ultima voce: " + spesa.get(spesa.size() - 1));
        System.out.println("Serve il pane? " + spesa.contains("pane"));
        System.out.println("Servono le uova? " + spesa.contains("uova"));

        spesa.add("uova");   // me le ero dimenticate: nessun problema
        System.out.println("Dopo l'aggiunta: " + spesa.size() + " voci");
    }
}

Da notare

  • System.out.println(spesa) stampa direttamente tutta la lista tra parentesi quadre: con un array, invece, avresti visto una scritta strana tipo [Ljava.lang.String;@1b6d3586.
  • L'ultima voce prima di aggiungere le uova è "latte" (la seconda volta): l'ordine di inserimento viene mantenuto.
  • Array contro lista: array.length (proprietà), stringa.length() (metodo di String), lista.size() (metodo di List). Tre nomi diversi per la stessa idea!

Soluzione spiegata

A · tra < > vanno solo classi

riga 6: error: unexpected type

"unexpected type" vuol dire "tipo inaspettato": nelle righe successive il compilatore precisa che voleva un tipo riferimento (una classe) e ha trovato il primitivo int. Le collezioni contengono solo oggetti. Correzione: List<Integer> numeri = new ArrayList<>();. La riga numeri.add(5) poi va benissimo: grazie all'autoboxing Java trasforma da solo 5 in un Integer.

B · il tipo lo controlla il compilatore

riga 8: error: incompatible types: int cannot be converted to String

La lista è dichiarata List<String>: accetta solo String. Il compilatore vede che 42 è un int e che non può diventare una String ("incompatible types: int cannot be converted to String" = tipi incompatibili, un int non si converte in String). È proprio il vantaggio dei generics: l'errore salta fuori quando compili, non mentre il programma gira. Correzione: nomi.add("42"); se volevi il testo, oppure una lista diversa per i numeri.

C · un'interfaccia non si crea con new

riga 5: error: List is abstract; cannot be instantiated

List è un'interfaccia: un contratto che dice cosa si può fare, non come ("is abstract; cannot be instantiated" = è astratta, non si può creare). Serve una classe che la implementi. Correzione: List<String> nomi = new ArrayList<>(); (e il relativo import java.util.ArrayList;).

RiassuntoA sinistra l'interfaccia (List), a destra la classe concreta (ArrayList, LinkedList, Vector), tra < > sempre una classe (Integer, Double, String…).

04La playlist medio

Consegna. Scrivi un programma che gestisce una playlist (una List<String>):

  1. parte vuota; aggiungi "Alba", "Mare", "Notte";
  2. inserisci "Pioggia" come seconda canzone;
  3. sostituisci "Notte" con "Notte (live)" senza scrivere a mano la sua posizione;
  4. prova a togliere "Vento" (che non c'è) e "Mare", stampando cosa restituisce ogni remove;
  5. stampa la playlist numerata a partire da 1;
  6. svuotala e controlla che sia vuota.

Output atteso:

Tolgo Vento: false
Tolgo Mare: true
1. Alba
2. Pioggia
3. Notte (live)
Vuota? true (size 0)
Soluzione spiegata

Ragionamento

  1. "Seconda canzone" vuol dire posizione 1 (si conta da 0): add(1, "Pioggia"). La lista diventa [Alba, Pioggia, Mare, Notte].
  2. Per sostituire "Notte" mi serve la sua posizione: me la dà indexOf (qui 3). Poi set(pos, ...) mette il nuovo titolo al suo posto.
  3. remove("Vento") riceve una String, quindi è il remove per oggetto: non trova "Vento" e restituisce false, senza errori. remove("Mare") lo trova, lo toglie e restituisce true.
  4. Per numerare serve l'indice: for classico fino a size(), stampando i + 1.
  5. clear() svuota tutto; isEmpty() è come scrivere size() == 0, ma si legge meglio.

Codice

import java.util.ArrayList;
import java.util.List;

public class Playlist {
    public static void main(String[] args) {
        List<String> playlist = new ArrayList<>();
        playlist.add("Alba");
        playlist.add("Mare");
        playlist.add("Notte");

        // b) "Pioggia" diventa la seconda canzone (posizione 1)
        playlist.add(1, "Pioggia");

        // c) sostituisco "Notte" senza sapere a memoria dov'è
        int pos = playlist.indexOf("Notte");
        playlist.set(pos, "Notte (live)");

        // d) remove per oggetto restituisce true o false
        System.out.println("Tolgo Vento: " + playlist.remove("Vento"));
        System.out.println("Tolgo Mare: " + playlist.remove("Mare"));

        // e) stampa numerata
        for (int i = 0; i < playlist.size(); i++) {
            System.out.println((i + 1) + ". " + playlist.get(i));
        }

        // f) svuoto tutto
        playlist.clear();
        System.out.println("Vuota? " + playlist.isEmpty() + " (size " + playlist.size() + ")");
    }
}

Errori da evitare

  • Scrivere playlist.set(3, "Notte (live)") a mano: funziona oggi, ma se prima cambi l'ordine delle canzoni sostituisci quella sbagliata. Con indexOf il programma si adatta.
  • Se indexOf restituisce -1 (canzone che non c'è), set(-1, ...) lancia IndexOutOfBoundsException. In un programma vero si controlla prima: if (pos != -1).
  • (i + 1) va tra parentesi, altrimenti Java attacca il testo: "01. Alba", "11. Pioggia"…

Dentro ArrayList: size e capacità

Ripasso lampoDentro un ArrayList c'è un normale array, un po' più grande del necessario. La size è quanti elementi ci sono davvero; la capacità è quanti ne entrano prima di dover creare un array più grande e copiare tutto. Inserire in mezzo costa perché bisogna spostare gli elementi successivi. Teoria: ArrayList: l'array dinamico.
06Capacità non è size facile

Consegna. Un compagno crea una lista "da 50 posti" e pensa di poter leggere subito il secondo posto. Prevedi l'output e spiega l'errore.

List<String> posti = new ArrayList<>(50);
System.out.println(posti.size());
System.out.println(posti.isEmpty());
posti.add("Anna");
System.out.println(posti.size() + " " + posti.get(0));
try {
    System.out.println(posti.get(1));
} catch (IndexOutOfBoundsException e) {
    System.out.println("Errore: " + e.getMessage());
}
Soluzione spiegata

Output

0
true
1 Anna
Errore: Index 1 out of bounds for length 1

Spiegazione

  • new ArrayList<>(50) crea una lista vuota: il 50 è la capacità iniziale, cioè lo spazio preparato in anticipo nell'array interno. La size è 0 e isEmpty() è true.
  • Dopo add("Anna") la size è 1: esiste solo la posizione 0.
  • get(1) chiede una posizione che non esiste (anche se nell'array interno c'è posto): IndexOutOfBoundsException. Il messaggio "Index 1 out of bounds for length 1" parla della size (1), non della capacità (50).
Differenza con gli arrayCon new int[50] hai subito 50 caselle (piene di 0) e puoi leggerle tutte. Con new ArrayList<>(50) non hai nessun elemento: le posizioni nascono solo con add. La capacità serve solo a evitare ingrandimenti inutili se sai già che arriveranno tanti elementi.
07Costruisci il tuo ArrayList difficile

Consegna. Per capire davvero come funziona ArrayList, costruiscine uno tuo per i numeri interi, usando solo un array. Scrivi una classe ListaInteri con:

  • gli attributi int[] dati (l'array interno) e int size (quanti elementi ci sono davvero);
  • un costruttore che riceve la capacità iniziale;
  • void add(int x): aggiunge in fondo; se l'array è pieno ne crea uno più grande del 50%, copia tutto e stampa un messaggio;
  • int add(int pos, int x) (overload): inserisce in posizione pos spostando avanti gli altri e restituisce quanti elementi ha spostato;
  • int get(int i): lancia IndexOutOfBoundsException se i non è tra 0 e size - 1.

Nel main parti con capacità 4, aggiungi 10, 20, …, 100 e poi inserisci 5 in testa.

Output atteso:

add(10)
add(20)
add(30)
add(40)
add(50)
  piena! ingrandisco da 4 a 6
add(60)
add(70)
  piena! ingrandisco da 6 a 9
add(80)
add(90)
add(100)
  piena! ingrandisco da 9 a 13
size 10, capacità 13
add(0, 5) ha spostato 10 elementi
primo 5, ultimo 100

Soluzione spiegata

Ragionamento

  1. Servono due numeri diversi: dati.length è la capacità, size è quanti elementi ho messo. Il prossimo elemento va nella casella dati[size].
  2. L'array è pieno quando size == dati.length. Gli array non si allungano, quindi ne creo uno nuovo più grande (length + length / 2, cioè +50%), copio gli elementi con un ciclo e faccio puntare dati al nuovo array. Il vecchio verrà buttato via da Java.
  3. Per inserire in posizione pos devo fare posto: prima allungo la lista di uno (riuso add, così l'eventuale ingrandimento è già gestito), poi sposto ogni elemento di una casella in avanti partendo dal fondo, fino a pos. Infine scrivo x in dati[pos].
  4. In get controllo l'indice con la size, non con la capacità: le caselle oltre size esistono nell'array ma non fanno parte della lista.

Codice

class ListaInteri {
    int[] dati;
    int size;

    ListaInteri(int capacitaIniziale) {
        this.dati = new int[capacitaIniziale];
        this.size = 0;
    }

    // aggiunge in fondo: si ingrandisce se è piena
    void add(int x) {
        if (size == dati.length) {
            int nuovaCapacita = dati.length + dati.length / 2;   // circa +50%
            System.out.println("  piena! ingrandisco da " + dati.length + " a " + nuovaCapacita);
            int[] nuovo = new int[nuovaCapacita];
            for (int i = 0; i < size; i++) {
                nuovo[i] = dati[i];
            }
            dati = nuovo;
        }
        dati[size] = x;
        size++;
    }

    // inserisce in posizione pos: restituisce quanti elementi ha spostato
    int add(int pos, int x) {
        add(0);   // fa posto in fondo (e si ingrandisce se serve)
        int spostati = 0;
        for (int i = size - 1; i > pos; i--) {
            dati[i] = dati[i - 1];
            spostati++;
        }
        dati[pos] = x;
        return spostati;
    }

    int get(int i) {
        if (i < 0 || i >= size) {
            throw new IndexOutOfBoundsException("indice " + i + ", size " + size);
        }
        return dati[i];
    }
}

public class MiaLista {
    public static void main(String[] args) {
        ListaInteri l = new ListaInteri(4);
        for (int k = 1; k <= 10; k++) {
            System.out.println("add(" + (k * 10) + ")");
            l.add(k * 10);
        }
        System.out.println("size " + l.size + ", capacità " + l.dati.length);

        int spostati = l.add(0, 5);
        System.out.println("add(0, 5) ha spostato " + spostati + " elementi");
        System.out.println("primo " + l.get(0) + ", ultimo " + l.get(l.size - 1));
        System.out.println("size " + l.size + ", capacità " + l.dati.length);
    }
}

Leggere l'output

  • Capacità 4: i primi quattro add non spostano niente. Al quinto l'array è pieno: da 4 a 6. Al settimo da 6 a 9, al decimo da 9 a 13. Gli ingrandimenti sono rari: per questo add in fondo costa O(1) "in media" (ammortizzato).
  • add(0, 5) ha spostato 10 elementi, cioè tutti: inserire in testa costa O(n). Con un milione di elementi sarebbero un milione di spostamenti.
  • Lo spostamento parte dal fondo: se partissi dall'inizio, dati[1] = dati[0] cancellerebbe il valore di dati[1] prima di averlo copiato, e avresti tanti 10 uguali.
  • I due add sono un overload: stesso nome, parametri diversi (uno o due int). Lo fa anche il vero ArrayList.

Scorrere la lista: for, foreach e Iterator

Ripasso lampoTre modi: il foreach (il più leggibile, quando servono solo i valori), il for con indice (quando serve la posizione) e l'Iterator (hasNext(), next(), remove()), l'unico che permette di togliere elementi mentre scorri. Teoria: Scorrere la lista.
08Ripulire la chat medio

Consegna. La lista

List<String> chat = new ArrayList<>(List.of(
        "ciao", "", "OFFERTA!!!", "ci vediamo alle 5", "", "OFFERTA!!!", "ok"));

contiene i messaggi di una chat, compresi messaggi vuoti e spam. Usa tutti e tre i modi di scorrere, ognuno per il compito giusto:

  1. stampa ogni messaggio con la sua posizione, tra parentesi quadre (così si vedono i vuoti);
  2. togli i messaggi vuoti e quelli uguali a "OFFERTA!!!", contando quanti ne togli;
  3. calcola quanti caratteri ci sono in totale nei messaggi rimasti.

Output atteso:

0: [ciao]
1: []
2: [OFFERTA!!!]
3: [ci vediamo alle 5]
4: []
5: [OFFERTA!!!]
6: [ok]
Messaggi tolti: 4
Rimasti: [ciao, ci vediamo alle 5, ok]
Caratteri in totale: 23
Soluzione spiegata

Ragionamento: quale ciclo per quale compito?

  1. Stampare con la posizione: mi serve l'indice, quindi for classico con i < chat.size() e chat.get(i).
  2. Togliere mentre scorro: è il lavoro dell'Iterator. Lo chiedo alla lista con chat.iterator(); finché hasNext() è vero prendo il prossimo con next() e, se è da scartare, lo tolgo con it.remove() (dell'iteratore, non della lista!).
  3. Sommare le lunghezze: mi servono solo i valori, quindi foreach, il più semplice.

Codice

import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class Messaggi {
    public static void main(String[] args) {
        List<String> chat = new ArrayList<>(List.of(
                "ciao", "", "OFFERTA!!!", "ci vediamo alle 5", "", "OFFERTA!!!", "ok"));

        // 1) for con indice: mi serve la posizione
        for (int i = 0; i < chat.size(); i++) {
            System.out.println(i + ": [" + chat.get(i) + "]");
        }

        // 2) Iterator: tolgo mentre scorro
        int tolti = 0;
        Iterator<String> it = chat.iterator();
        while (it.hasNext()) {
            String m = it.next();
            if (m.isEmpty() || m.equals("OFFERTA!!!")) {
                it.remove();
                tolti++;
            }
        }
        System.out.println("Messaggi tolti: " + tolti);
        System.out.println("Rimasti: " + chat);

        // 3) foreach: mi servono solo i valori
        int caratteri = 0;
        for (String m : chat) {
            caratteri += m.length();
        }
        System.out.println("Caratteri in totale: " + caratteri);
    }
}

Da ricordare

  • next() va chiamato una sola volta per giro: salvo il risultato in m e poi lo controllo. Se scrivessi it.next().isEmpty() || it.next().equals(...) la seconda chiamata prenderebbe il messaggio successivo.
  • it.remove() toglie l'ultimo elemento restituito da next(); l'iteratore sa di averlo tolto e continua dal punto giusto.
  • Conto dei caratteri: "ciao" (4) + "ci vediamo alle 5" (17) + "ok" (2) = 23. Per l'Iterator serve import java.util.Iterator;.
09Trova l'errore: togliere i numeri pari difficile

Consegna. Due compagni vogliono togliere tutti i numeri pari da una lista. Nessuno dei due programmi funziona, ma sbagliano in modo diverso. Per ognuno: cosa succede, e perché? Poi scrivi la versione corretta.

A · con il foreach

Vector e la capacità incrementale

Ripasso lampoVector è come ArrayList (un array che si ingrandisce) ma con tutti i metodi synchronized: thread-safe e più lento. È legacy (Java 1.0). Di solito raddoppia; con new Vector<>(capacità, incremento) scegli tu di quanto cresce. Teoria: Vector: l'antenato thread-safe.

LinkedList: la lista di nodi

Ripasso lampoLinkedList non ha un array: ogni elemento sta in un nodo con un riferimento al precedente e uno al successivo. Conosce il primo e l'ultimo nodo, quindi lavorare sulle estremità è velocissimo (addFirst, addLast, removeFirst, removeLast, getFirst, getLast), mentre get(i) deve scorrere i nodi. Teoria: LinkedList: la lista concatenata.

LinkedList come pila e come coda

Ripasso lampoCon Deque<T> d = new LinkedList<>(); hai una sequenza a due estremità. Pila (LIFO, l'ultimo entrato esce per primo): push, pop, peek. Coda (FIFO, il primo entrato esce per primo): offer, poll, peek. Su una deque vuota poll/peek restituiscono null, remove/get lanciano NoSuchElementException. Teoria: LinkedList come pila e come coda.

16Trova la lentezza: get(i) su una LinkedList difficile

Consegna. Un programma somma 20 000 numeri contenuti in una LinkedList in due modi. Il risultato è identico, ma la prima versione è migliaia di volte più lenta. Spiega perché, calcolando quanti "passi tra i nodi" fa ciascuna versione, e scrivi un metodo che stimi i passi di get(i).

import java.util.LinkedList;
import java.util.List;

public class SommaLenta {

    // versione lenta su LinkedList: get(i) riparte ogni volta da un'estremità
    static long sommaConIndice(List<Integer> l) {
        long s = 0;
        for (int i = 0; i < l.size(); i++) {
            s += l.get(i);
        }
        return s;
    }

    // versione giusta: il foreach passa da un nodo al successivo
    static long sommaForEach(List<Integer> l) {
        long s = 0;
        for (int x : l) {
            s += x;
        }
        return s;
    }

    // quanti nodi attraversa in totale get(i) per i = 0 .. n-1
    static long passiGet(int n) {
        long passi = 0;
        for (int i = 0; i < n; i++) {
            if (i < n / 2) {
                passi += i;            // parte dalla testa
            } else {
                passi += n - 1 - i;    // parte dalla coda
            }
        }
        return passi;
    }

    public static void main(String[] args) {
        int n = 20000;
        List<Integer> lista = new LinkedList<>();
        for (int i = 0; i < n; i++) {
            lista.add(i);
        }
        System.out.println("Somma con get(i): " + sommaConIndice(lista));
        System.out.println("Somma con foreach: " + sommaForEach(lista));
        System.out.println("Passi tra i nodi con get(i): " + passiGet(n));
        System.out.println("Passi tra i nodi con foreach: " + n);
    }
}

Soluzione spiegata

Ragionamento

  1. Su una LinkedList non si può "saltare" alla posizione i: get(i) parte dal primo nodo (o dall'ultimo, se i è nella seconda metà) e segue le frecce una per una.
  2. Nel for con l'indice, get(i) riparte da capo a ogni giro: per i = 5000 fa 5000 passi, per i = 5001 ne fa 5001… Non ricorda dove era arrivato.
  3. Sommo i passi: per la prima metà i passi, per la seconda n - 1 - i (si parte dalla coda). È quello che calcola passiGet: quasi 100 milioni di passi, circa n²/4. Il costo totale è O(n²): O(n) per ogni get, ripetuto n volte.
  4. Il foreach usa un iteratore che resta sul nodo corrente e passa al successivo con un solo passo: in tutto n = 20 000 passi, O(n).

Soluzione spiegata

1 · Ragionamento

  1. Il parametro è List<String>: il metodo chiede solo "dammi una lista di stringhe", non quale. Così accetta ArrayList, LinkedList e Vector, che implementano tutte List.
  2. Dentro, scorro con il foreach (veloce con tutte e tre) e aggiungo a una lista nuova le parole con length() >= min.
  3. Anche il tipo restituito è List<String>: chi chiama il metodo non ha bisogno di sapere che dentro ho usato un ArrayList.
  4. new LinkedList<>(List.of(...)) e new Vector<>(List.of(...)) funzionano come new ArrayList<>(List.of(...)): creano una lista modificabile partendo da quei valori.

Codice

import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;
import java.util.Vector;

public class PerInterfaccia {

    static List<String> lunghe(List<String> parole, int min) {
        List<String> risultato = new ArrayList<>();
        for (String p : parole) {
            if (p.length() >= min) {
                risultato.add(p);
            }
        }
        return risultato;
    }

    static void stampa(String etichetta, List<String> l) {
        System.out.println(etichetta + " " + l + " -> " + lunghe(l, 5));
    }

    public static void main(String[] args) {
        List<String> a = new ArrayList<>(List.of("mela", "banana", "kiwi", "ciliegia"));
        List<String> b = new LinkedList<>(List.of("cane", "gatto", "criceto"));
        List<String> c = new Vector<>(List.of("sole", "luna", "pianeta"));

        stampa("LinkedList", b);
        stampa("Vector    ", c);

2 · Perché non compila

riga 16: error: incompatible types: LinkedList<String> cannot be converted to ArrayList<String>

Il parametro è ArrayList<String>: il metodo accetta solo ArrayList. Una LinkedList è una List, ma non è un ArrayList, quindi il compilatore rifiuta la chiamata ("incompatible types": tipi non compatibili). Correzione: static int contaVuote(List<String> l). Il corpo del metodo non cambia, perché usa solo cose che ogni List sa fare.

RegolaIl tipo concreto (ArrayList, LinkedList…) compare solo dopo il new. Ovunque altrove (variabili, parametri, tipo di ritorno) scrivi List<T>. Se ti servono i metodi delle estremità, usa Deque<T>.

Passo 1 · Progettare prima di scrivere

Prima di tutto scelgo la struttura giusta per ogni dato, guardando l'operazione che userò di più. È la parte più importante, ed è quella che si chiede nelle verifiche.

Passo 2 · La classe Libro

Tre attributi, un costruttore che usa this. per distinguere l'attributo dal parametro con lo stesso nome, e descrizione() che restituisce una String. smarrito parte sempre da false, quindi non serve passarlo al costruttore.

Passo 3 · Catalogo e donazioni

Dopo i tre add, add(0, ...) mette I Malavoglia in testa e fa scalare gli altri. Il Vector parte con capacità 2: al terzo libro è pieno e cresce di 2, quindi la capacità diventa 4 (con la size a 3). addAll(donati) aggiunge in fondo al catalogo tutti gli elementi del Vector, nell'ordine: si può fare perché anche il Vector è una collezione. Il catalogo arriva a 7 libri.

Passo 4 · Stampare e cercare (per interfaccia)

Entrambi i metodi ricevono una List<Libro>, non un ArrayList: funzionerebbero anche con il Vector delle donazioni. stampaCatalogo usa il for con indice perché deve numerare. cerca confronta i titoli con equals e restituisce la posizione appena lo trova; se il ciclo finisce senza trovarlo restituisce -1, come indexOf.

Perché non usare direttamente catalogo.indexOf(...)? Perché indexOf cerca un oggetto Libro uguale, mentre io ho solo il titolo. Per questo il punto 11 costruisce una lista di String, dove contains e indexOf funzionano direttamente.

Passo 5 · set, Iterator e remove

  • set: cerca trova Il barone rampante in posizione 1 (è scalato dopo l'inserimento in testa) e set(1, ...) lo sostituisce con il libro corretto. La size resta 7.
  • Iterator: segno i due libri come smarriti e poi togliSmarriti li toglie mentre scorre, come nell'esercizio della chat. Con un foreach e libri.remove(...) avrei una ConcurrentModificationException. Restano 5 libri.
  • remove per posizione: catalogo.remove(cerca(...)) riceve un int, quindi toglie per posizione e restituisce il libro tolto, che salvo in restauro. Restano 4 libri.

Passo 6 · Gli scaffali

scaffali.remove(1) toglierebbe l'elemento in posizione 1, che è proprio lo scaffale 1, per pura coincidenza! Con Integer.valueOf(1) tolgo il numero 1 ovunque si trovi: il codice è giusto per il motivo giusto, e resta giusto anche se cambia l'ordine degli scaffali. Risultato: [3, 4, 2].

Passo 7 · Coda e pila

  • Coda: tre offer in fondo; poll fa uscire Anna (la prima arrivata); peek mostra Bruno senza toglierlo, quindi in attesa restano 2 persone.
  • Pila: il foreach mette sul carrello i libri nell'ordine del catalogo (Il barone rampante, Uno nessuno e centomila, Il fu Mattia Pascal, Le città invisibili). L'ultimo appoggiato è in cima, quindi il while (!carrello.isEmpty()) con pop li riprende al contrario. Il ciclo si ferma quando la pila è vuota, così pop non lancia mai eccezioni.

Passo 8 · Le ricerche finali

Costruisco titoli con un foreach sul catalogo. Senilità è stato tolto all'inventario, quindi contains dà false; Le città invisibili è l'ultimo dei 4 libri, posizione 3.

Codice completo

import java.util.ArrayList;
import java.util.Deque;
import java.util.Iterator;
import java.util.LinkedList;
import java.util.List;
import java.util.Vector;

class Libro {
    String titolo;
    String autore;
    boolean smarrito;

    Libro(String titolo, String autore) {
        this.titolo = titolo;
        this.autore = autore;
        this.smarrito = false;
    }

    String descrizione() {
        return titolo + " (" + autore + ")";
    }
}

public class Biblioteca {

    // ---------- programmare per interfaccia: va bene qualsiasi List ----------
    static void stampaCatalogo(List<Libro> libri) {
        for (int i = 0; i < libri.size(); i++) {
            System.out.println("  " + (i + 1) + ". " + libri.get(i).descrizione());
        }
    }

    static int cerca(List<Libro> libri, String titolo) {
        for (int i = 0; i < libri.size(); i++) {
            if (libri.get(i).titolo.equals(titolo)) {
                return i;
            }
        }
        return -1;
    }

    // ---------- Iterator: togliere mentre si scorre ----------
    static int togliSmarriti(List<Libro> libri) {
        int tolti = 0;
        Iterator<Libro> it = libri.iterator();
        while (it.hasNext()) {
            Libro l = it.next();
            if (l.smarrito) {
                it.remove();
                tolti++;
            }
        }
        return tolti;
    }

    public static void main(String[] args) {
        // 1. il catalogo: ArrayList, perché si legge per posizione
        List<Libro> catalogo = new ArrayList<>();
        catalogo.add(new Libro("Il barone rampante", "Calvino"));
        catalogo.add(new Libro("La coscienza di Zeno", "Svevo"));
        catalogo.add(new Libro("Uno, nessuno e centomila", "Pirandello"));
        catalogo.add(0, new Libro("I Malavoglia", "Verga"));   // novità in testa

        // 2. le donazioni arrivano dal vecchio programma, che usa un Vector
        Vector<Libro> donati = new Vector<>(2, 2);
        donati.add(new Libro("Il fu Mattia Pascal", "Pirandello"));
        donati.add(new Libro("Senilità", "Svevo"));
        donati.add(new Libro("Le città invisibili", "Calvino"));
        System.out.println("Donati: " + donati.size() + " (capacità del Vector: " + donati.capacity() + ")");
        catalogo.addAll(donati);

        System.out.println("Catalogo, " + catalogo.size() + " libri:");
        stampaCatalogo(catalogo);

        // 3. correggere un dato con set
        int pos = cerca(catalogo, "Il barone rampante");
        catalogo.set(pos, new Libro("Il barone rampante", "Italo Calvino"));
        System.out.println("Corretto in posizione " + pos + ": " + catalogo.get(pos).descrizione());

        // 4. inventario: i libri smarriti si tolgono con l'Iterator
        catalogo.get(cerca(catalogo, "La coscienza di Zeno")).smarrito = true;
        catalogo.get(cerca(catalogo, "Senilità")).smarrito = true;
        System.out.println("Smarriti tolti: " + togliSmarriti(catalogo));

        // 5. un libro ritirato per restauro: remove per posizione restituisce il libro
        Libro restauro = catalogo.remove(cerca(catalogo, "I Malavoglia"));
        System.out.println("In restauro: " + restauro.descrizione());
        System.out.println("Catalogo, " + catalogo.size() + " libri:");
        stampaCatalogo(catalogo);

        // 6. gli scaffali: attenzione alla trappola di remove
        List<Integer> scaffali = new ArrayList<>(List.of(3, 1, 4, 2));
        scaffali.remove(Integer.valueOf(1));   // chiude lo scaffale NUMERO 1
        System.out.println("Scaffali aperti: " + scaffali);

        // 7. prenotazioni: coda FIFO
        Deque<String> prenotazioni = new LinkedList<>();
        prenotazioni.offer("Anna");
        prenotazioni.offer("Bruno");
        prenotazioni.offer("Carla");
        System.out.println("Prestito a: " + prenotazioni.poll());
        System.out.println("Prossimo: " + prenotazioni.peek() + " (in attesa: " + prenotazioni.size() + ")");

        // 8. carrello dei libri restituiti: pila LIFO
        Deque<Libro> carrello = new LinkedList<>();
        for (Libro l : catalogo) {
            carrello.push(l);
        }
        System.out.println("Rimetto a posto, dall'alto del carrello:");
        while (!carrello.isEmpty()) {
            System.out.println("  " + carrello.pop().titolo);
        }

        // 9. ricerche veloci su una lista di titoli
        List<String> titoli = new ArrayList<>();
        for (Libro l : catalogo) {
            titoli.add(l.titolo);
        }
        System.out.println("C'è Senilità? " + titoli.contains("Senilità"));
        System.out.println("Posizione di Le città invisibili: " + titoli.indexOf("Le città invisibili"));
    }
}
