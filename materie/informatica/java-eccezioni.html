Java: eccezioni

Un programma serio deve prevedere che qualcosa vada storto: un numero diviso per zero, un file che non c'è, un utente che scrive "abc" dove serviva un numero. Le eccezioni sono il modo di Java per accorgersene e reagire, senza che il programma si fermi di colpo.

Prima di cominciareServono le basi di Java: variabili, if, cicli, metodi e array. Se hai già visto Java: gestione dei file hai incontrato un primo try-catch: qui capiamo meglio come funzionano le eccezioni, in generale.

Cosa sono le eccezioni

In una fraseUn'eccezione è un evento imprevisto che si verifica durante l'esecuzione e interrompe il normale flusso del programma. Java la gestisce in modo strutturato, evitando la terminazione improvvisa dell'applicazione.

L'esempio classico è la divisione per zero:

int a = 10;
int b = 0;
int risultato = a / b;   // genera ArithmeticException
Exception in thread "main" java.lang.ArithmeticException: / by zero

Senza nessuna protezione, il programma si ferma in quella riga e le istruzioni successive non vengono mai eseguite. Il messaggio dice il tipo di errore (ArithmeticException) e il motivo (/ by zero).

Un paragoneUn'eccezione è come l'allarme antincendio: appena qualcosa va storto, suona e tutto si ferma. Il try-catch è il responsabile della sicurezza: sente l'allarme, decide cosa fare e fa ripartire le attività in modo ordinato.

L'eccezione è un oggetto

Dal punto di vista formale, un'eccezione è un oggetto Java che viene "lanciato" (thrown) quando si verifica una condizione anomala. Ogni tipo di errore ha la sua classe:

ClasseQuando succede
ArithmeticExceptionoperazione matematica impossibile (10 / 0)
NullPointerExceptionsi usa un oggetto che vale null (vedi programmazione a oggetti)
ArrayIndexOutOfBoundsExceptionindice fuori da un array (n[10] in un array di 3)
NumberFormatExceptiontesto non convertibile in numero (Integer.parseInt("abc"))
IOExceptionproblema di input/output, per esempio con i file

try, catch e finally

Il meccanismo si basa su tre blocchi: try contiene il codice rischioso, catch gestisce l'errore, finally esegue le operazioni finali.

try {
    // codice rischioso
} catch (TipoEccezione e) {
    // gestione dell'errore
} finally {
    // operazioni finali
}

Un esempio completo

try {
    int r = 10 / 0;
    System.out.println(r);
} catch (ArithmeticException e) {
    System.out.println("Non puoi dividere per zero!");
} finally {
    System.out.println("Esecuzione terminata.");
}
Non puoi dividere per zero!
Esecuzione terminata.

Cosa è successo, in ordine:

  1. Java entra nel try e prova 10 / 0: lancia un'ArithmeticException.
  2. La riga System.out.println(r) viene saltata: dopo l'errore il try si interrompe subito.
  3. Il controllo passa al catch che gestisce quel tipo di eccezione, e stampa il messaggio.
  4. Infine si esegue il finally, e poi il programma prosegue normalmente.
Il blocco finallyViene eseguito sempre: sia se l'eccezione c'è, sia se non c'è, sia se nel try c'è un return. Serve per rilasciare risorse, chiudere file o connessioni, fare pulizia. È facoltativo: si può scrivere try-catch senza finally (o anche try-finally senza catch).
Quasi "sempre"L'unico modo di saltare il finally è fermare del tutto il programma, per esempio con System.exit(0) dentro il try, o se il computer si spegne. (Precisazione aggiunta alle slide.)

finally per chiudere un file

L'uso classico è la chiusura di una risorsa: se close() sta nel try e prima c'è un errore, il file resta aperto; nel finally invece viene sempre eseguito.

FileReader lettore = null;
try {
    lettore = new FileReader("prova.txt");
    System.out.println((char) lettore.read());
} catch (IOException e) {
    System.out.println("Problema con il file");
} finally {
    try {
        if (lettore != null) {
            lettore.close();
        }
    } catch (IOException e) {
        System.out.println("Impossibile chiudere il file");
    }
}

È una forma lunga e noiosa: per questo Java ha introdotto il try-with-resources, che chiude da solo la risorsa (try (FileReader lettore = new FileReader("prova.txt")) { ... }). (Extra rispetto alle slide.)

L'oggetto Exception e più catch

L'oggetto eccezione

Nel catch la lettera e è una variabile che contiene l'oggetto eccezione: si può interrogare per avere informazioni.

try {
    int x = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println(e);              // tipo + messaggio
    System.out.println(e.getMessage()); // solo il messaggio
    e.printStackTrace();                // stack trace (debug)
}
IstruzioneCosa stampa
System.out.println(e)java.lang.ArithmeticException: / by zero (tipo e messaggio)
e.getMessage()/ by zero (solo il messaggio)
e.printStackTrace()l'intero percorso dell'errore, riga per riga, fino al punto in cui è nato

printStackTrace() è prezioso durante il debug perché mostra esattamente dove si è verificato l'errore: cerca la riga con il nome del tuo file e il numero di riga (per esempio Main.java:5).

Quale usare?printStackTrace() è utilissimo a te che programmi; getMessage() (o un messaggio tuo) è meglio per l'utente, che non deve vedere pagine di errori tecnici.

Gestire più eccezioni

Un try può avere più blocchi catch, uno per ogni tipo di errore. I catch più specifici vanno prima di quelli generici.

try {
    int[] n = {10, 20, 30};
    System.out.println(n[10]);
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Indice non valido!");
} catch (Exception e) {
    System.out.println("Errore generico.");
}

Qui l'indice 10 non esiste (l'array ha 3 elementi, indici 0, 1, 2): viene scelto il primo catch compatibile, cioè quello dell'array, e gli altri vengono ignorati.

Le eccezioni sono parentiException è la classe "madre" di quasi tutte le eccezioni: ArithmeticException, IOException… sono sue figlie. Un catch (Exception e) prende qualunque eccezione, ed è per questo che deve stare in fondo, come rete di sicurezza.
L'ordine contaSe metti catch (Exception e) prima di catch (ArrayIndexOutOfBoundsException e), il programma non compila (errore: exception has already been caught): il primo prenderebbe già tutto e il secondo non verrebbe mai raggiunto. Regola: dal più specifico al più generico.

Checked e unchecked exceptions

Java divide le eccezioni in due grandi famiglie, che si comportano in modo diverso con il compilatore.

Unchecked (non controllate)

Derivano da RuntimeException. Il compilatore non obbliga a gestirle.

  • ArithmeticException
  • NullPointerException
  • ArrayIndexOutOfBoundsException
  • NumberFormatException
String s = "abc";
int n = Integer.parseInt(s);
// NumberFormatException

Di solito sono errori di programmazione.

Checked (controllate)

Il compilatore obbliga a gestirle con try-catch o a dichiararle con throws.

  • IOException (file)
  • FileNotFoundException
  • SQLException (database)
public static void leggi()
        throws IOException {
    // il chiamante deve gestire
}

Di solito sono problemi del mondo esterno.

Il criterio è questo:

  • Unchecked: dipendono da come hai scritto il programma (dividere per zero, usare un null, sbagliare indice). Si prevengono scrivendo codice corretto: per esempio con un if (b != 0).
  • Checked: dipendono da cose fuori dal tuo controllo (un file cancellato, il disco pieno, la rete caduta). Non si possono evitare del tutto, quindi Java ti costringe a pensarci.
Per riconoscerleUna eccezione checked è una figlia di Exception ma non di RuntimeException. Se il compilatore si lamenta con "unreported exception … must be caught or declared to be thrown", hai una checked non gestita: o la racchiudi in un try-catch o la dichiari con throws.

throw e throws

throw: generare un'eccezione

Permette di generare esplicitamente un'eccezione nel proprio codice: tu stesso "lanci l'allarme" quando un dato non è valido.

throws: dichiarare un'eccezione

Si scrive nella firma del metodo per avvisare chi lo chiama che può verificarsi un'eccezione checked.

throw

public static void controllaEta(int eta) {
    if (eta < 0) {
        throw new IllegalArgumentException("Età non valida");
    }
    System.out.println("Età: " + eta);
}

// chiamata:
controllaEta(-5);   // genera l'eccezione

throw new ... crea l'oggetto eccezione (con un messaggio) e lo lancia: il metodo si interrompe subito e la riga System.out.println("Età: ...") non viene eseguita. Chi chiama il metodo può intercettare l'errore:

try {
    controllaEta(-5);
} catch (IllegalArgumentException e) {
    System.out.println("Errore: " + e.getMessage());   // Errore: Età non valida
}
Attenzione alla differenzathrow (senza s) è un'istruzione che lancia un'eccezione adesso; throws (con la s) è una dichiarazione nella firma del metodo. Una agisce, l'altra avvisa. IllegalArgumentException è unchecked, quindi qui non serve throws.

throws

public static void leggiFile() throws IOException {
    // codice che può generare IOException
    Path p = Path.of("dati.txt");
    String testo = Files.readString(p);
}

Chi chiama leggiFile() dovrà gestire l'eccezione con try-catch oppure dichiararla a sua volta:

// 1) la gestisce qui
public static void main(String[] args) {
    try {
        leggiFile();
    } catch (IOException e) {
        System.out.println("Impossibile leggere il file");
    }
}

// 2) la passa a chi lo chiama (anche al sistema)
public static void main(String[] args) throws IOException {
    leggiFile();
}

Con throws il metodo dice: "io non so come gestire questo problema, ci pensi tu che mi hai chiamato". L'eccezione "risale" la catena delle chiamate finché qualcuno la intercetta. Se nessuno lo fa, arriva fino a main e il programma si ferma.

Mappa riassuntiva

  • Eccezione = oggetto lanciato quando succede un evento anomalo; interrompe il flusso normale del programma.
  • try (codice rischioso) · catch (gestione) · finally (si esegue sempre, per le pulizie).
  • Nel catch: e, e.getMessage(), e.printStackTrace().
  • Più catch: dal più specifico al più generico, Exception per ultimo.
  • Unchecked (RuntimeException): non obbligano a gestirle. Checked (IOException…): obbligo di try-catch o throws.
  • throw new ... lancia un'eccezione; throws nella firma dichiara che il metodo può lanciarla.

Esercizi

01Quale eccezione? facile

Di' quale eccezione si verifica e se è checked o unchecked: a) Integer.parseInt("12a"); b) String s = null; s.length();; c) new FileReader("assente.txt"); d) int[] v = new int[3]; v[3] = 1;; e) 5 / 0.

Soluzione

a) NumberFormatException, unchecked. b) NullPointerException, unchecked. c) FileNotFoundException, checked (figlia di IOException). d) ArrayIndexOutOfBoundsException, unchecked (l'array ha indici 0, 1, 2). e) ArithmeticException, unchecked.

Solo la c) obbliga a un try-catch o a un throws: tocca il mondo esterno (il disco).

02Cosa stampa? facile
try {
    System.out.println("A");
    int x = 5 / 0;
    System.out.println("B");
} catch (ArithmeticException e) {
    System.out.println("C");
} finally {
    System.out.println("D");
}
System.out.println("E");

Cosa stampa? E se la riga della divisione fosse int x = 5 / 1;?

Soluzione

Con 5 / 0: A, C, D, E (una per riga). La "B" non compare: dopo l'errore il try si interrompe.

Con 5 / 1: A, B, D, E. Nessun errore, quindi il catch è saltato, ma il finally gira comunque.

03Trova l'errore di compilazione medio
try {
    int[] n = {1, 2, 3};
    System.out.println(n[5]);
} catch (Exception e) {
    System.out.println("Errore generico");
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Indice non valido");
}

Perché non compila? Come si corregge?

Soluzione

Exception è la classe generale e prende qualsiasi eccezione: il secondo catch non potrebbe mai essere raggiunto, e il compilatore lo segnala come errore. Basta invertire l'ordine, mettendo prima il caso specifico:

} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Indice non valido");
} catch (Exception e) {
    System.out.println("Errore generico");
}
04Leggere un numero dalla tastiera medio

Scrivi un programma che chiede un numero intero e lo stampa raddoppiato. Se l'utente scrive qualcosa che non è un numero, deve stampare "Non è un numero!" e richiedere il valore, finché non è corretto.

Soluzione
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        boolean valido = false;

        while (!valido) {
            System.out.print("Inserisci un numero: ");
            try {
                int n = Integer.parseInt(scanner.nextLine());
                System.out.println("Il doppio è " + (n * 2));
                valido = true;               // arriviamo qui solo se parseInt è riuscito
            } catch (NumberFormatException e) {
                System.out.println("Non è un numero!");
            }
        }
        scanner.close();
    }
}

La riga valido = true è dopo parseInt dentro il try: se parseInt lancia l'eccezione viene saltata, e il ciclo ricomincia.

05Un metodo che lancia medio

Scrivi il metodo static double dividi(double a, double b) che lancia una ArithmeticException con messaggio "Divisione per zero" se b vale 0, altrimenti restituisce il quoziente. Nel main chiamalo con (10, 4) e con (5, 0), intercettando l'errore.

Soluzione
public class Main {
    static double dividi(double a, double b) {
        if (b == 0) {
            throw new ArithmeticException("Divisione per zero");
        }
        return a / b;
    }

    public static void main(String[] args) {
        try {
            System.out.println(dividi(10, 4));   // 2.5
            System.out.println(dividi(5, 0));    // lancia l'eccezione
        } catch (ArithmeticException e) {
            System.out.println("Errore: " + e.getMessage());
        }
    }
}

Output: 2.5 e poi Errore: Divisione per zero. Serve il controllo perché con i double 5.0 / 0 non lancia nessuna eccezione (dà Infinity): con i numeri interi sì, con quelli decimali no. Qui ArithmeticException è unchecked, quindi non serve throws.

06throws o try-catch? medio
static void aspetta() {
    Thread.sleep(1000);   // ferma il programma per un secondo
    System.out.println("Fatto");
}

Il codice non compila. Perché? Dai due correzioni diverse. (Suggerimento: Thread.sleep può lanciare InterruptedException.)

Soluzione

InterruptedException è una eccezione checked (non deriva da RuntimeException): va gestita o dichiarata.

// Correzione 1: la dichiaro, la gestirà chi chiama
static void aspetta() throws InterruptedException {
    Thread.sleep(1000);
    System.out.println("Fatto");
}

// Correzione 2: la gestisco io
static void aspetta() {
    try {
        Thread.sleep(1000);
        System.out.println("Fatto");
    } catch (InterruptedException e) {
        System.out.println("Attesa interrotta");
    }
}

Nel primo caso il metodo "passa il problema" a chi lo chiama; nel secondo lo risolve da solo. Quale scegliere dipende da chi ha le informazioni per decidere cosa fare in caso di errore.

07Il conto corrente completo

Scrivi una classe Conto con l'attributo double saldo e due metodi:

  • deposita(double importo): se l'importo è zero o negativo lancia una IllegalArgumentException con un messaggio; altrimenti lo aggiunge al saldo;
  • preleva(double importo): stesso controllo sull'importo, e se supera il saldo lancia una IllegalStateException ("Saldo insufficiente").

Nel main prova un deposito valido, un prelievo troppo alto e un deposito negativo, intercettando gli errori con due catch e usando un finally che stampa il saldo finale.

Soluzione
class Conto {
    double saldo;

    void deposita(double importo) {
        if (importo <= 0) {
            throw new IllegalArgumentException("L'importo deve essere positivo");
        }
        saldo = saldo + importo;
    }

    void preleva(double importo) {
        if (importo <= 0) {
            throw new IllegalArgumentException("L'importo deve essere positivo");
        }
        if (importo > saldo) {
            throw new IllegalStateException("Saldo insufficiente");
        }
        saldo = saldo - importo;
    }
}

public class Main {
    public static void main(String[] args) {
        Conto c = new Conto();
        try {
            c.deposita(100);
            c.preleva(250);     // lancia IllegalStateException
            c.deposita(-5);     // non viene mai eseguita
        } catch (IllegalArgumentException e) {
            System.out.println("Importo non valido: " + e.getMessage());
        } catch (IllegalStateException e) {
            System.out.println("Operazione rifiutata: " + e.getMessage());
        } finally {
            System.out.println("Saldo finale: " + c.saldo);
        }
    }
}
Operazione rifiutata: Saldo insufficiente
Saldo finale: 100.0
  • Il prelievo di 250 lancia l'eccezione: il try si interrompe e c.deposita(-5) non viene eseguita. Per provarla servirebbe un secondo try.
  • Le due eccezioni sono unchecked, quindi i metodi non hanno bisogno di throws.
  • Il finally stampa il saldo in ogni caso, anche se non ci fossero errori.
