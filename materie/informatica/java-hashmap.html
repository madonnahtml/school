Java: HashMap

In una lista trovi un dato per posizione: "dammi il terzo". Molto spesso però vuoi trovarlo per nome: "dammi l'età di Marco", "dammi il prezzo del caffè". Per questo esiste la HashMap, che tiene i dati a coppie chiave → valore e li ritrova in un attimo.

Prima di cominciareServono le wrapper classes (Integer al posto di int) e aiuta aver letto Collections, ArrayList, Vector e LinkedList: la HashMap fa parte dello stesso Collections Framework. Le parti segnate (extra) non sono nelle slide: sono aggiunte per capire meglio.

Cosa sono le HashMap

In una fraseUna HashMap è una struttura dati che memorizza le informazioni in coppie chiave → valore. Ogni elemento è identificato da una chiave unica, a cui è associato un valore.

Un esempio: l'età di alcuni studenti.

"Marco" → 18
"Luca"  → 20
"Anna"  → 17

Il nome è la chiave, l'età è il valore. Per sapere l'età di Anna non devi scorrere tutto l'elenco: chiedi direttamente "Anna" e ottieni 17.

Chiave (key)

Identifica l'elemento. Non può essere duplicata: in una mappa c'è al massimo un "Marco".

Valore (value)

L'informazione associata alla chiave. Può essere duplicato: Marco e Giulia possono avere entrambi 18 anni.

Un paragoneUna HashMap è come la rubrica del telefono: cerchi per nome (la chiave) e trovi il numero (il valore). Due contatti possono avere lo stesso numero, ma non puoi avere due contatti con lo stesso identico nome: se salvi di nuovo "Mamma", sostituisci quello vecchio. Altri esempi: il dizionario (parola → definizione), il registro (studente → voto), il menù del bar (prodotto → prezzo).

La classe si trova nel pacchetto java.util e va importata: import java.util.HashMap;

Creare una HashMap

A differenza di una lista, servono due tipi: quello della chiave e quello del valore.

HashMap<TipoChiave, TipoValore> nome = new HashMap<>();

Per l'esempio degli studenti la chiave è il nome (testo, String) e il valore è l'età (numero, Integer):

import java.util.HashMap;

public class Main {
    public static void main(String[] args) {
        HashMap<String, Integer> studenti = new HashMap<>();
    }
}
  • HashMap è una classe generic: i tipi tra < > fanno controllare tutto al compilatore. Se provi a fare studenti.put("Marco", "diciotto") il programma non compila.
  • Come per le liste, dentro < > vanno solo classi: Integer, non int; Double, non double.
  • Chiave e valore possono essere di qualsiasi tipo: String, Integer, anche oggetti tuoi (per esempio HashMap<String, Studente>) o perfino liste (HashMap<String, List<Integer>> per i voti di ogni studente).
Map a sinistra (extra)Come si scrive List a sinistra e ArrayList a destra, per le mappe si può scrivere l'interfaccia Map: Map<String, Integer> studenti = new HashMap<>(); (con import java.util.Map;). Funziona tutto uguale; nelle slide si usa HashMap da entrambe le parti, ed è corretto lo stesso.

Aggiungere e modificare con put()

Il metodo put(chiave, valore) inserisce una coppia nella mappa. Primo parametro la chiave, secondo il valore.

studenti.put("Marco", 18);
studenti.put("Luca", 20);
studenti.put("Anna", 17);
System.out.println(studenti);
{Marco=18, Luca=20, Anna=17}

Stampando la mappa, Java mostra le coppie tra graffe nella forma chiave=valore.

put() ha un doppio ruolo

Se la chiave è nuova, put aggiunge una coppia. Se la chiave esiste già, put sostituisce il vecchio valore: le chiavi non possono essere duplicate, quindi non c'è un secondo "Marco".

studenti.put("Marco", 18);   // aggiunge Marco con 18
studenti.put("Marco", 19);   // Marco esiste già: ora vale 19

System.out.println(studenti.get("Marco"));   // 19
System.out.println(studenti.size());         // Marco conta una volta sola

Per "modificare" un valore quindi non c'è un metodo apposta: si rifà put con la stessa chiave.

Aggiornare partendo dal vecchio valore (extra)Per fare "Marco compie gli anni" leggi il vecchio valore e rimetti quello nuovo: studenti.put("Marco", studenti.get("Marco") + 1);. Funziona solo se Marco c'è: altrimenti get restituisce null e il + 1 lancia NullPointerException (vedi la trappola più sotto).
L'ordine non è garantitoLa HashMap non mantiene l'ordine di inserimento: quando la stampi o la scorri, le coppie possono uscire in un ordine diverso da quello in cui le hai messe. Nell'esempio sopra l'ordine coincide per caso; con altre chiavi no. Non scrivere mai un programma che conta sull'ordine di una HashMap.

Leggere con get() e controllare

get(): il valore di una chiave

get(chiave) restituisce il valore associato a quella chiave. Se la chiave non esiste, restituisce null (cioè "niente").

System.out.println(studenti.get("Marco"));   // 18

int eta = studenti.get("Luca");
System.out.println(eta);                     // 20

System.out.println(studenti.get("Paolo"));   // null: Paolo non c'è
La trappola del null (extra)Stampare null non fa danni, ma metterlo in un int sì: 
int eta = studenti.get("Paolo");   // NullPointerException!
Java prova a trasformare l'Integer in int (unboxing), ma null non è un numero. Per questo prima di usare get si controlla con containsKey, oppure si usa getOrDefault.

containsKey(): la chiave c'è?

Restituisce true se la chiave è presente, false altrimenti. È buona abitudine usarlo prima di get.

if (studenti.containsKey("Marco")) {
    System.out.println("Marco è presente!");
}

System.out.println(studenti.containsKey("Marco"));   // true
System.out.println(studenti.containsKey("Paolo"));   // false

containsValue(): il valore c'è?

Controlla se un certo valore è presente, qualunque sia la chiave.

if (studenti.containsValue(20)) {
    System.out.println("C'è uno studente di 20 anni.");
}
Uno veloce, uno lento (extra)containsKey è velocissimo, O(1): la mappa sa subito dove guardare. containsValue invece deve controllare tutte le coppie una per una, O(n): la mappa è organizzata per chiave, non per valore. Come nella rubrica: cercare per nome è immediato, cercare "chi ha questo numero?" vuol dire leggerla tutta.

getOrDefault(): un valore di riserva (extra)

Se la chiave c'è restituisce il suo valore, altrimenti il valore "di riserva" che scegli tu. Niente null, niente if:

int eta = studenti.getOrDefault("Paolo", 0);   // 0, perché Paolo non c'è

Rimuovere, svuotare e contare

remove(): togliere una coppia

remove(chiave) elimina la coppia con quella chiave (chiave e valore insieme).

// Prima: {Marco=18, Luca=20, Anna=17}
studenti.remove("Luca");
// Dopo:  {Marco=18, Anna=17}

// Rimozione "sicura"
if (studenti.containsKey("Luca")) {
    studenti.remove("Luca");
}

Nota: se la chiave non c'è, remove non lancia errori, semplicemente non fa niente (e restituisce null). Il controllo con containsKey serve se vuoi sapere se c'era, per esempio per stampare "Luca non è in elenco".

clear(): svuotare tutto

studenti.clear();
System.out.println(studenti);   // {}

L'oggetto mappa continua a esistere, ma è vuoto: puoi rimetterci dentro altre coppie. Dopo clear(), size() vale 0 e containsKey dà false per qualunque chiave.

size(): quante coppie ci sono

size() restituisce il numero di coppie chiave-valore. Seguendo l'esempio:

Momentosize()
dopo aver aggiunto Marco, Luca e Anna con put3
dopo remove("Luca")2
dopo clear()0

Per sapere se è vuota c'è anche isEmpty(), che equivale a size() == 0 (extra).

Scorrere una HashMap

(Extra rispetto alle slide, ma serve quasi in ogni esercizio.) Una mappa non ha indici, quindi niente for (int i = 0; ...). Si scorre in tre modi, a seconda di cosa ti serve:

// 1) solo le chiavi
for (String nome : studenti.keySet()) {
    System.out.println(nome);
}

// 2) solo i valori
for (int eta : studenti.values()) {
    System.out.println(eta);
}

// 3) chiave e valore insieme
for (Map.Entry<String, Integer> coppia : studenti.entrySet()) {
    System.out.println(coppia.getKey() + " ha " + coppia.getValue() + " anni");
}
MetodoRestituisceUsalo quando
keySet()l'insieme delle chiaviti servono i nomi (e magari fai get)
values()tutti i valorivuoi sommare, fare la media, trovare il massimo
entrySet()tutte le coppie (Map.Entry)ti servono chiave e valore insieme

Un Map.Entry è una singola coppia: getKey() dà la chiave, getValue() il valore. Per usare Map.Entry serve import java.util.Map;.

Ricorda l'ordineIn tutti e tre i casi l'ordine di uscita non è garantito. Se ti serve un ordine, vedi TreeMap e LinkedHashMap più sotto.

Come funziona dentro

(Extra: non è nelle slide, ma spiega perché la HashMap è veloce e perché non ha ordine.)

Dentro una HashMap c'è un array di "cassetti", chiamati bucket. Quando fai put("Anna", 17):

  1. Java calcola l'hash della chiave con il metodo hashCode(): un numero intero ricavato da "Anna". La stessa stringa dà sempre lo stesso numero.
  2. Da quel numero ricava il cassetto in cui mettere la coppia (all'inizio i cassetti sono 16, e il numero viene "ridotto" tra 0 e 15, un po' come il resto di una divisione).
  3. Mette la coppia in quel cassetto.
"Anna".hashCode()  → 2045632   → cassetto 15
"Luca".hashCode()  → 2379719   → cassetto 3
"Marco".hashCode() → 74113578  → cassetto 0

cassetti (16): [0: Marco=18] [1] [2] [3: Luca=20] … [15: Anna=17]

Quando fai get("Anna") rifà lo stesso calcolo, va dritto al cassetto 15 e trova la coppia. Non scorre niente: per questo put, get, containsKey e remove sono in media O(1), veloci con 10 elementi come con un milione.

  • Perché non c'è ordine: le coppie stanno nel cassetto deciso dall'hash, non in fila nell'ordine in cui sono arrivate.
  • Collisioni: due chiavi diverse possono finire nello stesso cassetto. Nessun problema: il cassetto ne tiene più di una e Java le distingue con equals(). Se succede di rado, resta tutto veloce.
  • Il nome HashMap viene proprio da qui.
Oggetti tuoi come chiave: hashCode() ed equals()Con String e Integer come chiavi va tutto bene, perché Java sa già calcolarne l'hash e confrontarle. Se usi come chiave un oggetto di una tua classe (per esempio Punto con x e y), devi sovrascrivere sia hashCode() sia equals(). Altrimenti due oggetti new Punto(1, 2) creati separatamente vengono considerati chiavi diverse, e get non trova quello che hai messo con put. Regola: due oggetti uguali per equals devono avere lo stesso hashCode.

Esempio completo

Tutte le operazioni principali in un solo programma. Leggi il codice e prova a prevedere l'output prima di guardarlo.

import java.util.HashMap;

public class Main {
    public static void main(String[] args) {
        // Creazione
        HashMap<String, Integer> studenti = new HashMap<>();

        // Aggiunta
        studenti.put("Marco", 18);
        studenti.put("Luca", 20);
        studenti.put("Anna", 17);
        System.out.println(studenti);

        // Accesso
        System.out.println("Età di Marco: " + studenti.get("Marco"));

        // Controllo chiave
        if (studenti.containsKey("Anna")) {
            System.out.println("Anna è presente.");
        }

        // Modifica
        studenti.put("Marco", 19);
        System.out.println("Nuova età di Marco: " + studenti.get("Marco"));

        // Rimozione
        studenti.remove("Luca");
        System.out.println(studenti);

        // Numero di elementi
        System.out.println("Numero studenti: " + studenti.size());

        // Pulizia
        studenti.clear();
        System.out.println("HashMap dopo clear: " + studenti);
    }
}
{Marco=18, Luca=20, Anna=17}
Età di Marco: 18
Anna è presente.
Nuova età di Marco: 19
{Marco=19, Anna=17}
Numero studenti: 2
HashMap dopo clear: {}

Nota la riga 5: Marco vale 19, non 18, perché il secondo put ha sostituito il valore. E le stampe della mappa potrebbero avere un ordine diverso su un altro computer o con altre chiavi.

HashMap o lista?

ArrayList

  • trovi i dati per posizione (get(3))
  • mantiene l'ordine
  • ammette duplicati
  • cercare un elemento (contains) è O(n)

Un elenco: la fila, la classifica, i voti in ordine di data.

HashMap

  • trovi i dati per chiave (get("Anna"))
  • nessun ordine garantito
  • chiavi uniche, valori anche ripetuti
  • cercare per chiave (containsKey) è O(1)

Una rubrica: nome → numero, prodotto → prezzo, parola → quante volte compare.

La domanda da farsi: "come cercherò i dati?" Per posizione o scorrendoli tutti, lista. Per un nome o un codice, mappa.

I prossimi passi

ClasseCosa cambia rispetto a HashMap
LinkedHashMapmantiene l'ordine di inserimento (extra)
TreeMaptiene le chiavi ordinate (alfabetico, numerico); operazioni un po' più lente, O(log n)
HashSetsolo chiavi, senza valori: un insieme di elementi unici (funziona con lo stesso meccanismo degli hash)

Si usano tutte con gli stessi metodi visti qui: cambiando new HashMap<>() in new TreeMap<>(), la stampa esce in ordine alfabetico. Per approfondire ogni metodo c'è la documentazione ufficiale Oracle di java.util.HashMap.

Esercizi

01Chiave o valore? facile

Per ogni situazione di' quale sarebbe la chiave, quale il valore e i tipi Java: a) il prezzo dei prodotti di un bar; b) i voti finali degli studenti di una classe; c) il numero di giorni di ogni mese; d) le capitali degli stati europei. In quale caso i valori si ripetono?

Soluzione
  • a) prodotto → prezzo: HashMap<String, Double>.
  • b) studente → voto: HashMap<String, Integer>.
  • c) mese → giorni: HashMap<String, Integer>. Qui i valori si ripetono tantissimo (molti mesi hanno 30 o 31 giorni), ed è permesso.
  • d) stato → capitale: HashMap<String, String>.

Anche in a) e b) i valori possono ripetersi (due prodotti allo stesso prezzo, due studenti con 7). Le chiavi invece sono sempre uniche: è quello con cui cerchi.

02Cosa stampa? facile
HashMap<String, Integer> m = new HashMap<>();
m.put("a", 1);
m.put("b", 2);
m.put("a", 5);
m.put("c", 2);
m.remove("b");
m.remove("z");
System.out.println(m.size());
System.out.println(m.get("a") + " " + m.get("b"));
System.out.println(m.containsKey("c") + " " + m.containsValue(2));
Soluzione
2
5 null
true true

Il secondo put("a", 5) sostituisce l'1. Dopo remove("b") restano "a" e "c": size 2. remove("z") non fa nulla. get("b") dà null perché "b" è stata tolta. Il valore 2 c'è ancora, associato a "c".

03Trova l'errore facile
HashMap<String, Integer> voti = new HashMap<>();
voti.put("Anna", 8);
int v = voti.get("anna");
System.out.println(v + 1);

Il programma compila, ma si ferma con un errore. Quale e perché? Correggilo in due modi.

Soluzione

Le chiavi String distinguono maiuscole e minuscole: "anna" non è "Anna", quindi get restituisce null, e mettere null in un int lancia NullPointerException.

// 1) controllo prima
if (voti.containsKey("anna")) {
    int v = voti.get("anna");
    System.out.println(v + 1);
} else {
    System.out.println("Studente non trovato");
}

// 2) valore di riserva
int v = voti.getOrDefault("anna", 0);

E naturalmente, se si voleva Anna, va scritta con la maiuscola.

04Il listino del bar medio

Crea una mappa con i prezzi: caffè 1.20, cappuccino 1.50, cornetto 1.30, spremuta 3.00. Poi: a) aumenta di 10 centesimi il prezzo del caffè; b) togli la spremuta; c) stampa ogni prodotto con il suo prezzo; d) calcola quanto costa un ordine fatto da {"caffè", "cornetto", "cornetto", "tè"}, segnalando i prodotti che non ci sono.

Soluzione
import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        HashMap<String, Double> prezzi = new HashMap<>();
        prezzi.put("caffè", 1.20);
        prezzi.put("cappuccino", 1.50);
        prezzi.put("cornetto", 1.30);
        prezzi.put("spremuta", 3.00);

        prezzi.put("caffè", prezzi.get("caffè") + 0.10);   // a)
        prezzi.remove("spremuta");                         // b)

        for (Map.Entry<String, Double> p : prezzi.entrySet()) {   // c)
            System.out.println(p.getKey() + ": " + p.getValue() + " €");
        }

        String[] ordine = {"caffè", "cornetto", "cornetto", "tè"};   // d)
        double totale = 0;
        for (String prodotto : ordine) {
            if (prezzi.containsKey(prodotto)) {
                totale += prezzi.get(prodotto);
            } else {
                System.out.println("Non disponibile: " + prodotto);
            }
        }
        System.out.printf("Totale: %.2f €%n", totale);
    }
}
cappuccino: 1.5 €
caffè: 1.3 €
cornetto: 1.3 €
Non disponibile: tè
Totale: 3.90 €

L'ordine delle righe del listino può essere diverso: è una HashMap. Il printf con %.2f stampa il totale con due decimali (con i double la somma potrebbe venire 3.9000000000000004).

05Contare le parole medio

Data la frase "il gatto e il cane e il topo", conta quante volte compare ogni parola usando una HashMap e stampa il risultato. Suggerimento: frase.split(" ") divide la frase in un array di parole.

Soluzione
String frase = "il gatto e il cane e il topo";
HashMap<String, Integer> conta = new HashMap<>();

for (String parola : frase.split(" ")) {
    if (conta.containsKey(parola)) {
        conta.put(parola, conta.get(parola) + 1);   // già vista: +1
    } else {
        conta.put(parola, 1);                       // prima volta
    }
}
System.out.println(conta);
{il=3, e=2, cane=1, gatto=1, topo=1}

Le parole escono in un ordine diverso dalla frase: è una HashMap. È lo schema classico del contatore con una mappa: la parola è la chiave, il numero di volte il valore. Le tre righe dell'if si possono scrivere in una: conta.put(parola, conta.getOrDefault(parola, 0) + 1);

06Il migliore della classe medio

Data una mappa studente → media (Anna 7.5, Bruno 6.0, Carla 8.25, Dario 5.5), stampa: la media della classe, lo studente con la media più alta e i nomi degli studenti insufficienti (media sotto 6).

Soluzione
HashMap<String, Double> medie = new HashMap<>();
medie.put("Anna", 7.5);
medie.put("Bruno", 6.0);
medie.put("Carla", 8.25);
medie.put("Dario", 5.5);

double somma = 0;
for (double m : medie.values()) {
    somma += m;
}
System.out.println("Media della classe: " + somma / medie.size());

String migliore = null;
for (String nome : medie.keySet()) {
    if (migliore == null || medie.get(nome) > medie.get(migliore)) {
        migliore = nome;
    }
}
System.out.println("Migliore: " + migliore + " (" + medie.get(migliore) + ")");

for (Map.Entry<String, Double> e : medie.entrySet()) {
    if (e.getValue() < 6) {
        System.out.println("Insufficiente: " + e.getKey());
    }
}
Media della classe: 6.8125
Migliore: Carla (8.25)
Insufficiente: Dario

Tre modi di scorrere per tre scopi: values() per la somma (servono solo i numeri), keySet() per il massimo (serve sapere chi), entrySet() per il filtro (servono nome e media insieme).

07La rubrica completo

Scrivi una classe Rubrica con un attributo HashMap<String, String> contatti (nome → numero) e i metodi:

  • boolean aggiungi(String nome, String numero): aggiunge il contatto solo se il nome non c'è già, e dice se ci è riuscito;
  • String cerca(String nome): restituisce il numero, oppure "non trovato";
  • boolean elimina(String nome): dice se il contatto c'era;
  • String chiHa(String numero): restituisce il nome di chi ha quel numero, oppure null.

Provala nel main. Perché chiHa è più lento degli altri metodi?

Soluzione
import java.util.HashMap;
import java.util.Map;

class Rubrica {
    private HashMap<String, String> contatti = new HashMap<>();

    boolean aggiungi(String nome, String numero) {
        if (contatti.containsKey(nome)) {
            return false;               // non sovrascrivo un contatto esistente
        }
        contatti.put(nome, numero);
        return true;
    }

    String cerca(String nome) {
        return contatti.getOrDefault(nome, "non trovato");
    }

    boolean elimina(String nome) {
        if (!contatti.containsKey(nome)) {
            return false;
        }
        contatti.remove(nome);
        return true;
    }

    String chiHa(String numero) {
        for (Map.Entry<String, String> c : contatti.entrySet()) {
            if (c.getValue().equals(numero)) {
                return c.getKey();
            }
        }
        return null;
    }
}

public class Main {
    public static void main(String[] args) {
        Rubrica r = new Rubrica();
        System.out.println(r.aggiungi("Mamma", "333 111 2222"));   // true
        System.out.println(r.aggiungi("Luca", "347 555 6666"));    // true
        System.out.println(r.aggiungi("Mamma", "000"));            // false
        System.out.println(r.cerca("Mamma"));                      // 333 111 2222
        System.out.println(r.cerca("Zia"));                        // non trovato
        System.out.println(r.chiHa("347 555 6666"));               // Luca
        System.out.println(r.elimina("Luca"));                     // true
        System.out.println(r.elimina("Luca"));                     // false
    }
}
  • In aggiungi il controllo con containsKey serve perché un semplice put sovrascriverebbe il numero della mamma.
  • I numeri sono String, non int: hanno spazi, possono iniziare con 0 o con +39, e non ci si fanno calcoli.
  • chiHa cerca per valore: deve scorrere tutte le coppie, O(n). Gli altri metodi cercano per chiave, O(1). Le stringhe si confrontano con equals, non con ==.
