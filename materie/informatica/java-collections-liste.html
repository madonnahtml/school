Un array ha una dimensione fissa: se lo crei da 10 posti, resta da 10 posti. Nei programmi veri però non sai quasi mai in anticipo quanti dati arriveranno. Le liste di Java risolvono il problema: crescono e si accorciano da sole. Qui vediamo le tre più importanti, come funzionano dentro e quale scegliere.

Il Java Collections Framework

In una fraseIl Java Collections Framework (JCF) è l'insieme standard di interfacce, classi e algoritmi che Java mette a disposizione per gestire gruppi di oggetti. È arrivato con Java 1.2 e sta nel pacchetto java.util.

Una collezione è semplicemente un oggetto che contiene altri oggetti: una lista di studenti, un elenco di prodotti, la coda delle stampe. Invece di riscrivere ogni volta il codice per aggiungere, togliere, cercare e ordinare, usi quello già pronto e collaudato. Nel JCF trovi:

  • un'architettura unica: tutte le collezioni si usano in modo simile (add, remove, size…), quindi impari una volta e vale per tutte;
  • meno lavoro: niente "reinventare la ruota" a ogni progetto;
  • algoritmi pronti, per esempio per ordinare (Collections.sort) e cercare;
  • collezioni che passano facilmente da una parte all'altra del programma e tra librerie diverse;
  • i generics (List<String>), che fanno controllare i tipi al compilatore.
Interfaccia e classe, in parole sempliciUn'interfaccia è un contratto: dice cosa si può fare, non come. Una classe che la implementa è chi mantiene la promessa, ognuna a modo suo. È come la patente B: dice che sai guidare un'auto, poi l'auto può essere una Panda o una Golf, ma i pedali sono sempre quelli.

I generics: il tipo tra < >

Tra le parentesi angolari scrivi che tipo di oggetti contiene la collezione. Dal Java 5 in poi è il modo giusto di usarle:

List<String> nomi = new ArrayList<>();
nomi.add("Anna");
nomi.add(42);              // ERRORE di compilazione: 42 non è una String
String primo = nomi.get(0); // nessun cast: il compilatore sa che è una String
  • Dentro < > vanno solo classi: List<Integer>, mai List<int>. Grazie all'autoboxing poi scrivi numeri.add(5) e Java trasforma da solo 5 in un Integer.
  • A destra basta il "diamante" <> vuoto: il tipo Java lo ricava da sinistra.

L'interfaccia List

Cos'è una ListUna List è una sequenza ordinata di elementi, ognuno con la sua posizione (indice) a partire da 0, come in un array. A differenza di un Set, una List ammette duplicati e mantiene l'ordine di inserimento.

Una lista della spesa è un buon esempio: le voci hanno un ordine (prima, seconda, terza…) e puoi scrivere "latte" due volte. Un insieme (Set) invece è come l'elenco dei partecipanti a una gita: ogni nome compare una volta sola e l'ordine non conta.

List è un'interfaccia, quindi non si può fare new List(): serve una classe che la implementi. Le tre classiche sono:

ClasseCome è fatta dentroIn una parola
ArrayListun array che si ingrandisce da soloarray dinamico
Vectorcome ArrayList, ma con i metodi sincronizzatithread-safe (e vecchio)
LinkedListuna catena di nodi collegati tra loronodi collegati

Tutte e tre hanno gli stessi metodi di List (add, get, remove, size…): da fuori si usano allo stesso modo. Cambia la velocità delle operazioni, perché cambia come tengono i dati in memoria. È tutto il senso del capitolo.

ArrayList: l'array dinamico

ArrayList è la collezione più usata in Java. Dentro ha un normale array, un po' più grande del necessario. Quando si riempie, Java ne crea uno più grande, ci copia tutti gli elementi e butta via quello vecchio. Tu non te ne accorgi: vedi solo una lista che cresce.

size = 3, capacità = 4          aggiungo "D": c'è posto
[ "A" | "B" | "C" |     ]   →   [ "A" | "B" | "C" | "D" ]

aggiungo "E": è pieno! nuovo array più grande e copia
[ "A" | "B" | "C" | "D" | "E" |     ]
size e capacitàLa size è quanti elementi ci sono davvero (lista.size()). La capacità è quanti ne entrano nell'array interno prima di doverlo ingrandire. La capacità è un dettaglio interno: tu lavori solo con la size.

Per capire i pregi e i difetti basta ricordare che sotto c'è un array:

Vantaggi

  • Accesso per indice immediato, O(1): gli elementi sono uno dopo l'altro in memoria, quindi Java calcola subito dove sta l'elemento i, come in un array.
  • Scorrere la lista è velocissimo: elementi vicini in memoria vengono caricati insieme nella cache del processore.
  • API semplice e familiare.
  • Puoi indicare una capacità iniziale se sai già più o meno quanti elementi arriveranno, e così eviti ingrandimenti inutili.

Svantaggi

  • Inserire o togliere in mezzo è lento, O(n): tutti gli elementi dopo vanno spostati di un posto.
  • Non è thread-safe: se due thread la modificano insieme possono rovinarla.
  • Ogni tanto paga l'ingrandimento: copiare tutto in un array nuovo costa.

Perché inserire in mezzo è lento? Guarda cosa succede con lista.add(1, "X"):

prima:  [ "A" | "B" | "C" | "D" |     ]
         "D" va avanti di uno, poi "C", poi "B"…
dopo:   [ "A" | "X" | "B" | "C" | "D" ]

Con 4 elementi non è niente; con un milione di elementi e un inserimento in testa, gli spostamenti sono un milione. Aggiungere in fondo invece non sposta nessuno, ed è per questo che è veloce.

Quanto cresce? (precisazione alle slide)Le slide dicono che ArrayList "raddoppia". In realtà nella versione standard di Java l'array di ArrayList cresce di circa il 50% (da 10 a 15, poi 22…), mentre è Vector che di solito raddoppia. Per le verifiche conta il concetto: quando è pieno, si crea un array più grande e si copia tutto.
Cosa vuol dire "thread-safe"Un thread è un "filo" di esecuzione: un programma può farne girare più di uno insieme (per esempio un server che serve tanti utenti). Una struttura è thread-safe se più thread possono usarla nello stesso momento senza danni. Finché il tuo programma ha un solo thread (tutti gli esercizi di scuola), non devi preoccupartene.

Usare ArrayList: la sintassi

Dichiarare e creare

import java.util.ArrayList;
import java.util.List;

// Buona pratica: a sinistra l'interfaccia, a destra la classe concreta
List<String> lista = new ArrayList<>();

// Con capacità iniziale (se sai che saranno circa 100 elementi)
List<Integer> numeri = new ArrayList<>(100);

Scrivere List a sinistra si chiama programmare per interfaccia: il resto del programma sa solo che lista è "una lista", non quale. Se un domani vuoi una LinkedList, cambi una parola e tutto il resto funziona uguale.

Capacità non è sizenew ArrayList<>(100) crea una lista vuota: size() vale 0, e lista.get(0) lancia IndexOutOfBoundsException. Il 100 è solo lo spazio preparato in anticipo.

Aggiungere e inserire

lista.add("Primo elemento");          // [Primo elemento]
lista.add("Secondo elemento");        // [Primo elemento, Secondo elemento]
lista.add(1, "Inserito in pos. 1");   // [Primo elemento, Inserito in pos. 1, Secondo elemento]

List<String> altri = List.of("A", "B", "C");
lista.addAll(altri);                  // ... e in fondo A, B, C

List.of(...) crea al volo una piccola lista non modificabile: comoda per dati fissi o per riempirne un'altra, ma se ci fai add lancia UnsupportedOperationException.

Leggere, modificare, togliere

String primo = lista.get(0);             // legge per indice
lista.set(0, "Modificato");              // sostituisce l'elemento 0

lista.remove(0);                         // toglie per indice
lista.remove("Secondo elemento");        // toglie per oggetto

int dimensione = lista.size();           // quanti elementi
boolean contiene = lista.contains("A");  // c'è "A"?
Trappola con List<Integer> (extra)Con una lista di numeri remove(1) è ambiguo: toglie l'elemento in posizione 1 o il numero 1? Java sceglie la posizione, perché 1 è un int. Per togliere il valore scrivi remove(Integer.valueOf(1)). 
List<Integer> v = new ArrayList<>(List.of(5, 1, 7));
v.remove(1);                   // toglie la posizione 1 → [5, 7]
v.remove(Integer.valueOf(7));  // toglie il valore 7   → [5]

Scorrere la lista

// 1) for-each: il più leggibile, da usare quasi sempre
for (String elemento : lista) {
    System.out.println(elemento);
}

// 2) for con indice: quando ti serve sapere la posizione
for (int i = 0; i < lista.size(); i++) {
    System.out.println(i + ": " + lista.get(i));
}

// 3) Iterator: permette di togliere elementi mentre scorri
Iterator<String> it = lista.iterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.isEmpty()) {
        it.remove();               // toglie l'elemento appena letto
    }
}

Un Iterator è un "segnalibro" che scorre la collezione: hasNext() chiede se c'è un altro elemento, next() lo prende e va avanti, remove() toglie l'ultimo elemento preso con next(). Serve import java.util.Iterator;.

L'esempio delle slideNelle slide il ciclo con l'Iterator chiama it.next(); it.remove(); per ogni elemento, senza condizione: così svuota tutta la lista. Serve a mostrare la sintassi; nella pratica il remove() sta dentro un if, come sopra.
Non togliere dentro un for-each (extra)Se dentro un for-each chiami lista.remove(...), Java di solito lancia ConcurrentModificationException: la lista è cambiata mentre la stavi scorrendo. Per togliere mentre scorri usa l'Iterator, oppure lista.removeIf(s -> s.isEmpty());.

Vector: l'antenato thread-safe

Vector è una delle classi più antiche di Java: c'era già in Java 1.0, prima ancora del Collections Framework. Dentro è quasi identica ad ArrayList: anche lei usa un array che si ingrandisce. La differenza è una sola, ma pesa:

SincronizzazioneOgni metodo di Vector è synchronized: un solo thread alla volta può usarlo. È come un bagno con la chiave: chi entra chiude, gli altri aspettano. Così più thread possono usare lo stesso Vector senza rovinarlo, senza scrivere codice in più.

Il prezzo è la lentezza: "chiudere e riaprire la porta" a ogni chiamata costa tempo, anche quando il thread è uno solo e nessuno aspetta. Per questo oggi Vector è considerato legacy (roba vecchia, tenuta per compatibilità).

La capacità incrementale

Vector ha una cosa che ArrayList non ha: puoi decidere di quanto cresce con il capacityIncrement.

// capacità iniziale 10; quando è pieno cresce di 5 posti alla volta (10, 15, 20…)
Vector<String> v = new Vector<>(10, 5);
v.add("ciao");          // si usa come una qualsiasi List

Cosa usare al suo posto

Se ti serve davvero una lista condivisa tra thread:

  • Collections.synchronizedList(new ArrayList<>()): un ArrayList "con la chiave", stessa idea di Vector;
  • CopyOnWriteArrayList (pacchetto java.util.concurrent): ottimo quando si legge spesso e si scrive raramente;
  • le altre collezioni di java.util.concurrent, pensate apposta per i thread.

LinkedList: la lista concatenata

LinkedList è fatta in modo completamente diverso: niente array. Ogni elemento sta in un nodo, e ogni nodo contiene il valore più due riferimenti: uno al nodo precedente e uno al successivo. Per questo si chiama lista doppiamente collegata (doubly-linked list).

 null ← [ "A" ] ⇄ [ "B" ] ⇄ [ "C" ] → null
           ↑                   ↑
         first                last

 ogni nodo:  [ prev | valore | next ]

Pensa a una caccia al tesoro: ogni biglietto dice dove trovare il prossimo (e qui anche il precedente). I biglietti possono stare ovunque in casa, non uno accanto all'altro. La lista conosce solo il primo e l'ultimo nodo.

Inserire "X" tra "A" e "B" vuol dire solo cambiare qualche freccia (quelle di A, X e B): nessun elemento si sposta.

prima:  "A" ⇄ "B" ⇄ "C"
dopo:   "A" ⇄ "X" ⇄ "B" ⇄ "C"

Ma per arrivare all'elemento numero 500 bisogna seguire le frecce una per una partendo da un'estremità: non si può "saltare" direttamente come in un array.

Vantaggi

  • Inserire e togliere è O(1) una volta arrivati nel punto giusto: si cambiano solo i collegamenti.
  • Mai ingrandimenti: ogni nuovo elemento è un nodo nuovo, niente copie.
  • Implementa anche Deque: ha metodi pronti per lavorare su testa e coda (addFirst, removeLast…).
  • Ottima per fare code e pile.

Svantaggi

  • Accesso per indice lento, O(n): get(i) deve scorrere i nodi dall'inizio o dalla fine (da quella più vicina).
  • Più memoria: ogni nodo porta con sé due riferimenti in più (prev e next).
  • Nodi sparsi in memoria: la cache del processore aiuta poco, quindi anche scorrere la lista è più lento.
  • Non thread-safe, come ArrayList.

LinkedList come pila e come coda

Una LinkedList si può usare come normale List, ma implementa anche l'interfaccia Deque (Double-Ended Queue, "coda a due estremità", si legge "deck"): una sequenza in cui si aggiunge e si toglie da entrambe le estremità.

import java.util.LinkedList;
import java.util.List;
import java.util.Deque;

List<String>  lista = new LinkedList<>();   // usata come lista
Deque<String> coda  = new LinkedList<>();   // usata come deque

Il tipo a sinistra decide quali metodi vedi: con Deque hai addFirst, pollLast, push…; con List hai get(i), set(i, e)…

Le operazioni sulle estremità

coda.addFirst("Inizio");             // aggiunge in testa
coda.addLast("Fine");                // aggiunge in fondo

String primo  = coda.removeFirst();  // toglie e restituisce la testa
String ultimo = coda.removeLast();   // toglie e restituisce l'ultimo

coda.offerFirst("Testa");            // come addFirst
coda.pollLast();                     // come removeLast (null se vuota)
coda.peekFirst();                    // legge la testa senza toglierla

Ci sono due "famiglie" di metodi che fanno la stessa cosa e si comportano diversamente quando la deque è vuota:

OperazioneSe è vuota lancia un'eccezioneSe è vuota restituisce null
aggiungi in testa / in fondoaddFirst / addLastofferFirst / offerLast
togli la testa / l'ultimoremoveFirst / removeLastpollFirst / pollLast
guarda senza toglieregetFirst / getLastpeekFirst / peekLast

Per ricordarle: poll e peek sono "gentili" e rispondono null; remove e get si arrabbiano con NoSuchElementException. (Gli offer su una LinkedList riescono sempre, perché non ha un limite di posti.)

La pila (stack): l'ultimo che entra è il primo che esce

Una pila è come una pila di piatti: appoggi sopra e prendi da sopra. Si dice LIFO: Last In, First Out. Esempi: il tasto "Annulla" (annulla l'ultima azione), il tasto "Indietro" del browser.

  • push(e): mette in cima
  • pop(): toglie e restituisce la cima
  • peek(): guarda la cima senza toglierla
Deque<Integer> pila = new LinkedList<>();

pila.push(1);
pila.push(2);
pila.push(3);          // cima: 3

int cima  = pila.pop();   // 3 (e lo toglie)
int sopra = pila.peek();  // 2 (resta lì)
  1. 3push(3)l'ultimo entrato: è il primo a uscire con pop()
  2. 2push(2)dopo il pop() è lui la cima: peek() restituisce 2
  3. 1push(1)il primo entrato: uscirà per ultimo

La coda (queue): il primo che entra è il primo che esce

Una coda è come la fila al bar: chi arriva si mette in fondo, si serve chi è davanti. Si dice FIFO: First In, First Out. Esempi: la coda di stampa, i messaggi da elaborare.

  • offer(e): entra in fondo alla fila (enqueue)
  • poll(): esce il primo della fila (dequeue)
  • peek(): guarda chi è il primo senza farlo uscire
Deque<String> coda = new LinkedList<>();

coda.offer("Alice");
coda.offer("Bob");
coda.offer("Charlie");

String prossimo = coda.poll();  // "Alice"
String testa    = coda.peek();  // "Bob"
esce ←  [ Alice | Bob | Charlie ]  ← entra
poll() → Alice esce;  ora la testa è Bob
Pila e coda insiemeSulla stessa Deque, push e pop lavorano sulla testa; offer aggiunge in fondo e poll toglie dalla testa. Per non confonderti usa ogni deque per un solo scopo: o come pila o come coda.
E la classe Stack? (extra)Java ha anche una classe Stack, ma è figlia di Vector e quindi legacy anche lei. Oggi per pile e code si usa una Deque: LinkedList come nelle slide, oppure ArrayDeque, che di solito è ancora più veloce.

Prestazioni: O(1) e O(n)

Per scegliere la lista giusta bisogna sapere quanto costa ogni operazione. Si usa la notazione O grande (Big O), che dice come cresce il tempo quando crescono gli elementi.

O(1): tempo costante

Il tempo non dipende da quanti elementi ci sono: con 10 o con 10 milioni ci mette uguale. È il caso ideale.

Come aprire un libro alla pagina 200 se sai già il numero.

O(n): tempo lineare

Il tempo cresce insieme al numero di elementi n: con un milione di elementi potresti fare un milione di passi.

Come cercare una parola sfogliando il libro pagina per pagina.

Il costo nascosto di LinkedListNella tabella add(i, e) su LinkedList è O(1), ma è un mezzo trucco: prima bisogna raggiungere la posizione i, e per farlo si scorrono i nodi, cioè O(n). Quindi lista.add(500, x) su una LinkedList costa comunque O(n). Il vero vantaggio si vede quando sei già lì: in testa, in fondo, oppure scorrendo con un ListIterator, che ricorda la posizione e permette più inserimenti di seguito senza ripartire ogni volta dall'inizio.
// Inserisce "-" dopo ogni elemento, in una sola passata
ListIterator<String> it = lista.listIterator();
while (it.hasNext()) {
    it.next();
    it.add("-");     // su LinkedList: O(1), siamo già nel punto giusto
}

Come scegliere: la regola d'oro

Non esiste una lista migliore in assoluto: dipende da cosa fai più spesso.

ArrayList · quasi sempre

La scelta di default (circa il 90% dei casi). Quando accedi spesso per indice, scorri la lista con il for-each, aggiungi soprattutto in fondo. Esempi: elenco di prodotti, risultati di una ricerca, voti di uno studente.

LinkedList · casi specifici

Quando aggiungi e togli spesso in testa, ti serve una coda o una pila, o modifichi la lista mentre la scorri con un ListIterator. Esempi: coda di task, cronologia annulla/ripeti.

Vector · da evitare

È obsoleto per il codice nuovo. Se serve la sicurezza tra thread: Collections.synchronizedList(new ArrayList<>()), CopyOnWriteArrayList o le collezioni di java.util.concurrent.

Regola praticaParti sempre da ArrayList. Solo se misuri il programma e scopri che è lento proprio sugli inserimenti in testa o in mezzo, valuta LinkedList. Non ottimizzare prima di avere un problema.

Una domanda veloce che risolve quasi tutti gli esercizi: "leggo per posizione?" Se sì, ArrayList. "Lavoro sulle estremità, come in una fila o in una pila?" Se sì, LinkedList (come Deque).

Buone abitudini

1. Programma per interfaccia

Dichiara le variabili come List<T>, non come ArrayList<T>. Così puoi cambiare implementazione senza toccare il resto del codice, e anche i metodi accettano qualsiasi lista.

List<String> nomi = new ArrayList<>();

// Il metodo funziona con ArrayList, LinkedList, Vector…
static void stampa(List<String> l) {
    for (String s : l) System.out.println(s);
}

2. Usa sempre i generics

Scrivi sempre il tipo tra < >. Una collezione raw (senza tipo) accetta qualsiasi cosa: gli errori saltano fuori solo durante l'esecuzione, come ClassCastException, invece che quando compili.

List<Integer> numeri = new ArrayList<>();   // giusto

List grezza = new ArrayList();               // raw: da non fare
grezza.add("ciao");
grezza.add(3);                               // il compilatore non dice niente
String s = (String) grezza.get(1);           // ClassCastException a runtime!

Mappa riassuntiva

  • JCF = interfacce, classi e algoritmi di java.util per gestire gruppi di oggetti. Con i generics (List<Integer>, mai <int>).
  • List = sequenza ordinata con indice da 0, ammette duplicati. Implementazioni: ArrayList, Vector, LinkedList.
  • ArrayList = array che si ingrandisce copiando. get(i) O(1), aggiunta in fondo O(1) ammortizzata, inserimento/rimozione in mezzo O(n). Non thread-safe. La scelta di default.
  • Vector = come ArrayList ma synchronized: thread-safe e più lento. Legacy (Java 1.0). Ha il capacityIncrement.
  • LinkedList = nodi con prev e next. get(i) O(n); inserire/togliere O(1) una volta arrivati; più memoria. Implementa Deque.
  • Pila (LIFO): push, pop, peek. Coda (FIFO): offer, poll, peek.
  • Metodi base: add, add(i, e), get, set, remove, size, contains. Per togliere mentre scorri: Iterator.
  • Buone abitudini: List<T> x = new ArrayList<>() e mai collezioni raw.

Esercizi

01Quale lista? facile

Per ogni situazione scegli tra ArrayList, LinkedList (come Deque) e una lista sincronizzata, e spiega perché in una riga: a) i voti di uno studente, che leggi spesso per calcolare la media; b) la coda delle richieste di stampa; c) il tasto "Annulla" di un editor; d) l'elenco dei prodotti di un negozio, mostrati per pagina (dal 21° al 40°); e) una lista di utenti connessi, modificata da più thread di un server.

Soluzione
  • a) ArrayList: si scorre e si aggiunge in fondo, il caso tipico.
  • b) LinkedList come coda (FIFO): offer per mettere in fila, poll per stampare il prossimo.
  • c) LinkedList come pila (LIFO): push a ogni azione, pop per annullare l'ultima.
  • d) ArrayList: serve l'accesso per indice (get(20)…get(39)), che è O(1).
  • e) Lista sincronizzata: Collections.synchronizedList(new ArrayList<>()) o CopyOnWriteArrayList, non Vector.
02Cosa stampa? facile
List<String> l = new ArrayList<>();
l.add("rosso");
l.add("verde");
l.add(0, "blu");
l.add("giallo");
l.set(2, "nero");
l.remove("rosso");
System.out.println(l);
System.out.println(l.size() + " " + l.get(1) + " " + l.contains("verde"));
Soluzione
[blu, nero, giallo]
3 nero false

Passo passo: [rosso, verde] → add(0, "blu") → [blu, rosso, verde] → [blu, rosso, verde, giallo] → set(2, "nero") sostituisce "verde" → [blu, rosso, nero, giallo] → tolto "rosso" → [blu, nero, giallo]. "verde" non c'è più, quindi contains dà false.

03Pila e coda facile
Deque<Integer> pila = new LinkedList<>();
Deque<Integer> coda = new LinkedList<>();
for (int i = 1; i <= 4; i++) {
    pila.push(i);
    coda.offer(i);
}
System.out.println(pila.pop() + " " + pila.pop() + " " + pila.peek());
System.out.println(coda.poll() + " " + coda.poll() + " " + coda.peek());

Cosa stampa? Quanti elementi restano in ciascuna?

Soluzione
4 3 2
1 2 3

La pila restituisce prima l'ultimo entrato (LIFO), la coda il primo (FIFO). peek guarda senza togliere: in entrambe restano 2 elementi (pila: 2 e 1; coda: 3 e 4).

04Trappola remove medio
List<Integer> n = new ArrayList<>(List.of(10, 20, 30, 2));
n.remove(2);
System.out.println(n);
n.remove(Integer.valueOf(2));
System.out.println(n);

Cosa stampa? Perché i due remove si comportano in modo diverso?

Soluzione
[10, 20, 2]
[10, 20]

remove(2) riceve un int, quindi Java usa remove(int indice): toglie l'elemento in posizione 2, cioè 30. remove(Integer.valueOf(2)) riceve un oggetto, quindi usa remove(Object): toglie il valore 2. È un caso di overload: stesso nome, parametri diversi.

05Togliere i voti insufficienti medio

Data List<Integer> voti = new ArrayList<>(List.of(7, 4, 8, 5, 6, 3)); togli tutti i voti minori di 6 usando un Iterator, poi stampa la lista e la media dei voti rimasti. Perché non si può fare con un for-each?

Soluzione
import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> voti = new ArrayList<>(List.of(7, 4, 8, 5, 6, 3));

        Iterator<Integer> it = voti.iterator();
        while (it.hasNext()) {
            if (it.next() < 6) {
                it.remove();
            }
        }

        int somma = 0;
        for (int v : voti) {
            somma += v;
        }
        System.out.println(voti);
        System.out.println("Media: " + (double) somma / voti.size());
    }
}
[7, 8, 6]
Media: 7.0

Con un for-each e voti.remove(...) la lista cambierebbe mentre la stai scorrendo e Java lancerebbe ConcurrentModificationException. L'Iterator invece sa di aver tolto l'elemento e continua dal punto giusto. Il cast (double) serve per non fare la divisione tra interi.

06Parentesi bilanciate medio

Scrivi il metodo static boolean bilanciata(String s) che usa una pila per dire se le parentesi tonde di s sono bilanciate. Esempi: "(a+b)*(c)" → true; "((a)" → false; ")(" → false.

Soluzione
static boolean bilanciata(String s) {
    Deque<Character> pila = new LinkedList<>();
    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (c == '(') {
            pila.push(c);
        } else if (c == ')') {
            if (pila.isEmpty()) {
                return false;          // chiusa senza nessuna aperta
            }
            pila.pop();
        }
    }
    return pila.isEmpty();             // nessuna aperta rimasta senza chiusura
}

Ogni ( va nella pila, ogni ) ne toglie una. Due errori possibili: una ) quando la pila è vuota (")("), oppure qualche ( rimasta alla fine ("((a)"). Con un solo tipo di parentesi basterebbe un contatore; la pila diventa indispensabile con più tipi, ( [ {: lì si fa push della parentesi aperta e al momento della chiusa si controlla che pop() sia quella giusta.

07La coda della segreteria completo

Scrivi una classe Segreteria che gestisce la fila degli studenti allo sportello, con un attributo Deque<String> fila e i metodi:

  • arriva(String nome): lo studente si mette in fondo alla fila;
  • arrivaUrgente(String nome): lo studente passa davanti a tutti;
  • servi(): restituisce il nome del prossimo da servire e lo toglie dalla fila, oppure "Nessuno in fila" se è vuota;
  • quanti(): quanti studenti aspettano.

Nel main fai arrivare Anna, Bruno e Carla, poi Dario urgente, e servi 5 volte stampando il risultato.

Soluzione
import java.util.Deque;
import java.util.LinkedList;

class Segreteria {
    private Deque<String> fila = new LinkedList<>();

    void arriva(String nome) {
        fila.offerLast(nome);
    }

    void arrivaUrgente(String nome) {
        fila.offerFirst(nome);
    }

    String servi() {
        String prossimo = fila.pollFirst();
        if (prossimo == null) {
            return "Nessuno in fila";
        }
        return prossimo;
    }

    int quanti() {
        return fila.size();
    }
}

public class Main {
    public static void main(String[] args) {
        Segreteria s = new Segreteria();
        s.arriva("Anna");
        s.arriva("Bruno");
        s.arriva("Carla");
        s.arrivaUrgente("Dario");
        System.out.println("In fila: " + s.quanti());

        for (int i = 0; i < 5; i++) {
            System.out.println("Servo: " + s.servi());
        }
    }
}
In fila: 4
Servo: Dario
Servo: Anna
Servo: Bruno
Servo: Carla
Servo: Nessuno in fila
  • Si usa una Deque perché servono entrambe le estremità: in fondo per chi arriva, in testa per l'urgente e per servire.
  • pollFirst() restituisce null quando la fila è vuota, invece di lanciare un'eccezione come removeFirst(): comodo per il quinto servi().
  • LinkedList è la scelta giusta: tutte le operazioni sono sulle estremità, quindi O(1).
