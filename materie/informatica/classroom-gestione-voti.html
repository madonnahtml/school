Scenario

Realizzare un programma Java chiamato GestioneVoti. Il programma deve permettere di gestire i voti di una classe. Avremo inizialmente un array contenente alcuni voti:

int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

Il programma dovrà progressivamente diventare più strutturato attraverso l'utilizzo di array, metodi e Wrapper Classes.

Tienili a menteQuesti otto voti tornano in tutta l'esercitazione. Conviene sapere già i risultati, così controlli subito se il programma sbaglia: 8 voti, somma 60, media 7.5, massimo 10, minimo 5. Indici da 0 a 7.

Parte 1 – Creazione dell'array

Ripasso lampoUn array è una fila di variabili dello stesso tipo, numerate da 0. Si legge una casella con voti[indice]. Teoria: Creare un array e usare gli indici.
01Esercizio 1 · Primo, quarto e ultimo voto facile

Consegna. Creare il progetto Java e una classe:

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

    }
}

Esercizio 1. Visualizzare:

  1. il primo voto;
  2. il quarto voto;
  3. l'ultimo voto.

Utilizzare gli indici dell'array.

Domande

A. Qual è l'indice del primo elemento?
B. Qual è l'indice dell'ultimo elemento?
C. Perché non possiamo utilizzare voti[8]?

Risposta spiegata

Ragionamento

  1. Gli indici partono da 0: il primo voto è voti[0].
  2. Il quarto voto non è voti[4] ma voti[3]: la posizione "umana" meno uno.
  3. Gli elementi sono 8, quindi l'ultimo indice è 8 − 1 = 7. Invece di scrivere 7 "a mano" scrivo voti.length - 1: così funziona anche se domani i voti diventano 20.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        // gli indici partono da 0
        System.out.println("Primo voto: " + voti[0]);
        System.out.println("Quarto voto: " + voti[3]);
        // l'ultimo indice e' length - 1 (qui 7)
        System.out.println("Ultimo voto: " + voti[voti.length - 1]);
    }
}

Output

Primo voto: 7
Quarto voto: 9
Ultimo voto: 7

Risposte alle domande

Indice01234567
Voto786958107
  • A. L'indice del primo elemento è 0. In Java (come in C) l'indice dice "quanti passi faccio dall'inizio": per il primo non ne faccio nessuno.
  • B. L'indice dell'ultimo elemento è 7, cioè voti.length - 1. In generale, con n elementi gli indici vanno da 0 a n − 1.
  • C. Perché la casella 8 non esiste: le caselle sono 8 ma numerate da 0 a 7. Il programma compila (il compilatore non controlla gli indici), ma quando lo esegui si ferma con un errore. Ecco cosa succede davvero con System.out.println(voti[8]);:
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 8 out of bounds for length 8
	at ProvaIndice.main(ProvaIndice.java:6)

Il messaggio si legge così: "indice 8 fuori dai limiti per lunghezza 8". È l'errore più classico con gli array: l'indice ha "sforato" di uno.

Parte 2 – Proprietà length

Ripasso lampovoti.length dice quante caselle ha l'array. È una proprietà, quindi senza parentesi. Teoria: length, for e foreach.
02Esercizio 2 · Quanti voti ci sono facile

Consegna. Utilizzare voti.length per visualizzare il numero di voti presenti. Esempio:

System.out.println("Numero voti: " + voti.length);

Ricorda: length è una proprietà dell'array e non un metodo, quindi non bisogna scrivere length().

Esercizio 2. Visualizzare:

Numero di voti: 8

senza scrivere direttamente il numero 8.

Risposta spiegata

Ragionamento

  1. Il numero 8 non lo scrivo io: lo chiedo all'array con voti.length.
  2. Lo concateno alla scritta con +.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        // length e' una proprieta': si scrive senza parentesi
        System.out.println("Numero di voti: " + voti.length);
    }
}

Output

Numero di voti: 8

Perché funziona

Se aggiungo un voto nelle graffe, l'output diventa 9 da solo, senza toccare la println. È proprio il motivo per cui la consegna vieta di scrivere 8: un numero "scritto a mano" va cambiato ovunque ogni volta che cambiano i dati.

Errori da evitare

Non confondere: per gli array è voti.length (proprietà), per le stringhe è nome.length() (metodo, con le parentesi). Scrivere voti.length() non compila.

Parte 3 – Ciclo for

Ripasso lampoIl for classico usa un contatore i che va da 0 a length - 1: dentro il ciclo ho sia l'indice i sia il valore voti[i]. Teoria: length, for e foreach.
03Tutti i voti numerati con il for facile

Consegna. Utilizzare un ciclo for per visualizzare tutti i voti. Il ciclo for è particolarmente utile quando è necessario conoscere l'indice dell'elemento. Modificare il programma affinché visualizzi:

Voto 1: 7
Voto 2: 8
Voto 3: 6
...

Attenzione: l'indice dell'array parte da 0, ma per l'utente il primo voto deve essere indicato come 1.

Risposta spiegata

Ragionamento

  1. Il ciclo parte da i = 0 e continua finché i < voti.length (quindi l'ultimo giro è con i = 7).
  2. Il valore lo leggo con voti[i].
  3. Il numero da mostrare all'utente è i + 1, tra parentesi: senza parentesi Java incollerebbe le stringhe e scriverebbe "Voto 01", "Voto 11"...

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        // i va da 0 a voti.length - 1
        for (int i = 0; i < voti.length; i++) {
            // all'utente mostro i + 1, cosi' il primo voto e' "Voto 1"
            System.out.println("Voto " + (i + 1) + ": " + voti[i]);
        }
    }
}

Output

Voto 1: 7
Voto 2: 8
Voto 3: 6
Voto 4: 9
Voto 5: 5
Voto 6: 8
Voto 7: 10
Voto 8: 7

Errori da evitare

  • i <= voti.length: un giro di troppo, all'ultimo giro voti[8] e quindi ArrayIndexOutOfBoundsException.
  • "Voto " + i + 1: si legge da sinistra a destra, "Voto " + 0 diventa la stringa "Voto 0", poi + 1 incolla "1" e viene "Voto 01". Servono le parentesi.

Parte 4 – Ciclo foreach

04Gli stessi voti con il foreach facile

Consegna. Riscrivere la visualizzazione dei voti utilizzando il ciclo foreach. Il foreach permette di attraversare tutti gli elementi senza gestire direttamente l'indice. Poi rispondere:

Domanda. Qual è la differenza principale tra for e foreach?

Risposta spiegata

Ragionamento

  1. La forma è for (tipo variabile : array), che si legge "per ogni voto contenuto in voti".
  2. A ogni giro la variabile voto contiene già il valore: niente i, niente voti[i].

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        // si legge: "per ogni voto contenuto in voti"
        for (int voto : voti) {
            System.out.println(voto);
        }
    }
}

Output

7
8
6
9
5
8
10
7

Risposta alla domanda

La differenza principale è l'indice: il for classico ce l'ha (i), il foreach no, ti dà direttamente il valore di ogni elemento.

for classicoforeach
Indicesì, ino
Ordine e passoli scegli tu (anche al contrario, o uno sì e uno no)sempre tutti, dal primo all'ultimo
Modificare l'arraysì, con voti[i] = ...no (vedi Parte 5)
Quando usarloserve la posizione ("Voto 1: 7") o devi cambiare i valoridevi solo leggere tutti i valori (stampa, somma, massimo)

Per questo nella Parte 3 serviva il for (dovevo scrivere "Voto 1", "Voto 2"), mentre qui basta il foreach, più corto e senza il rischio di sbagliare i limiti.

Parte 5 – Modificare un array

05Il 5 diventa 6 facile

Consegna. Modificare il voto 5 trasformandolo in 6. Utilizzare l'indice corretto. Esempio:

voti[4] = 6;

Successivamente visualizzare nuovamente l'array.

Domanda. Perché con un for possiamo facilmente modificare gli elementi dell'array mentre con un foreach è meno appropriato utilizzare la variabile del ciclo per modificare direttamente l'array?

Risposta spiegata

Ragionamento

  1. Il 5 è il quinto voto della lista, quindi sta all'indice 4.
  2. Un'assegnazione a voti[4] sostituisce il valore nella casella.
  3. Per ristampare uso il for della Parte 3, così vedo anche la posizione.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        // il 5 e' il quinto voto, quindi sta all'indice 4
        voti[4] = 6;

        for (int i = 0; i < voti.length; i++) {
            System.out.println("Voto " + (i + 1) + ": " + voti[i]);
        }
    }
}

Output

Voto 1: 7
Voto 2: 8
Voto 3: 6
Voto 4: 9
Voto 5: 6
Voto 6: 8
Voto 7: 10
Voto 8: 7

Risposta alla domanda

Nel foreach la variabile del ciclo (voto) è una copia del valore della casella, non la casella. Se le assegno un valore nuovo cambio solo la copia, e l'array resta com'era. Con il for invece ho l'indice i e scrivo direttamente voti[i] = ..., cioè dentro la casella vera. L'ho provato:

// tentativo SBAGLIATO: modifico la variabile del ciclo
for (int voto : voti) {
    if (voto == 5) {
        voto = 6;   // cambia solo la copia, non l'array
    }
}
System.out.println("Con foreach, voti[4] = " + voti[4]);

// modo corretto: con il for ho l'indice
for (int i = 0; i < voti.length; i++) {
    if (voti[i] == 5) {
        voti[i] = 6;
    }
}
System.out.println("Con for, voti[4] = " + voti[4]);
Con foreach, voti[4] = 5
Con for, voti[4] = 6

Il programma compila e non dà errori: semplicemente il foreach non ha cambiato niente. È un errore "silenzioso", per questo è meglio non usare il foreach per modificare.

Parte 6 – Calcolo della somma

Ripasso lampoAccumulatore: una variabile che parte da 0 e a ogni giro aggiunge il valore corrente. Teoria: Esempio guidato: somma, media e massimo.
06La somma dei voti facile

Consegna. Creare un programma che calcoli la somma di tutti i voti. Utilizzare una variabile:

int somma = 0;

e un ciclo. La logica fondamentale è:

somma += voto;

Le slide utilizzano proprio questo approccio nel calcolo della somma tramite foreach.

Obiettivo. Visualizzare:

Somma = ...
Risposta spiegata

Ragionamento

  1. somma parte da 0 (l'elemento "neutro" della somma).
  2. Con il foreach prendo un voto alla volta e lo aggiungo: somma += voto vuol dire somma = somma + voto.
  3. La stampa va dopo il ciclo, quando i voti sono stati sommati tutti.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        int somma = 0;   // l'accumulatore parte da zero
        for (int voto : voti) {
            somma += voto;   // somma = somma + voto
        }
        System.out.println("Somma = " + somma);
    }
}

Output

Somma = 60

Perché funziona

Ecco come cresce somma giro dopo giro: 0 → 7 → 15 → 21 → 30 → 35 → 43 → 53 → 60. Controllo a mano: 7+8+6+9+5+8+10+7 = 60.

Errori da evitare

  • Dichiarare int somma = 0; dentro il ciclo: verrebbe azzerata a ogni giro (e fuori dal ciclo non esisterebbe nemmeno).
  • Mettere la println dentro il ciclo: stamperebbe 8 somme parziali invece del risultato.

Parte 7 – Calcolo della media

07La media e il cast (double) facile

Consegna. Calcolare la media dei voti. Utilizzare:

double media = (double) somma / voti.length;

Domanda fondamentale. Perché è necessario utilizzare (double)?

Risposta spiegata

Ragionamento

  1. Calcolo la somma come nella Parte 6.
  2. Divido per voti.length, cioè per il numero di voti.
  3. Per vedere a cosa serve il cast, calcolo la media anche senza e confronto.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        int somma = 0;
        for (int voto : voti) {
            somma += voto;
        }

        // senza cast: divisione tra due int, la parte decimale si perde
        double mediaSbagliata = somma / voti.length;
        // con il cast: somma diventa double PRIMA della divisione
        double media = (double) somma / voti.length;

        System.out.println("Senza (double): " + mediaSbagliata);
        System.out.println("Media = " + media);
    }
}

Output

Senza (double): 7.0
Media = 7.5

Risposta alla domanda fondamentale

Perché somma e voti.length sono due int, e in Java la divisione tra due interi è una divisione intera: 60 / 8 fa 7 e il resto (0,5) viene buttato via. Solo dopo il 7 viene messo nella variabile double, diventando 7.0: ormai il mezzo voto è perso. Lo vedi nella prima riga dell'output.

Il cast (double) trasforma somma in 60.0 prima della divisione. Ora è "double diviso int", Java fa la divisione con la virgola e il risultato è 7.5.

Errori da evitare

(double) (somma / voti.length) dà ancora 7.0: le parentesi fanno eseguire prima la divisione intera, e il cast arriva troppo tardi. Il cast va sul numeratore.

Parte 8 – Massimo e minimo

08Voto massimo e voto minimo medio

Consegna. Creare due variabili:

int massimo = voti[0];
int minimo = voti[0];

Utilizzare un ciclo per individuare:

  • voto massimo;
  • voto minimo.

Output previsto

Voto massimo: 10
Voto minimo: 5

Importante: non utilizzare Math.max() o Math.min(). L'obiettivo è esercitarsi con array e cicli.

Risposta spiegata

Ragionamento

  1. Il "campione provvisorio" all'inizio è il primo voto: sia per il massimo sia per il minimo.
  2. Scorro tutti i voti. Se ne trovo uno più grande del massimo attuale, diventa il nuovo massimo.
  3. Nello stesso giro, se ne trovo uno più piccolo del minimo attuale, diventa il nuovo minimo. Due if separati, non else if: un voto va confrontato con entrambi.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        // si parte dal primo voto, non da 0
        int massimo = voti[0];
        int minimo = voti[0];

        for (int voto : voti) {
            if (voto > massimo) {
                massimo = voto;
            }
            if (voto < minimo) {
                minimo = voto;
            }
        }
        System.out.println("Voto massimo: " + massimo);
        System.out.println("Voto minimo: " + minimo);
    }
}

Output

Voto massimo: 10
Voto minimo: 5

Perché partire da voti[0]

Se scrivessi int minimo = 0;, nessun voto sarebbe mai minore di 0 e il programma direbbe "Voto minimo: 0", un voto che non esiste. Partendo da un elemento vero dell'array il risultato è sempre uno dei voti. Il massimo con 0 qui funzionerebbe per caso (i voti sono positivi), ma con voti[0] funziona sempre.

Parte 9 – Trasformare il programma in metodi

Ripasso lampoUn metodo è un blocco di codice con un nome che svolge un compito. void = non restituisce niente; un tipo (int, double) = restituisce un valore con return. Teoria: I metodi e Metodi e array: un programma strutturato.
09Cinque metodi per cinque compiti medio

Consegna. A questo punto il programma deve essere riorganizzato. Le slide sottolineano che un metodo deve svolgere un compito specifico e che suddividere il programma in metodi rende il codice più leggibile e manutenibile. Creare i seguenti metodi:

static void stampaVoti(int[] voti)
static int calcolaSomma(int[] voti)
static double calcolaMedia(int[] voti)
static int trovaMassimo(int[] voti)
static int trovaMinimo(int[] voti)
Risposta spiegata

Ragionamento

  1. Ogni pezzo delle Parti 4–8 diventa un metodo: il ciclo di stampa va in stampaVoti, l'accumulatore in calcolaSomma, e così via.
  2. Ogni metodo riceve l'array come parametro (int[] voti): così lavora sui dati che gli passa il main, non su una variabile "sua".
  3. Il tipo prima del nome dice cosa restituisce: stampaVoti stampa e basta (void), gli altri calcolano un numero e lo restituiscono con return.
  4. I metodi sono static perché li chiamo dal main, che è static, senza creare oggetti.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        // il main ora "dirige": ogni compito lo fa un metodo
        stampaVoti(voti);
        System.out.println("Somma: " + calcolaSomma(voti));
        System.out.println("Media: " + calcolaMedia(voti));
        System.out.println("Voto massimo: " + trovaMassimo(voti));
        System.out.println("Voto minimo: " + trovaMinimo(voti));
    }

    // stampa i voti, uno per riga (non restituisce nulla)
    static void stampaVoti(int[] voti) {
        for (int voto : voti) {
            System.out.println(voto);
        }
    }

    // restituisce la somma di tutti i voti
    static int calcolaSomma(int[] voti) {
        int somma = 0;
        for (int voto : voti) {
            somma += voto;
        }
        return somma;
    }

    // restituisce la media (riusa calcolaSomma)
    static double calcolaMedia(int[] voti) {
        return (double) calcolaSomma(voti) / voti.length;
    }

    // restituisce il voto piu' alto
    static int trovaMassimo(int[] voti) {
        int massimo = voti[0];
        for (int voto : voti) {
            if (voto > massimo) {
                massimo = voto;
            }
        }
        return massimo;
    }

    // restituisce il voto piu' basso
    static int trovaMinimo(int[] voti) {
        int minimo = voti[0];
        for (int voto : voti) {
            if (voto < minimo) {
                minimo = voto;
            }
        }
        return minimo;
    }
}

Output

8
6
9
5
8
10
7
Somma: 60
Media: 7.5
Voto massimo: 10
Voto minimo: 5

Perché conviene

  • Leggibilità: il main ora si legge come un indice ("stampa, somma, media, massimo, minimo"); i dettagli sono nei metodi.
  • Manutenzione: se il calcolo del massimo è sbagliato, so esattamente dove guardare.
  • Riuso: calcolaMedia non riscrive la somma, chiama calcolaSomma. E posso chiamare gli stessi metodi su un altro array (per esempio i voti di un'altra classe).

Le Parti 10, 11 e 12 guardano da vicino tre di questi metodi uno per uno.

Parte 10 – Metodo void

10stampaVoti: perché void facile

Consegna. Realizzare:

static void stampaVoti(int[] voti) {

    for (int voto : voti) {
        System.out.println(voto);
    }

}

Nel main:

stampaVoti(voti);

Domanda. Perché il metodo è dichiarato void e non int?

Risposta spiegata

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        stampaVoti(voti);   // chiamata "da sola": non c'e' niente da salvare
    }

    static void stampaVoti(int[] voti) {

        for (int voto : voti) {
            System.out.println(voto);
        }
    }
}

Output

7
8
6
9
5
8
10
7

Risposta alla domanda

Perché il compito del metodo è fare qualcosa (stampare a video), non calcolare un risultato da restituire. Non c'è nessun numero che il main debba ricevere indietro, quindi il tipo di ritorno è void ("vuoto"). Infatti nel main la chiamata è da sola, stampaVoti(voti);, e non int x = stampaVoti(voti);.

Se lo dichiarassi int il compilatore pretenderebbe un return con un numero intero, e io non ho niente di sensato da restituire. Infatti, cambiando solo void in int, javac risponde:

ProvaInt.java:13: error: missing return statement
    }
    ^
1 error

"missing return statement" = manca l'istruzione return: un metodo int deve restituire un int in ogni caso.

Parte 11 – Metodo con return

11calcolaSomma restituisce un valore facile

Consegna. Creare:

static int calcolaSomma(int[] voti) {

    int somma = 0;

    for (int voto : voti) {
        somma += voto;
    }

    return somma;
}

Nel main:

int somma = calcolaSomma(voti);

e successivamente:

System.out.println("Somma: " + somma);

Un metodo con return restituisce un valore al punto in cui viene chiamato.

Risposta spiegata

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        // il valore restituito "torna qui" e lo salvo in una variabile
        int somma = calcolaSomma(voti);

        System.out.println("Somma: " + somma);
    }

    static int calcolaSomma(int[] voti) {

        int somma = 0;

        for (int voto : voti) {
            somma += voto;
        }

        return somma;
    }
}

Output

Somma: 60

Perché funziona

  1. Il main arriva a calcolaSomma(voti) e "salta" dentro il metodo, passandogli l'array.
  2. Il metodo fa il ciclo e arriva a return somma;: il valore 60 viene spedito indietro e il metodo finisce.
  3. Nel main, al posto della chiamata è come se ci fosse scritto 60: int somma = 60;.

Da notare: ci sono due variabili somma, una nel main e una nel metodo. Sono diverse: ognuna vive solo dentro il suo metodo. Il collegamento tra le due lo fa solo il return.

Parte 12 – Metodo per la media

12calcolaMedia riusa calcolaSomma facile

Consegna. Creare:

static double calcolaMedia(int[] voti) {

    return (double) calcolaSomma(voti) / voti.length;

}

Nel main:

double media = calcolaMedia(voti);

System.out.println("Media: " + media);

Questo esercizio riprende direttamente il modello delle slide relativo ai metodi che ricevono un array e restituiscono un risultato.

Risposta spiegata

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int[] voti = {7, 8, 6, 9, 5, 8, 10, 7};

        double media = calcolaMedia(voti);

        System.out.println("Media: " + media);
    }

    static int calcolaSomma(int[] voti) {
        int somma = 0;
        for (int voto : voti) {
            somma += voto;
        }
        return somma;
    }

    static double calcolaMedia(int[] voti) {

        // un metodo puo' chiamarne un altro: riuso calcolaSomma
        return (double) calcolaSomma(voti) / voti.length;
    }
}

Media: 7.5

Perché funziona

  • calcolaMedia ha bisogno della somma ma non la ricalcola: chiama calcolaSomma, che deve quindi esistere nella stessa classe.
  • L'ordine è: prima calcolaSomma(voti) dà 60, poi il cast lo rende 60.0, poi la divisione per 8 dà 7.5. Il cast è sul risultato di calcolaSomma, cioè sul numeratore, come nella Parte 7.
  • Il tipo di ritorno è double perché la media può avere la virgola; se fosse int, 7.5 non ci starebbe.

Parte 14 – Autoboxing

14Da int a Integer da solo facile

Consegna. Autoboxing, cioè la conversione automatica:

int → Integer

come mostrato nelle slide.

(La consegna è solo il titolo dell'argomento: la risposta mostra un esempio che lo mette in pratica.)

Risposta spiegata

Ragionamento

  1. Parto da un int e lo assegno a una variabile Integer, senza scrivere nessuna conversione.
  2. Per vedere cosa fa Java "di nascosto", faccio la stessa cosa anche a mano con Integer.valueOf.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        int voto = 9;                // tipo primitivo

        Integer votoOggetto = voto;  // AUTOBOXING: int -> Integer, fatto da Java

        // e' come se Java avesse scritto per noi:
        Integer votoOggetto2 = Integer.valueOf(voto);

        System.out.println("int: " + voto);
        System.out.println("Integer (autoboxing): " + votoOggetto);
        System.out.println("Integer (a mano): " + votoOggetto2);
    }
}

Output

int: 9
Integer (autoboxing): 9
Integer (a mano): 9

Perché funziona

Boxing = "mettere nella scatola": il numero 9 viene chiuso dentro un oggetto Integer. Auto perché lo fa il compilatore al posto nostro: dove serve un Integer e trova un int, aggiunge lui Integer.valueOf(...). Succede anche nella Parte 13 (Integer voto = 8;: 8 è un int), e ogni volta che fai lista.add(7) su un ArrayList<Integer>.

Parte 15 – Unboxing

15Da Integer a int da solo facile

Consegna.

Integer → int

Questa operazione prende il nome di: unboxing.

(Anche qui la consegna presenta solo l'argomento: la risposta lo mostra in un programma.)

Risposta spiegata

Ragionamento

  1. È il contrario della Parte 14: assegno un Integer a un int e Java tira fuori il numero dalla "scatola".
  2. L'unboxing avviene anche quando uso un Integer in un calcolo (+, >...), perché gli operatori aritmetici lavorano sui primitivi.
  3. Provo anche il caso pericoloso: un Integer che vale null.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        Integer votoOggetto = 7;          // autoboxing

        int voto = votoOggetto;           // UNBOXING: Integer -> int, fatto da Java

        // e' come se Java avesse scritto per noi:
        int voto2 = votoOggetto.intValue();

        // unboxing anche dentro un calcolo: + lavora sui primitivi
        int bonus = votoOggetto + 1;

        System.out.println("int (unboxing): " + voto);
        System.out.println("int (a mano): " + voto2);
        System.out.println("Con bonus: " + bonus);

        // ATTENZIONE: un Integer null non si puo' "spacchettare"
        Integer assente = null;
        try {
            int x = assente;              // unboxing di null
            System.out.println(x);
        } catch (NullPointerException e) {
            System.out.println("Unboxing di null: NullPointerException");
        }
    }
}

Output

int (unboxing): 7
int (a mano): 7
Con bonus: 8
Unboxing di null: NullPointerException

Errori da evitare

L'unboxing di un Integer che vale null compila, ma durante l'esecuzione lancia NullPointerException: dentro la scatola non c'è nessun numero da tirare fuori. Un int non può mai essere "vuoto", quindi Java non sa cosa metterci. (Il try/catch qui serve solo a mostrare l'errore senza far fermare il programma.)

Parte 16 – Conversione di stringhe

16parseInt, parseDouble e la media di tre stringhe facile

Consegna. Utilizzare:

Integer.parseInt("25");

per trasformare la stringa "25" in un numero intero. Poi utilizzare:

Double.parseDouble("12.5");

per trasformare "12.5" in un double. Le slide presentano inoltre Integer.toString() per effettuare la conversione inversa da intero a stringa.

Esercizio. Scrivere un programma che trasformi:

String voto1 = "7";
String voto2 = "8";
String voto3 = "9";

in numeri interi e calcoli la loro media.

Risposta spiegata

Ragionamento

  1. Prima provo le tre conversioni della consegna, facendo un calcolo con ciascuna per vedere se il risultato è davvero un numero (o una stringa).
  2. Faccio vedere cosa succede se "sommo" le stringhe senza convertirle.
  3. Converto i tre voti con Integer.parseInt, li sommo e divido per 3 con il cast (double), come nella Parte 7.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        // conversioni di prova
        int n = Integer.parseInt("25");
        double d = Double.parseDouble("12.5");
        String s = Integer.toString(n);

        System.out.println("parseInt(\"25\") + 1 = " + (n + 1));
        System.out.println("parseDouble(\"12.5\") * 2 = " + (d * 2));
        System.out.println("toString(25) + 1 = " + (s + 1));

        // esercizio: tre voti scritti come testo
        String voto1 = "7";
        String voto2 = "8";
        String voto3 = "9";

        // senza conversione il + incolla le stringhe
        System.out.println("Senza conversione: " + (voto1 + voto2 + voto3));

        int v1 = Integer.parseInt(voto1);
        int v2 = Integer.parseInt(voto2);
        int v3 = Integer.parseInt(voto3);

        int somma = v1 + v2 + v3;
        double media = (double) somma / 3;

        System.out.println("Somma: " + somma);
        System.out.println("Media: " + media);
    }
}

Output

parseInt("25") + 1 = 26
parseDouble("12.5") * 2 = 25.0
toString(25) + 1 = 251
Senza conversione: 789
Somma: 24
Media: 8.0

Perché funziona

  • "25" tra virgolette è testo, due caratteri. parseInt lo "legge" e restituisce il numero 25: infatti +1 dà 26. Al contrario, dopo toString torna testo e +1 incolla: "251".
  • Allo stesso modo "7" + "8" + "9" dà "789", non 24. Per questo bisogna convertire prima di fare conti. È quello che serve quando i numeri arrivano dalla tastiera o da un file, che danno sempre stringhe.
  • (7 + 8 + 9) / 3 = 24 / 3 = 8, quindi la media è 8.0.

Errori da evitare

Integer.parseInt("sette") o Integer.parseInt("7.5") fanno fermare il programma con NumberFormatException: la stringa deve contenere un intero scritto con le cifre. Per i decimali si usa Double.parseDouble, con il punto, non la virgola.

Parte 17 – Method overloading

Ripasso lampoOverload = più metodi con lo stesso nome nella stessa classe, ma con parametri diversi (nel numero, nel tipo o nell'ordine). Java sceglie quello giusto guardando gli argomenti della chiamata. Teoria: Overload dei metodi.
17somma() con 2 e con 3 parametri medio

Consegna. Ora aggiungere al programma: somma() con un determinato numero di parametri. Creare un altro metodo con lo stesso nome, ma un numero diverso di parametri. È un esempio di method overloading.

Risposta spiegata

Ragionamento

  1. Scelgo le firme che poi servono nell'esercizio finale: somma(int a, int b) e somma(int a, int b, int c). Tutte e due restituiscono un int.
  2. Stesso nome, ma uno ha 2 parametri e l'altro 3: le firme sono diverse, quindi possono convivere.
  3. Nel main chiamo somma una volta con due argomenti e una volta con tre: Java conta gli argomenti e sceglie da solo.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        // Java sceglie il metodo guardando QUANTI argomenti passo
        System.out.println("Somma di 2 numeri: " + somma(5, 10));
        System.out.println("Somma di 3 numeri: " + somma(5, 10, 15));
    }

    // versione con 2 parametri
    static int somma(int a, int b) {
        return a + b;
    }

    // stesso nome, ma 3 parametri: e' un overload
    static int somma(int a, int b, int c) {
        return a + b + c;
    }
}

Output

Somma di 2 numeri: 15
Somma di 3 numeri: 30

Perché funziona

Per Java un metodo è identificato dalla sua firma: nome + lista dei tipi dei parametri. Qui le firme sono somma(int, int) e somma(int, int, int): diverse, quindi sono due metodi distinti. Il vantaggio è che chi usa il programma ricorda un solo nome, "somma", invece di somma2, somma3... Un esempio che usi da sempre: System.out.println è overloaded (una versione per int, una per String, una per double...).

Parte 18 – Overload per tipo

18somma() per int e per double medio

Consegna. Effettuare un overload per tipo.

Risposta spiegata

Ragionamento

  1. Questa volta il numero di parametri resta uguale (2), cambia il loro tipo: somma(int a, int b) e somma(double a, double b).
  2. La versione double restituisce un double, perché la somma di due decimali può avere la virgola.
  3. Per vedere quale versione sceglie Java, ognuna stampa il proprio nome tra quadre prima del risultato.

Codice

public class GestioneVoti {

    public static void main(String[] args) {

        // stesso numero di argomenti: Java guarda il loro TIPO
        System.out.println("Somma di due int: " + somma(5, 10));
        System.out.println("Somma di due double: " + somma(7.5, 8.0));
    }

    static int somma(int a, int b) {
        System.out.print("[uso somma(int, int)] ");
        return a + b;
    }

    // stesso nome e stesso numero, ma tipi diversi: overload per tipo
    static double somma(double a, double b) {
        System.out.print("[uso somma(double, double)] ");
        return a + b;
    }
}

Output

[uso somma(int, int)] Somma di due int: 15
[uso somma(double, double)] Somma di due double: 15.5

Perché funziona

  • somma(5, 10): 5 e 10 sono letterali int, quindi Java sceglie somma(int, int). somma(7.5, 8.0): sono letterali double (hanno il punto), quindi sceglie somma(double, double).
  • Le scritte tra quadre escono prima di "Somma di...": Java deve prima eseguire il metodo per sapere il valore da concatenare, e la print dentro il metodo avviene in quel momento. Poi la println del main stampa la riga intera.
  • Il fatto che i due metodi abbiano tipi di ritorno diversi (int e double) qui va bene perché i parametri sono diversi. Se cambiasse solo il tipo di ritorno, invece, sarebbe un errore: è la Parte 19.

Parte 19 – Errore da individuare

19Overload solo sul tipo di ritorno medio

Consegna. Provare a dichiarare:

static int somma(int a, int b) {
    return a + b;
}

e:

static double somma(int a, int b) {
    return a + b;
}

Domanda. Perché Java genera un errore?

Risposta da motivare.

Risposta spiegata

Il programma provato

public class GestioneVoti {

    public static void main(String[] args) {
        System.out.println(somma(3, 4));
    }

    static int somma(int a, int b) {
        return a + b;
    }

    static double somma(int a, int b) {
        return a + b;
    }
}

L'errore vero di javac

GestioneVoti.java:11: error: method somma(int,int) is already defined in class GestioneVoti
    static double somma(int a, int b) {
                  ^
1 error

Traduzione: "il metodo somma(int,int) è già definito nella classe GestioneVoti". L'errore è alla riga 11, cioè sul secondo metodo: per il compilatore è un doppione del primo.

Risposta motivata

  1. La firma di un metodo, quella che Java usa per distinguere i metodi, è fatta da nome + tipi dei parametri. Il tipo di ritorno non fa parte della firma. Guarda il messaggio: dice somma(int,int), senza nominare int o double come ritorno.
  2. Qui entrambi i metodi hanno firma somma(int, int): per Java sono lo stesso metodo scritto due volte.
  3. Il motivo pratico: davanti alla chiamata somma(3, 4), Java sceglie il metodo guardando solo gli argomenti (due int), e qui vanno bene tutti e due. Non può decidere in base al ritorno, anche perché il risultato si può perfino ignorare: somma(3, 4); da sola è un'istruzione valida, e lì nessuno "chiede" un int o un double. Sarebbe un'ambiguità impossibile da risolvere, quindi il linguaggio la vieta.

Come correggere

Si cambiano i parametri, non il ritorno: static double somma(double a, double b), come nella Parte 18. Oppure, se serve davvero un risultato diverso con gli stessi parametri, si usa un altro nome (per esempio sommaComeDouble).

    }

    static void stampaVoti(Integer[] voti) {
        // nessuna conversione: voto e' un Integer e println lo stampa
        for (Integer voto : voti) {
            System.out.println(voto);
        }
    }

    static int calcolaSomma(Integer[] voti) {
        int somma = 0;
        for (Integer voto : voti) {
            somma += voto;      // UNBOXING: voto (Integer) -> int per fare il +
        }
        return somma;
    }

    static double calcolaMedia(Integer[] voti) {
        return (double) calcolaSomma(voti) / voti.length;
    }

    static int trovaMassimo(Integer[] voti) {
        int massimo = voti[0];  // UNBOXING: voti[0] (Integer) -> int
        for (Integer voto : voti) {
            if (voto > massimo) {   // UNBOXING: > confronta numeri, non oggetti
                massimo = voto;     // UNBOXING: Integer -> int
            }
        }
        return massimo;
    }

    static int trovaMinimo(Integer[] voti) {
        int minimo = voti[0];   // UNBOXING
        for (Integer voto : voti) {
            if (voto < minimo) {    // UNBOXING
                minimo = voto;      // UNBOXING
            }
        }
        return minimo;
    }
}

Dove entrano in gioco autoboxing e unboxing

  • Autoboxing (int → Integer): nella creazione dell'array {7, 8, 6, ...}. Quei numeri sono letterali int, ma ogni casella vuole un Integer: Java li "inscatola" uno per uno.
  • Unboxing (Integer → int):
    • in somma += voto: l'addizione si fa sui primitivi;
    • in int massimo = voti[0] e int minimo = voti[0]: assegno un Integer a un int;
    • nei confronti voto > massimo e voto < minimo;
    • in massimo = voto e minimo = voto.
  • Nessuna conversione in stampaVoti: println riceve l'oggetto Integer e lo stampa così com'è. E calcolaMedia lavora sull'int restituito da calcolaSomma, quindi lì l'unboxing è già avvenuto prima.

Errori da evitare

Se una casella di un Integer[] fosse null (per esempio in un new Integer[3] non riempito), la riga somma += voto farebbe un unboxing di null e il programma si fermerebbe con NullPointerException, come nella Parte 15. Con int[] questo non può succedere.

Risposta spiegata
  1. Che cos'è un array? Una struttura che contiene più valori dello stesso tipo sotto un unico nome, in caselle numerate. La dimensione si decide alla creazione e poi non cambia. Esempio: int[] voti = {7, 8, 6}; sono tre int in un'unica variabile, invece di voto1, voto2, voto3.
  2. Da quale indice parte un array Java? Da 0. Di conseguenza l'ultimo indice è length - 1. Esempio: in GestioneVoti gli indici vanno da 0 a 7; voti[8] dà ArrayIndexOutOfBoundsException (Esercizio 1).
  3. A cosa serve length? Dice quanti elementi ha l'array. È una proprietà, senza parentesi. Serve per non scrivere numeri "a mano": nei cicli (i < voti.length) e nei calcoli (la media divide per voti.length).
  4. Differenza tra for e foreach? Il for classico usa un indice: posso scegliere da dove partire, saltare elementi, conoscere la posizione e modificare le caselle. Il foreach scorre sempre tutti gli elementi in ordine e dà direttamente il valore, senza indice: è più semplice ma serve solo per leggere (Parti 4 e 5).
  5. Che cosa significa return? Termina il metodo e restituisce un valore al punto in cui il metodo è stato chiamato. Il tipo del valore deve corrispondere al tipo dichiarato del metodo. Esempio: return somma; in calcolaSomma fa "tornare" 60 nel main.
  6. Metodo void e metodo che restituisce un valore? Il metodo void esegue un'azione (per esempio stampa) e non restituisce niente: si chiama da solo, stampaVoti(voti);. Quello con un tipo (int, double...) calcola un risultato e lo restituisce con return: si usa dentro un'espressione o un'assegnazione, int s = calcolaSomma(voti);.
  7. Che cos'è una Wrapper Class? Una classe che "avvolge" un tipo primitivo dentro un oggetto. Serve dove Java accetta solo oggetti (le collezioni), offre metodi utili (le conversioni) e permette il valore null. Ce n'è una per ogni primitivo: Integer, Double, Float, Boolean, Character...
  8. Qual è la Wrapper Class di int? Integer (attenzione: non "Int"). Le altre si chiamano come il primitivo con la maiuscola, tranne char → Character.
  9. Che cos'è l'autoboxing? La conversione automatica da tipo primitivo a wrapper, fatta dal compilatore. Esempio: Integer voto = 8; oppure lista.add(7) su un ArrayList<Integer>: Java scrive per noi Integer.valueOf(8).
  10. Che cos'è l'unboxing? La conversione automatica inversa, da wrapper a primitivo. Esempio: int x = votoOggetto; oppure somma += voto con voto di tipo Integer. Attenzione: l'unboxing di un null dà NullPointerException.
  11. A cosa serve Integer.parseInt()? Trasforma una stringa che contiene un numero intero nel numero int corrispondente, così si possono fare i calcoli. Esempio: Integer.parseInt("25") + 1 dà 26, mentre "25" + 1 dà "251". Se la stringa non è un intero valido lancia NumberFormatException.
  12. Che cos'è il method overloading? La possibilità di avere nella stessa classe più metodi con lo stesso nome ma parametri diversi. Java sceglie quale eseguire guardando gli argomenti della chiamata. Esempio: somma(5, 10), somma(5, 10, 15) e somma(7.5, 8.0) chiamano tre metodi diversi.
  13. Quali caratteristiche devono avere due metodi overloaded? Lo stesso nome, nella stessa classe, e una lista di parametri diversa: nel numero (somma(int, int) e somma(int, int, int)), nel tipo (somma(int, int) e somma(double, double)) o nell'ordine dei tipi (f(int, double) e f(double, int)). I nomi dei parametri non contano.
  14. Si può fare overload cambiando solo il tipo di ritorno? No. Il tipo di ritorno non fa parte della firma: due metodi con stesso nome e stessi parametri sono lo stesso metodo, e il compilatore dà error: method somma(int,int) is already defined (Parte 19). Java sceglie il metodo dagli argomenti, e da quelli non potrebbe capire quale dei due si vuole.
  15. Perché è utile dividere un programma in più metodi? Perché ogni metodo fa un solo compito con un nome chiaro: il main diventa leggibile come un elenco di passi, il codice si scrive una volta e si riusa (calcolaMedia riusa calcolaSomma), gli errori si trovano e si correggono in un punto solo, e ogni metodo si può provare da solo. In una parola: codice più leggibile e manutenibile.
