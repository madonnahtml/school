Esercizi: programmazione a oggetti

Consegne ed esercizi per allenarti su tutto il capitolo Java: programmazione a oggetti. Ogni soluzione spiega il ragionamento, mostra il codice completo e l'output vero del programma.

Come usare questa paginaLeggi la consegna, prova a scrivere il programma da solo (su carta o al computer) e solo dopo apri la soluzione spiegata. Gli esercizi vanno dal più facile al più difficile; l'ultimo li mette insieme tutti. Ogni programma è stato compilato ed eseguito: l'output che vedi è quello vero.
Una nota sui fileIn classe di solito ogni classe sta nel suo file (Studente.java, Main.java…). Qui, per avere ogni esercizio in un solo blocco da copiare, le classi "di supporto" sono scritte nello stesso file, prima della classe con il main, e senza public: in un file Java può esserci una sola classe public, quella che ha lo stesso nome del file. Il funzionamento è identico.

Classi, oggetti e attributi

Ripasso lampoLa classe è il modello, l'oggetto è una sua realizzazione concreta, creata con new. Gli attributi si dichiarano nel corpo della classe, fuori dai metodi, e si raggiungono con il punto: s1.nome. Se non li assegni valgono 0, false o null. Una variabile di tipo classe contiene un riferimento all'oggetto, non l'oggetto. Teoria: Classe e oggetto e Creare oggetti.
01Dalla descrizione alla classe Film facile

Consegna. Leggi questa descrizione: "Un film ha un titolo, un regista, un anno di uscita e una durata in minuti. Un film si può guardare, mettere in pausa e votare."

  1. Su carta: quali parole diventano attributi e quali diventerebbero metodi? Di che tipo è ogni attributo?
  2. Scrivi la classe Film con i soli attributi (i metodi arrivano nella prossima sezione).
  3. Nel main crea due film, "Inside Out" (2015, Pete Docter, 95 minuti) e "Interstellar" (2014, Christopher Nolan, 169 minuti), stampa una riga per ognuno e poi quanto dura la "maratona" dei due film in ore e minuti.

Output atteso:

Inside Out (2015) di Pete Docter, 95 minuti
Interstellar (2014) di Christopher Nolan, 169 minuti
Maratona: 4 ore e 24 minuti
Soluzione spiegata

Ragionamento

  1. Uso il trucco della teoria: i sostantivi sono attributi, i verbi sono metodi. Attributi: titolo e regista (testo, quindi String), anno e durata (numeri interi, quindi int). Metodi: guarda(), pausa(), vota().
  2. Gli attributi vanno nel corpo della classe, fuori da qualunque metodo. La classe da sola non fa niente: è solo lo stampino.
  3. Nel main creo ogni film con new Film() e riempio gli attributi con l'operatore punto: f1.titolo = ... si legge "il titolo di f1".
  4. Per le ore e i minuti uso la divisione intera e il resto: 264 / 60 = 4 ore, 264 % 60 = 24 minuti.

Codice

class Film {
    String titolo;
    String regista;
    int anno;
    int durata;   // in minuti
}

public class FilmInSala {
    public static void main(String[] args) {
        Film f1 = new Film();
        f1.titolo = "Inside Out";
        f1.regista = "Pete Docter";
        f1.anno = 2015;
        f1.durata = 95;

        Film f2 = new Film();
        f2.titolo = "Interstellar";
        f2.regista = "Christopher Nolan";
        f2.anno = 2014;
        f2.durata = 169;

        System.out.println(f1.titolo + " (" + f1.anno + ") di " + f1.regista + ", " + f1.durata + " minuti");
        System.out.println(f2.titolo + " (" + f2.anno + ") di " + f2.regista + ", " + f2.durata + " minuti");

        int totale = f1.durata + f2.durata;
        System.out.println("Maratona: " + totale / 60 + " ore e " + totale % 60 + " minuti");
    }
}

Da ricordare

  • f1 e f2 sono due oggetti indipendenti: hanno gli stessi attributi ma con valori propri. Cambiare f1.durata non tocca f2.durata.
  • La classe Film non è public perché sta nello stesso file di FilmInSala (vedi la nota in cima alla pagina). Il nome della classe è con la maiuscola, gli attributi con la minuscola.
  • In "Maratona: " + totale / 60 la divisione viene fatta prima del + (precedenza), quindi stampa 4 e non qualcosa di strano.
02Chi punta a chi? Riferimenti e valori di partenza difficile

Consegna. La classe è questa:

class Zaino {
    String colore;
    int libri;
    double peso;
    boolean pieno;
}

Senza eseguirlo, scrivi cosa stampa il frammento qui sotto. Poi rispondi: quanti oggetti Zaino esistono alla fine? Dopo a = c; lo zaino blu è cambiato?

Zaino a = new Zaino();
System.out.println(a.colore + " " + a.libri + " " + a.peso + " " + a.pieno);

a.colore = "blu";
a.libri = 3;
Zaino b = a;
b.libri = b.libri + 2;

Zaino c = new Zaino();
c.colore = "rosso";
a = c;
a.libri = 1;

System.out.println(b.colore + " " + b.libri);
System.out.println(c.colore + " " + c.libri);
System.out.println(a.colore + " " + a.libri);
Soluzione spiegata

Ragionamento: disegna le frecce

Le variabili a, b, c non sono zaini: sono frecce (riferimenti) che puntano a uno zaino. Gli zaini veri nascono solo con new: qui ce ne sono due, che chiamo Z1 e Z2.

Istruzionea punta ab punta ac punta aZ1Z2
a = new Zaino()Z1––null, 0, 0.0, false–
a.colore = "blu"; a.libri = 3Z1––blu, 3–
b = aZ1Z1–blu, 3–
b.libri = b.libri + 2Z1Z1–blu, 5–
c = new Zaino(); c.colore = "rosso"Z1Z1Z2blu, 5rosso, 0
a = cZ2Z1Z2blu, 5rosso, 0
a.libri = 1Z2Z1Z2blu, 5rosso, 1

Output

null 0 0.0 false
blu 5
rosso 1
rosso 1

Perché

  • Prima riga: nessun attributo è stato assegnato, quindi valgono i valori di partenza: null per la String, 0 per l'int, 0.0 per il double, false per il boolean. Attenzione: null unito a una stringa viene stampato come la parola "null".
  • b = a non crea un secondo zaino: dà un secondo nome allo stesso zaino. Per questo b.libri + 2 porta i libri dello zaino blu a 5.
  • a = c sposta solo la freccia a: ora punta allo zaino rosso. Lo zaino blu non cambia e resta raggiungibile tramite b.
  • Da quel momento a e c sono lo stesso zaino: a.libri = 1 si vede anche da c. Per questo le ultime due righe sono uguali.
Regola d'oroContare i new = contare gli oggetti. Un'assegnazione tra variabili (b = a, a = c) non crea e non copia oggetti: sposta frecce.

Metodi: cosa sa fare un oggetto

Ripasso lampoI metodi di un oggetto si scrivono dentro la classe, di solito senza static. Possono essere void (fanno qualcosa), ricevere parametri e restituire un valore con return. Si chiamano con il punto sull'oggetto (s1.studia()) e dentro il metodo gli attributi si usano direttamente per nome: sono quelli dell'oggetto su cui è stato chiamato. Teoria: I metodi.
03Il salvadanaio: tre tipi di metodo facile

Consegna. Scrivi la classe Salvadanaio con gli attributi proprietario (String) e soldi (double) e tre metodi:

  • mostra(): stampa di chi è il salvadanaio e quanti soldi contiene;
  • inserisci(double importo): aggiunge l'importo ai soldi;
  • puoComprare(double prezzo): restituisce true se i soldi bastano per quel prezzo.

Nel main crea il salvadanaio di Giulia, mostralo, inserisci 5 e 12.5 euro, mostralo di nuovo e chiedi se può comprare un libro da 15 euro e delle cuffie da 30.

Output atteso:

Salvadanaio di Giulia: 0.0 euro
Salvadanaio di Giulia: 17.5 euro
Può comprare un libro da 15 euro? true
Può comprare le cuffie da 30 euro? false
Soluzione spiegata

Ragionamento

  1. mostra deve solo stampare: non serve nessun dato da fuori e non restituisce niente, quindi è void senza parametri.
  2. inserisci ha bisogno di sapere quanto inserire: è un dato che arriva da fuori, quindi è un parametro. Modifica l'attributo soldi e non deve restituire nulla: void.
  3. puoComprare deve dare una risposta sì/no a chi la chiama: tipo di ritorno boolean. L'espressione soldi >= prezzo è già true o false, quindi la restituisco direttamente.
  4. Dentro i metodi scrivo soldi e proprietario senza niente davanti: sono gli attributi dell'oggetto su cui il metodo è stato chiamato (qui, il salvadanaio di Giulia).

Codice

class Salvadanaio {
    String proprietario;
    double soldi;

    void mostra() {
        System.out.println("Salvadanaio di " + proprietario + ": " + soldi + " euro");
    }

    void inserisci(double importo) {
        soldi = soldi + importo;
    }

    boolean puoComprare(double prezzo) {
        return soldi >= prezzo;
    }
}

public class Risparmi {
    public static void main(String[] args) {
        Salvadanaio s = new Salvadanaio();
        s.proprietario = "Giulia";
        s.mostra();

        s.inserisci(5);
        s.inserisci(12.5);
        s.mostra();

        System.out.println("Può comprare un libro da 15 euro? " + s.puoComprare(15));
        System.out.println("Può comprare le cuffie da 30 euro? " + s.puoComprare(30));
    }
}

Da notare

  • Alla prima chiamata di mostra() stampa 0.0: soldi non è mai stato assegnato e un double parte da 0.0.
  • s.inserisci(5) passa un int a un parametro double: Java lo allarga da solo a 5.0. Dopo i due inserimenti i soldi sono 5 + 12.5 = 17.5.
  • Il risultato di puoComprare viene usato (qui stampato). Se scrivessi solo s.puoComprare(15); la risposta verrebbe calcolata e buttata via.
04Stesso metodo, oggetti diversi medio

Consegna. Allo stadio ci sono due tornelli, Nord e Sud. Ecco la classe:

class Tornello {
    String ingresso;
    int passaggi;

    void passa() {
        passaggi++;
    }

    void passaGruppo(int persone) {
        for (int i = 0; i < persone; i++) {
            passa();
        }
    }

    boolean affollato(int limite) {
        return passaggi > limite;
    }
}

Dopo aver creato i due tornelli (nord e sud), il main esegue queste righe. Compila una tabella con i passaggi di ogni tornello dopo ogni istruzione e scrivi l'output.

nord.passa();
sud.passaGruppo(3);
nord.passaGruppo(4);
sud.passa();
nord.passa();

System.out.println(nord.ingresso + ": " + nord.passaggi);
System.out.println(sud.ingresso + ": " + sud.passaggi);
System.out.println("Totale: " + (nord.passaggi + sud.passaggi));
System.out.println("Nord affollato? " + nord.affollato(5));
System.out.println("Sud affollato? " + sud.affollato(5));
Soluzione spiegata

Ragionamento: la tabella

Ogni oggetto ha il suo attributo passaggi, che parte da 0. Un metodo chiamato su nord tocca solo i passaggi di nord.

Istruzionenord.passaggisud.passaggi
(appena creati)00
nord.passa()10
sud.passaGruppo(3)13
nord.passaGruppo(4)53
sud.passa()54
nord.passa()64

Output

Nord: 6
Sud: 4
Totale: 10
Nord affollato? true
Sud affollato? false

Perché funziona così

  • passaGruppo chiama passa() senza punto davanti: dentro un metodo, chiamare un altro metodo della stessa classe significa chiamarlo sullo stesso oggetto. Quindi sud.passaGruppo(3) esegue tre volte passa() sul tornello Sud.
  • Nel "Totale: " + (nord.passaggi + sud.passaggi) le parentesi sono indispensabili: senza, Java unirebbe i testi e stamperebbe "Totale: 64".
  • affollato(5): Nord ha 6 passaggi, 6 > 5 → true; Sud ne ha 4 → false. Il metodo è lo stesso, la risposta cambia perché lavora sui dati di oggetti diversi.
05Trova l'errore: metodi che non compilano medio

Consegna. Nessuno di questi tre programmi compila. Per ognuno trova l'errore, spiega cosa dice il compilatore e correggilo.

A

class Rettangolo {
    double base;
    double altezza;

    double area() {
        return base * altezza;
    }
}

public class ErroreSenzaOggetto {
    public static void main(String[] args) {
        Rettangolo r = new Rettangolo();
        r.base = 3;
        r.altezza = 4;
        System.out.println(area());
    }
}

B

class Alunno {
    String nome;
    double media;

    boolean promosso() {
        if (media >= 6) {
            return true;
        }
    }
}

public class ErrorePromosso {
    public static void main(String[] args) {
        Alunno a = new Alunno();
        a.media = 7;
        System.out.println(a.promosso());
    }
}

C

class Conto {
    double saldo;

    void versa(double importo) {
        saldo = saldo + importo;
    }
}

public class ErroreVersamento {
    public static void main(String[] args) {
        Conto c = new Conto();
        c.versa("50");
        System.out.println(c.saldo);
    }
}
Soluzione spiegata

A · il metodo di chi?

riga 15: error: cannot find symbol

"cannot find symbol" = non trovo questo nome. area() è un metodo della classe Rettangolo, non della classe con il main: chiamato così, Java lo cerca in ErroreSenzaOggetto e non lo trova. E poi, di quale rettangolo dovrebbe calcolare l'area? Un metodo di un oggetto va chiamato sull'oggetto, con il punto. Correzione: System.out.println(r.area()); che stampa 12.0.

B · e se la media è sotto il 6?

riga 9: error: missing return statement

"missing return statement" = manca un return. Il compilatore controlla tutte le strade: se media >= 6 il metodo restituisce true, ma se la condizione è falsa arriva alla graffa finale senza restituire niente, e un metodo boolean deve sempre restituire qualcosa. Correzione: aggiungere return false; dopo l'if, oppure scrivere tutto in una riga: return media >= 6;.

C · tipo dell'argomento sbagliato

riga 12: error: incompatible types: String cannot be converted to double

Il parametro di versa è un double, ma "50" tra virgolette è una String: un testo non diventa un numero da solo. Correzione: c.versa(50); (senza virgolette). Se il dato arriva davvero come testo, va convertito prima: c.versa(Double.parseDouble("50"));.

Il costruttore e la parola chiave this

Ripasso lampoIl costruttore ha lo stesso nome della classe, nessun tipo di ritorno (nemmeno void) ed è eseguito da new per inizializzare l'oggetto. Quando parametro e attributo hanno lo stesso nome, this.nome è l'attributo e nome il parametro: si scrive this.nome = nome;. Teoria: Il costruttore e this.
06Il magazzino della cartoleria facile

Consegna. Scrivi la classe Prodotto con gli attributi nome, prezzo e quantita (i pezzi in magazzino) e:

  • un costruttore che riceve i tre valori, con i parametri che si chiamano come gli attributi;
  • un metodo valore() che restituisce quanto vale la merce in magazzino (prezzo × quantità);
  • un metodo vendi(int pezzi) che toglie i pezzi venduti, ma solo se ce ne sono abbastanza; altrimenti stampa un avviso.

Nel main crea 40 quaderni da 2.5 euro e 100 penne da 1.25 euro, stampa il valore di entrambi, vendi 15 quaderni e 120 penne e stampa di nuovo i valori.

Output atteso:

Valore quaderni: 100.0
Valore penne: 125.0
Venduti 15 quaderni
Non ci sono abbastanza penne (ne restano 100)
Valore quaderni: 62.5
Valore penne: 125.0
Soluzione spiegata

Ragionamento

  1. Un prodotto senza nome o senza prezzo non ha senso: il costruttore obbliga a dare i dati quando l'oggetto nasce, con new Prodotto("quaderni", 2.5, 40), invece di riempire gli attributi a uno a uno.
  2. Il costruttore si chiama Prodotto come la classe e non ha tipo di ritorno.
  3. I parametri si chiamano come gli attributi, quindi dentro il costruttore uso this. per indicare l'attributo: this.prezzo = prezzo; = "il prezzo di questo prodotto riceve il valore del parametro prezzo".
  4. In valore() e vendi() invece non ci sono parametri con lo stesso nome degli attributi, quindi this non serve.

Codice

class Prodotto {
    String nome;
    double prezzo;
    int quantita;

    Prodotto(String nome, double prezzo, int quantita) {
        this.nome = nome;
        this.prezzo = prezzo;
        this.quantita = quantita;
    }

    double valore() {
        return prezzo * quantita;
    }

    void vendi(int pezzi) {
        if (pezzi <= quantita) {
            quantita = quantita - pezzi;
            System.out.println("Venduti " + pezzi + " " + nome);
        } else {
            System.out.println("Non ci sono abbastanza " + nome + " (ne restano " + quantita + ")");
        }
    }
}

public class Magazzino {
    public static void main(String[] args) {
        Prodotto p1 = new Prodotto("quaderni", 2.5, 40);
        Prodotto p2 = new Prodotto("penne", 1.25, 100);

        System.out.println("Valore quaderni: " + p1.valore());
        System.out.println("Valore penne: " + p2.valore());

        p1.vendi(15);
        p2.vendi(120);

        System.out.println("Valore quaderni: " + p1.valore());
        System.out.println("Valore penne: " + p2.valore());
    }
}

Perché funziona

  • Valori iniziali: 2.5 × 40 = 100.0 e 1.25 × 100 = 125.0.
  • p1.vendi(15): 15 ≤ 40, quindi i quaderni scendono a 25 e il valore diventa 2.5 × 25 = 62.5.
  • p2.vendi(120): 120 > 100, entra nell'else e la quantità non cambia: il valore delle penne resta 125.0.
07Compila, ma stampa male: il this dimenticato medio

Consegna. Questo programma compila e parte senza errori, ma stampa dati sbagliati. Prevedi l'output, trova il problema e correggilo.

class Squadra {
    String nome;
    String citta;
    int punti;

    Squadra(String nome, String citta, int punti) {
        nome = nome;
        this.citta = citta;
        punti = punti;
    }

    void stampa() {
        System.out.println(nome + " (" + citta + "): " + punti + " punti");
    }
}

public class SquadraSbagliata {
    public static void main(String[] args) {
        Squadra s1 = new Squadra("Lupi", "Roma", 12);
        Squadra s2 = new Squadra("Aquile", "Torino", 9);
        s1.stampa();
        s2.stampa();
    }
}
Soluzione spiegata

Output (sbagliato)

null (Roma): 0 punti
null (Torino): 0 punti

Ragionamento

  1. La città è giusta, nome e punti no: guardo cosa c'è di diverso nelle tre righe del costruttore. Solo la riga della città ha this..
  2. Dentro il costruttore, nome da solo indica la variabile più vicina, cioè il parametro. Quindi nome = nome; copia il parametro… in sé stesso. L'attributo non viene mai toccato.
  3. Un attributo mai assegnato tiene il valore di partenza: null per la String, 0 per l'int. Ecco spiegati "null" e "0 punti".
  4. Il compilatore non protesta perché nome = nome; è un'istruzione valida (inutile, ma valida). Per questo è un errore subdolo.

Correzione

Squadra(String nome, String citta, int punti) {
    this.nome = nome;
    this.citta = citta;
    this.punti = punti;
}
Lupi (Roma): 12 punti
Aquile (Torino): 9 punti

Da ricordare

  • Parametro e attributo con lo stesso nome → sempre this. a sinistra dell'uguale.
  • Un'altra soluzione, meno usata, è dare ai parametri nomi diversi (Squadra(String n, String c, int p) con nome = n;): così non c'è ambiguità e this non serve. Ma il codice si legge peggio.
  • Se un oggetto appena creato ha attributi a null o 0 che non ti aspetti, la prima cosa da controllare è il costruttore.
08Un costruttore che controlla i dati medio

Consegna. Scrivi la classe Verifica con gli attributi materia e voto (double). Il costruttore riceve i due valori, ma deve impedire voti impossibili: se il voto è minore di 1 diventa 1, se è maggiore di 10 diventa 10, e in entrambi i casi stampa un avviso. Aggiungi i metodi sufficiente() (restituisce true dal 6 in su) e stampa().

Prova con Storia 7.5, Fisica 12 e Latino -2.

Output atteso:

Voto 12.0 non valido in Fisica: diventa 10
Voto -2.0 non valido in Latino: diventa 1
Storia: 7.5, sufficiente? true
Fisica: 10.0, sufficiente? true
Latino: 1.0, sufficiente? false
Soluzione spiegata

Ragionamento

  1. Il costruttore è il posto giusto per i controlli: è eseguito sempre quando nasce un oggetto, quindi nessuna Verifica può esistere con un voto sbagliato.
  2. Nel costruttore ci sono due "voto": il parametro (il valore ricevuto, magari sbagliato) e l'attributo (quello che conservo). Nelle condizioni controllo il parametro (voto < 1), mentre assegno l'attributo (this.voto = 1).
  3. Uso if / else if / else perché i tre casi si escludono: troppo basso, troppo alto, oppure valido.
  4. stampa() riusa sufficiente() invece di riscrivere la condizione.

Codice

class Verifica {
    String materia;
    double voto;

    Verifica(String materia, double voto) {
        this.materia = materia;
        if (voto < 1) {
            System.out.println("Voto " + voto + " non valido in " + materia + ": diventa 1");
            this.voto = 1;
        } else if (voto > 10) {
            System.out.println("Voto " + voto + " non valido in " + materia + ": diventa 10");
            this.voto = 10;
        } else {
            this.voto = voto;
        }
    }

    boolean sufficiente() {
        return voto >= 6;
    }

    void stampa() {
        System.out.println(materia + ": " + voto + ", sufficiente? " + sufficiente());
    }
}

public class Pagella {
    public static void main(String[] args) {
        Verifica v1 = new Verifica("Storia", 7.5);
        Verifica v2 = new Verifica("Fisica", 12);
        Verifica v3 = new Verifica("Latino", -2);
        v1.stampa();
        v2.stampa();
        v3.stampa();
    }
}

Da notare

  • Gli avvisi vengono stampati per primi, perché il costruttore parte al momento del new, prima delle chiamate a stampa().
  • Nell'avviso di Fisica compare 12.0 e non 12: l'argomento 12 è un int, ma il parametro è double e Java lo ha già convertito.
  • Errore tipico: scrivere if (this.voto < 1). In quel momento l'attributo vale ancora 0.0 (non è stato assegnato), quindi la condizione sarebbe sempre vera e ogni voto diventerebbe 1.

Overload dei costruttori e this(...)

Ripasso lampoUna classe può avere più costruttori con parametri diversi (per numero, tipo o ordine): Java sceglie quello giusto guardando gli argomenti del new. Se scrivi almeno un costruttore, quello vuoto non c'è più (devi scriverlo tu). Con this(...), come prima riga, un costruttore ne chiama un altro della stessa classe. Teoria: Overload dei costruttori.
09Tre modi per ordinare una pizza medio

Consegna. Scrivi la classe Pizza con gli attributi gusto, diametro (cm) e mozzarellaExtra (boolean) e tre costruttori:

  • Pizza(): una margherita da 30 cm senza extra;
  • Pizza(String gusto): il gusto scelto, 30 cm, senza extra;
  • Pizza(String gusto, int diametro, boolean mozzarellaExtra): tutto scelto dal cliente.

Vincolo: le assegnazioni agli attributi devono comparire una volta sola, nel costruttore completo. Aggiungi un metodo prezzo() (6 euro, +3 se il diametro supera i 30 cm, +1.5 per la mozzarella extra) e un metodo stampa().

Output atteso:

margherita 30 cm: 6.0 euro
diavola 30 cm: 6.0 euro
capricciosa 40 cm + mozzarella: 10.5 euro
Soluzione spiegata

Ragionamento

  1. Tre costruttori con 0, 1 e 3 parametri: sono liste diverse, quindi è un overload valido. Java sceglie in base agli argomenti del new.
  2. Il vincolo dice di non ripetere le assegnazioni: allora solo il costruttore completo scrive negli attributi, e gli altri due lo chiamano con this(...), passando i valori "di default" al posto di quelli che mancano.
  3. Pizza() chiama this("margherita", 30, false); Pizza(String gusto) chiama this(gusto, 30, false), passando avanti il gusto ricevuto.
  4. this(...) deve essere la prima riga del costruttore.
  5. Nel prezzo uso una variabile locale p che parte da 6 e a cui aggiungo i supplementi.

Codice

class Pizza {
    String gusto;
    int diametro;   // in cm
    boolean mozzarellaExtra;

    Pizza() {
        this("margherita", 30, false);
    }

    Pizza(String gusto) {
        this(gusto, 30, false);
    }

    Pizza(String gusto, int diametro, boolean mozzarellaExtra) {
        this.gusto = gusto;
        this.diametro = diametro;
        this.mozzarellaExtra = mozzarellaExtra;
    }

    double prezzo() {
        double p = 6;
        if (diametro > 30) {
            p = p + 3;
        }
        if (mozzarellaExtra) {
            p = p + 1.5;
        }
        return p;
    }

    void stampa() {
        String extra = "";
        if (mozzarellaExtra) {
            extra = " + mozzarella";
        }
        System.out.println(gusto + " " + diametro + " cm" + extra + ": " + prezzo() + " euro");
    }
}

public class Pizzeria {
    public static void main(String[] args) {
        Pizza p1 = new Pizza();
        Pizza p2 = new Pizza("diavola");
        Pizza p3 = new Pizza("capricciosa", 40, true);
        p1.stampa();
        p2.stampa();
        p3.stampa();
    }
}

Perché conviene this(...)

  • Se domani si aggiunge un attributo (per esempio impastoIntegrale), basta modificare un costruttore, quello completo. Senza this(...) andrebbe aggiunto in tutti e tre, con il rischio di dimenticarne uno.
  • Prezzi: margherita e diavola da 30 cm costano 6.0 (30 non è maggiore di 30); la capricciosa da 40 cm con mozzarella costa 6 + 3 + 1.5 = 10.5.
  • Nota: this.gusto (con il punto) indica un attributo; this(...) (con le parentesi) chiama un costruttore. Sono due usi diversi della stessa parola.

Consegna. Ecco una classe con tre costruttori che stampano un messaggio:

Punto q = new Punto(4);

Soluzione spiegata

Output

A: punto nell'origine
C: punto (4, 4)
B: punto sulla diagonale
C: punto (2, 7)
6

Ragionamento, un new alla volta

  1. new Punto(): zero argomenti → costruttore A. La sua prima riga è this(0, 0), che salta subito nel costruttore C. C assegna e stampa "C: punto (0, 0)"; quando C finisce, si torna in A, che stampa il suo messaggio. Quindi prima C, poi A.
  2. new Punto(4): un int → costruttore B, che chiama this(4, 4): stampa C con (4, 4) e poi B.
  3. new Punto(2, 7): due int → direttamente C. Un solo messaggio.
  4. p.x + q.y + r.x: sono tre int, quindi è una somma: 0 + 4 + 2 = 6.
  5. "Somma: " + p.x + q.y + r.x: Java va da sinistra a destra. "Somma: " + 0 è già testo, e da lì ogni + unisce: "Somma: 0", poi "Somma: 04", poi "Somma: 042". Per avere 6 servono le parentesi: "Somma: " + (p.x + q.y + r.x).
Come una telefonatathis(...) è come mettere in attesa chi ti ha chiamato per fare un'altra telefonata: prima si conclude la chiamata interna (C), poi si riprende quella di partenza (A o B) dalla riga dopo.

Soluzione spiegata

A · due costruttori uguali

riga 9: error: constructor Persona(String) is already defined in class Persona

"already defined" = già definito. Per Java i due costruttori sono identici: entrambi ricevono una String. B · this(...) non è la prima riga

Correzione: scambiare le due righe, prima this(ore, 0); e poi la stampa. (Nelle versioni più recenti di Java questa regola è stata un po' allentata, ma a scuola e nelle verifiche vale così: this(...) in prima riga.)

Java guarda prima quanti argomenti ci sono: uno solo, quindi l'unico candidato è Orologio(int ore). Poi controlla il tipo: il parametro vuole un int, ma "dieci" è una String ("incompatible types: String cannot be converted to int"). Correzione: new Orologio(10). 13L'attributo nascosto difficile

Consegna. Nella classe Giocatore la parola punti compare in tre ruoli diversi. Prevedi l'output, poi spiega perché il metodo bonus() non regala davvero 150 punti a Sara.

class Giocatore {
    String nome;
    int punti;

    Giocatore(String nome) {
        this.nome = nome;
    }

    void bonus() {
        int punti = 100;
        punti = punti + 50;
        System.out.println("Dentro bonus: " + punti);
    }

    void segna(int punti) {
        this.punti = this.punti + punti;
    }

    void premio() {
        for (int i = 0; i < 3; i++) {
            punti = punti + i;
        }
    }
}

public class Ombra {
    public static void main(String[] args) {
        Giocatore g = new Giocatore("Sara");
        g.segna(10);
        g.bonus();
        System.out.println("Dopo bonus: " + g.punti);
        g.premio();
        System.out.println("Dopo premio: " + g.punti);
        g.segna(5);
        System.out.println("Finale: " + g.punti);
    }
}
Soluzione spiegata

Output

Dentro bonus: 150
Dopo bonus: 10
Dopo premio: 13
Finale: 18

Ragionamento: chi è "punti" in ogni metodo?

Metodopunti indica…Effetto sull'attributo
segna(10)il parametro (10); l'attributo è this.punti0 + 10 = 10
bonus()una variabile locale nuova, che vale 100 e poi 150nessuno: resta 10
premio()l'attributo (non c'è niente di più vicino con quel nome)10 + 0 + 1 + 2 = 13
segna(5)il parametro (5)13 + 5 = 18

Perché bonus() non funziona

  • int punti = 100; con il tipo davanti è una dichiarazione: crea una variabile locale nuova che ha lo stesso nome dell'attributo e lo "copre" (si dice che lo mette in ombra). Da lì in poi, nel metodo, punti è la variabile locale.
  • La variabile locale arriva a 150, viene stampata e muore alla fine del metodo. L'attributo non è mai stato toccato.
  • Correzione: togliere la dichiarazione e scrivere punti = punti + 150; oppure, per essere chiarissimi, this.punti = this.punti + 150;.
RegolaJava usa sempre la variabile più vicina con quel nome: prima le locali e i parametri, poi gli attributi. Con this. davanti indichi sempre e solo l'attributo.

14La finale dei 100 metri medio

Consegna. Scrivi la classe Atleta (nome, nazione, tempo in secondi) con un costruttore e un metodo stampa(). Nel main crea un array di 4 atleti:

  • Marco, ITA, 10.25 · Kim, KOR, 10.5 · Lena, GER, 9.75 · Omar, MAR, 10.0

Stampali tutti, poi con due metodi static della classe principale trova l'atleta più veloce (il metodo deve restituire l'oggetto Atleta, non solo il tempo) e il tempo medio.

Output atteso:

Marco (ITA): 10.25 s
Kim (KOR): 10.5 s
Lena (GER): 9.75 s
Omar (MAR): 10.0 s
Vince Lena con 9.75 s
Tempo medio: 10.125 s
Soluzione spiegata

Ragionamento

  1. new Atleta[4] crea 4 caselle vuote (null): le riempio tutte con new Atleta(...) prima di scorrere l'array.
  2. Per stampare tutti uso il foreach: a ogni giro a è un atleta e posso chiamare a.stampa().
  3. piuVeloce è la ricerca del minimo che conosci già, solo che confronto a.tempo e mi tengo l'oggetto intero: parto da atleti[0] e lo sostituisco quando trovo un tempo più basso. Restituendo l'atleta, chi chiama può leggere sia il nome sia il tempo.
  4. tempoMedio: accumulatore double con la somma dei tempi, diviso il numero di atleti.
  5. I due metodi sono static e stanno nella classe con il main, come quelli del capitolo sui metodi: ricevono l'array come parametro.

Codice

class Atleta {
    String nome;
    String nazione;
    double tempo;   // in secondi

    Atleta(String nome, String nazione, double tempo) {
        this.nome = nome;
        this.nazione = nazione;
        this.tempo = tempo;
    }

    void stampa() {
        System.out.println(nome + " (" + nazione + "): " + tempo + " s");
    }
}

public class Gara {

    static Atleta piuVeloce(Atleta[] atleti) {
        Atleta migliore = atleti[0];
        for (Atleta a : atleti) {
            if (a.tempo < migliore.tempo) {
                migliore = a;
            }
        }
        return migliore;
    }

    static double tempoMedio(Atleta[] atleti) {
        double somma = 0;
        for (Atleta a : atleti) {
            somma = somma + a.tempo;
        }
        return somma / atleti.length;
    }

    public static void main(String[] args) {
        Atleta[] gara = new Atleta[4];
        gara[0] = new Atleta("Marco", "ITA", 10.25);
        gara[1] = new Atleta("Kim", "KOR", 10.5);
        gara[2] = new Atleta("Lena", "GER", 9.75);
        gara[3] = new Atleta("Omar", "MAR", 10.0);

        for (Atleta a : gara) {
            a.stampa();
        }

        Atleta v = piuVeloce(gara);
        System.out.println("Vince " + v.nome + " con " + v.tempo + " s");
        System.out.println("Tempo medio: " + tempoMedio(gara) + " s");
    }
}

Da notare

  • Il più veloce è chi ha il tempo più basso: Lena con 9.75. Usare > invece di < darebbe il più lento.
  • Media: (10.25 + 10.5 + 9.75 + 10.0) / 4 = 40.5 / 4 = 10.125.
  • v non è una copia di Lena: è un altro riferimento allo stesso oggetto che sta in gara[2].
  • Se una casella fosse rimasta null, a.stampa() o a.tempo provocherebbero una NullPointerException.

Passo 2 · La classe Libro e i suoi costruttori

Il costruttore completo è l'unico che assegna gli attributi, con this.titolo = titolo; perché parametri e attributi hanno lo stesso nome. Quello con due parametri non ripete niente: chiama this(titolo, autore, 0) come prima riga. inPrestito non viene assegnato da nessun costruttore: parte da false, che è proprio "disponibile".

Passo 3 · I metodi del libro

descrizione() costruisce il testo un pezzo alla volta in una variabile locale testo e lo restituisce: sarà la biblioteca a decidere di stamparlo. presta() usa due return: se il libro è già in prestito esce subito con false e la riga inPrestito = true non viene eseguita.

Passo 4 · Lo scaffale: un array riempito a metà

Il costruttore di Biblioteca crea new Libro[capienza]: 4 caselle null, nessun libro. L'attributo quanti fa due lavori: dice quanti libri ci sono e qual è la prima casella libera. In aggiungi metto il libro in scaffale[quanti] e poi incremento. Quando quanti == scaffale.length lo scaffale è pieno: Fahrenheit 451 viene rifiutato, ed è per questo che il suo avviso è la prima riga dell'output (arriva prima del catalogo).

Tutti i cicli vanno da 0 a quanti, non a scaffale.length: così non si tocca mai una casella null e non c'è rischio di NullPointerException anche quando lo scaffale non è pieno.

Passo 5 · Cercare e prestare

cerca confronta i titoli con equals (sono String, cioè oggetti) e restituisce il riferimento al libro che sta nello scaffale, non una copia. Se il ciclo finisce senza trovarlo, restituisce null. prestito gestisce i tre casi in ordine: prima controlla l == null (se non lo facesse, l.presta() su Harry Potter fermerebbe il programma), poi prova a prestarlo. La prima richiesta di Dune va a buon fine, la seconda trova inPrestito già a true.

Passo 6 · Il catalogo e la restituzione

stampaCatalogo usa disponibili() nell'intestazione e descrizione() per ogni libro: nel secondo catalogo Dune e Il nome della rosa risultano in prestito e i disponibili scendono da 4 a 2. Alla fine b.cerca("Dune") restituisce lo stesso oggetto che sta nello scaffale: chiamando restituisci() su dune si modifica il libro della biblioteca, e i disponibili tornano 3.

Codice completo

// ===================== un libro =====================
class Libro {
    String titolo;
    String autore;
    int anno;
    boolean inPrestito;      // parte da false: nessuno lo assegna

    Libro(String titolo, String autore) {
        this(titolo, autore, 0);     // anno sconosciuto
    }

    Libro(String titolo, String autore, int anno) {
        this.titolo = titolo;
        this.autore = autore;
        this.anno = anno;
    }

    String descrizione() {
        String testo = titolo + " di " + autore;
        if (anno > 0) {
            testo = testo + " (" + anno + ")";
        }
        if (inPrestito) {
            testo = testo + " - IN PRESTITO";
        }
        return testo;
    }

    boolean presta() {
        if (inPrestito) {
            return false;
        }
        inPrestito = true;
        return true;
    }

    void restituisci() {
        inPrestito = false;
    }
}

// ================== la biblioteca ==================
class Biblioteca {
    String nome;
    Libro[] scaffale;
    int quanti;              // caselle occupate: parte da 0

    Biblioteca(String nome, int capienza) {
        this.nome = nome;
        this.scaffale = new Libro[capienza];
    }

    boolean aggiungi(Libro libro) {
        if (quanti == scaffale.length) {
            System.out.println("Scaffale pieno: non posso aggiungere " + libro.titolo);
            return false;
        }
        scaffale[quanti] = libro;
        quanti++;
        return true;
    }

    Libro cerca(String titolo) {
        for (int i = 0; i < quanti; i++) {
            if (scaffale[i].titolo.equals(titolo)) {
                return scaffale[i];
            }
        }
        return null;
    }

    void prestito(String titolo) {
        Libro l = cerca(titolo);
        if (l == null) {
            System.out.println("\"" + titolo + "\": non è in catalogo");
        } else if (l.presta()) {
            System.out.println("\"" + titolo + "\": prestito registrato");
        } else {
            System.out.println("\"" + titolo + "\": è già in prestito");
        }
    }

    int disponibili() {
        int conta = 0;
        for (int i = 0; i < quanti; i++) {
            if (!scaffale[i].inPrestito) {
                conta++;
            }
        }
        return conta;
    }

    void stampaCatalogo() {
        System.out.println("--- " + nome + ": " + quanti + " libri, " + disponibili() + " disponibili ---");
        for (int i = 0; i < quanti; i++) {
            System.out.println((i + 1) + ". " + scaffale[i].descrizione());
        }
    }
}

// ================== il programma ==================
public class BibliotecaDiClasse {
    public static void main(String[] args) {
        Biblioteca b = new Biblioteca("Biblioteca della 3B", 4);

        b.aggiungi(new Libro("Il barone rampante", "Italo Calvino", 1957));
        b.aggiungi(new Libro("Dune", "Frank Herbert", 1965));
        b.aggiungi(new Libro("Il diario della 3B", "Anonimo"));
        b.aggiungi(new Libro("Il nome della rosa", "Umberto Eco", 1980));
        b.aggiungi(new Libro("Fahrenheit 451", "Ray Bradbury", 1953));
        b.stampaCatalogo();

        b.prestito("Dune");
        b.prestito("Dune");
        b.prestito("Harry Potter");
        b.prestito("Il nome della rosa");
        b.stampaCatalogo();

        Libro dune = b.cerca("Dune");
        dune.restituisci();
        System.out.println("Disponibili dopo la restituzione: " + b.disponibili());
    }
}

Controlla di aver capito

  • Quanti oggetti Libro vengono creati in tutto? (5: anche Fahrenheit 451 nasce con new, solo che non entra nello scaffale.)
  • Cosa succede se in disponibili() il ciclo arriva a scaffale.length e lo scaffale ha una casella vuota? (scaffale[i].inPrestito su null: NullPointerException.)
  • Perché in descrizione() non serve this.titolo? (Nel metodo non c'è nessun parametro o variabile locale chiamata titolo: titolo indica già l'attributo.)
  • La variabile conta di disponibili() si può usare in stampaCatalogo()? (No: è locale, muore alla fine di disponibili(). Per questo il metodo la restituisce.)
  • Se scrivessi b.cerca("Harry Potter").restituisci(); cosa succederebbe? (cerca restituisce null e chiamare un metodo su null dà NullPointerException.)
