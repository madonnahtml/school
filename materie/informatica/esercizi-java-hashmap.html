Esercizi: HashMap

Consegne ed esercizi per allenarti su tutto il capitolo Java: HashMap. Ogni soluzione spiega il ragionamento, mostra il codice completo e l'output vero del programma.

Come usare questa paginaLeggi la consegna, prova a scrivere il programma da solo (su carta o al computer) e solo dopo apri la soluzione spiegata. Gli esercizi vanno dal più facile al più difficile; l'ultimo li mette insieme tutti. Ogni programma è stato compilato ed eseguito: l'output che vedi è quello vero.
Attenzione all'ordineUna HashMap non tiene le coppie nell'ordine in cui le hai inserite. Quando un output stampa o scorre un'intera mappa, le righe che vedi qui sono quelle uscite davvero sul nostro computer, ma l'ordine può essere diverso da quello che ti aspetti: conta che ci siano tutte, non la loro posizione. Lo segnaliamo ogni volta che succede.

L'idea chiave → valore e la creazione

Ripasso lampoUna HashMap tiene i dati a coppie chiave → valore. La chiave è unica (è quello con cui cerchi), il valore può ripetersi. Si crea indicando due tipi, e solo classi: HashMap<String, Integer> m = new HashMap<>();, con import java.util.HashMap;. Teoria: Cosa sono le HashMap e Creare una HashMap.
01Scegli chiave, valore e tipi facile

Consegna. Per ogni situazione decidi qual è la chiave, qual è il valore e scrivi la dichiarazione Java della mappa:

  1. la targa di un'auto e il cognome del proprietario;
  2. il codice di un prodotto (un numero intero, per esempio 1043) e quanti pezzi ci sono in magazzino;
  3. una parola italiana e la sua traduzione in inglese;
  4. uno studente e tutti i suoi voti;
  5. domanda trabocchetto: perché "data di nascita → studente" è una pessima mappa?

Poi scrivi un programma che crea le cinque mappe, mette almeno una coppia in ognuna e le stampa. Output atteso:

{AB123CD=Rossi}
{1043=25}
{gatto=cat}
{Anna=[7, 8]}
{12/03=Bruno}
Soluzione spiegata

Ragionamento

  1. La domanda da farsi è: con che cosa cercherò? Quello è la chiave. Quello che voglio ottenere è il valore.
  2. La chiave deve essere unica: due auto non hanno la stessa targa, due prodotti non hanno lo stesso codice. Il valore invece può ripetersi (due auto dello stesso signor Rossi).
  3. Tra < > vanno solo classi: il numero intero diventa Integer, non int.
  4. Se un valore è "più cose", come i tanti voti di uno studente, il valore può essere una lista: ArrayList<Integer>.
ChiaveValoreDichiarazione
atargaproprietarioHashMap<String, String>
bcodicepezziHashMap<Integer, Integer>
cparola italianaparola ingleseHashMap<String, String>
dstudentelista di votiHashMap<String, ArrayList<Integer>>

Codice

import java.util.ArrayList;
import java.util.HashMap;

public class Tipi {
    public static void main(String[] args) {
        // a) targa -> proprietario
        HashMap<String, String> auto = new HashMap<>();
        auto.put("AB123CD", "Rossi");

        // b) codice prodotto -> pezzi in magazzino
        HashMap<Integer, Integer> magazzino = new HashMap<>();
        magazzino.put(1043, 25);

        // c) parola italiana -> traduzione inglese
        HashMap<String, String> dizionario = new HashMap<>();
        dizionario.put("gatto", "cat");

        // d) studente -> tutti i suoi voti
        HashMap<String, ArrayList<Integer>> registro = new HashMap<>();
        registro.put("Anna", new ArrayList<>());
        registro.get("Anna").add(7);
        registro.get("Anna").add(8);

        System.out.println(auto);
        System.out.println(magazzino);
        System.out.println(dizionario);
        System.out.println(registro);

        // e) data di nascita -> studente: una cattiva idea
        HashMap<String, String> nati = new HashMap<>();
        nati.put("12/03", "Anna");
        nati.put("12/03", "Bruno");
        System.out.println(nati);
    }
}

Perché "data di nascita → studente" non va

Guarda l'ultima riga dell'output: {12/03=Bruno}. Anna e Bruno sono nati lo stesso giorno, ma una chiave non può comparire due volte: il secondo put ha sostituito Anna con Bruno, senza nessun errore. Anna è sparita in silenzio. Una data di nascita non è unica, quindi non può fare da chiave. Al contrario, "studente → data di nascita" funziona benissimo: i nomi sono le chiavi (unici) e le date i valori (possono ripetersi).

Da notare

  • Nel caso d), registro.get("Anna") restituisce la lista di Anna, e su quella lista chiamo add: la lista è dentro la mappa, quindi i voti finiscono lì. La stampa mostra la lista tra quadre dentro la mappa tra graffe: {Anna=[7, 8]}.
  • Ogni mappa qui ha una sola coppia, quindi il problema dell'ordine non si pone.

Soluzione spiegata

A · int al posto di Integer

riga 5: error: unexpected type

"unexpected type" = tipo inatteso: tra < > il compilatore vuole una classe e alla riga 5 ha trovato il primitivo int. Correzione: HashMap<String, Integer>. Poi nel put puoi scrivere tranquillamente 18: Java lo trasforma da solo in Integer (autoboxing).

B · valore del tipo sbagliato

riga 6: error: incompatible types: String cannot be converted to Integer

La mappa è stata dichiarata <String, Integer>: il valore deve essere un numero intero, e "diciotto" è una String. È proprio il vantaggio dei generics: l'errore lo trova il compilatore, prima ancora di eseguire. Correzione: eta.put("Marco", 18);

C · manca l'import

riga 3: error: cannot find symbol

"cannot find symbol" = non trovo questo nome. HashMap non fa parte del linguaggio base: sta nel pacchetto java.util e va importata. Correzione: aggiungere in cima import java.util.HashMap;

Da ricordareTre controlli prima di usare una mappa: l'import, i due tipi (chiave e valore) e che siano classi (Integer, Double, Boolean, Character…).

Aggiungere e modificare con put()

Ripasso lampoput(chiave, valore) ha un doppio ruolo: se la chiave è nuova aggiunge una coppia, se esiste già sostituisce il valore vecchio. Per aggiornare partendo dal valore vecchio: m.put(k, m.get(k) + 1). Teoria: Aggiungere e modificare con put().

04Il magazzino della cartoleria medio

Consegna. Una cartoleria ha in magazzino 40 penne, 25 quaderni e 10 gomme: mettili in una HashMap<String, Integer>. Poi arrivano dei pacchi, descritti da due array paralleli:

String[] arrivi = {"quaderni", "gomme", "righelli", "gomme"};
int[] quantita = {10, 5, 8, 15};

Per ogni pacco: se il prodotto c'è già, somma la quantità a quella esistente; se è nuovo, aggiungilo. Stampa un messaggio per ogni pacco, poi l'inventario finale (penne, quaderni, gomme, righelli, in quest'ordine) e quanti prodotti diversi ci sono.

Output atteso:

Aggiornato quaderni: ora sono 35
Aggiornato gomme: ora sono 15
Nuovo prodotto righelli: 8
Aggiornato gomme: ora sono 30
--- Inventario ---
penne: 40
quaderni: 35
gomme: 30
righelli: 8
Prodotti diversi: 4
Soluzione spiegata

Ragionamento

  1. Prodotto → quantità: la chiave è il nome (String), il valore il numero di pezzi (Integer).
  2. I due array sono paralleli: arrivi[i] e quantita[i] parlano dello stesso pacco. Mi serve l'indice, quindi uso il for classico.
  3. Per ogni pacco ci sono due casi. Se scrivessi solo scorte.put(prodotto, quantita[i]), per i quaderni metterei 10 al posto di 25: il put sostituisce, non somma. Devo prima leggere il vecchio valore con get, sommare e rimettere.
  4. Ma get su un prodotto che non c'è (i righelli) darebbe null, e null + 8 lancia NullPointerException. Per questo controllo prima con containsKey.
  5. Per l'inventario non stampo la mappa intera: l'ordine non è garantito. Scorro un array con i nomi nell'ordine che voglio e per ognuno faccio get.

Codice

import java.util.HashMap;

public class Magazzino {
    public static void main(String[] args) {
        HashMap<String, Integer> scorte = new HashMap<>();
        scorte.put("penne", 40);
        scorte.put("quaderni", 25);
        scorte.put("gomme", 10);

        String[] arrivi = {"quaderni", "gomme", "righelli", "gomme"};
        int[] quantita = {10, 5, 8, 15};

        for (int i = 0; i < arrivi.length; i++) {
            String prodotto = arrivi[i];
            if (scorte.containsKey(prodotto)) {
                scorte.put(prodotto, scorte.get(prodotto) + quantita[i]);
                System.out.println("Aggiornato " + prodotto + ": ora sono " + scorte.get(prodotto));
            } else {
                scorte.put(prodotto, quantita[i]);
                System.out.println("Nuovo prodotto " + prodotto + ": " + quantita[i]);
            }
        }

        System.out.println("--- Inventario ---");
        String[] elenco = {"penne", "quaderni", "gomme", "righelli"};
        for (String p : elenco) {
            System.out.println(p + ": " + scorte.get(p));
        }
        System.out.println("Prodotti diversi: " + scorte.size());
    }
}

Prova a mano

Le gomme arrivano due volte: la prima volta 10 + 5 = 15, la seconda 15 + 15 = 30. Funziona perché ogni volta get legge il valore aggiornato dal giro precedente. I righelli entrano come nuova chiave, quindi alla fine i prodotti diversi sono 4.

Errori da evitare

  • Usare solo put(prodotto, quantita[i]): perderesti le scorte vecchie.
  • Usare solo put(prodotto, scorte.get(prodotto) + quantita[i]) senza controllo: funziona per i prodotti già presenti ma si blocca al primo prodotto nuovo.
  • Le due righe dell'if si possono scrivere in una con getOrDefault: scorte.put(prodotto, scorte.getOrDefault(prodotto, 0) + quantita[i]); (lo vediamo nella prossima sezione).

Leggere e controllare: get, containsKey, containsValue, getOrDefault

Ripasso lampoget(k) dà il valore della chiave, oppure null se la chiave non c'è. containsKey(k) e containsValue(v) rispondono true/false: il primo è velocissimo, il secondo deve guardare tutte le coppie. getOrDefault(k, riserva) dà il valore oppure la riserva, mai null. Teoria: Leggere con get() e controllare.
05Il traduttore parola per parola facile

Consegna. Crea un piccolo dizionario italiano → inglese con queste coppie: il → the, la → the, gatto → cat, mangia → eats, pesce → fish. Traduci parola per parola la frase "il gatto mangia la torta": le parole che il dizionario non conosce vanno scritte tra quadre con un punto di domanda. Conta anche quante parole erano sconosciute. Infine controlla se nel dizionario c'è una parola che si traduce con "cat" e una che si traduce con "dog".

Suggerimento: frase.split(" ") divide la frase in un array di parole.

Output atteso:

the cat eats the [torta?] 
Parole sconosciute: 1
Qualcosa si traduce con "cat"? true
Qualcosa si traduce con "dog"? false
Soluzione spiegata

Ragionamento

  1. Cerco per parola italiana, quindi la parola italiana è la chiave e quella inglese il valore. "il" e "la" hanno lo stesso valore "the": è permesso, i valori possono ripetersi.
  2. Per ogni parola della frase chiedo prima containsKey: se c'è prendo la traduzione con get, altrimenti scrivo [parola?] e aumento il contatore.
  3. Costruisco la traduzione attaccando un pezzo alla volta a una String che parte vuota.
  4. "Esiste una parola che si traduce con cat?" è una domanda sul valore, non sulla chiave: serve containsValue.

Codice

import java.util.HashMap;

public class Traduttore {
    public static void main(String[] args) {
        HashMap<String, String> diz = new HashMap<>();
        diz.put("il", "the");
        diz.put("la", "the");
        diz.put("gatto", "cat");
        diz.put("mangia", "eats");
        diz.put("pesce", "fish");

        String frase = "il gatto mangia la torta";
        String traduzione = "";
        int sconosciute = 0;
        for (String parola : frase.split(" ")) {
            if (diz.containsKey(parola)) {
                traduzione = traduzione + diz.get(parola) + " ";
            } else {
                traduzione = traduzione + "[" + parola + "?] ";
                sconosciute++;
            }
        }
        System.out.println(traduzione);
        System.out.println("Parole sconosciute: " + sconosciute);

        System.out.println("Qualcosa si traduce con \"cat\"? " + diz.containsValue("cat"));
        System.out.println("Qualcosa si traduce con \"dog\"? " + diz.containsValue("dog"));
    }
}

Da ricordare

  • Lo stesso ciclo si può scrivere senza if: traduzione = traduzione + diz.getOrDefault(parola, "[" + parola + "?]") + " ";. Però così non potrei contare le parole sconosciute: quando serve fare qualcosa in più nel caso "non c'è", l'if con containsKey è più comodo.
  • containsKey("cat") avrebbe dato false: "cat" non è una chiave, è un valore. Confondere i due metodi è un errore classico.
  • containsValue è lento (O(n)): deve controllare tutte le coppie. In un dizionario vero, con 100.000 parole, per tradurre al contrario (inglese → italiano) conviene creare una seconda mappa con chiavi e valori scambiati.

HashMap<String, Integer> eta = new HashMap<>();
eta.put("Marco", 18);
eta.put("Giulia", 18);

System.out.println(eta.get("marco"));

System.out.println(eta.containsKey("20"));

System.out.println(eta.getOrDefault("Paolo", -1));
System.out.println(eta.getOrDefault("Giulia", -1));
System.out.println(eta.get("Luca") + eta.get("Marco"));
System.out.println("Somma: " + eta.get("Luca") + eta.get("Marco"));
Soluzione spiegata

Output

Riga per riga

  1. get("marco"): le chiavi String distinguono maiuscole e minuscole. "marco" non è "Marco", quindi la chiave non c'è e get restituisce null. Stamparlo non fa danni.
  2. containsKey("Luca"): la chiave c'è, true.
  3. containsKey("20"): due errori in uno. 20 è un valore, non una chiave; e comunque "20" tra virgolette è un testo, non il numero 20. false.
  4. containsValue(20): Luca ha 20 anni, true.
  5. containsValue(18): true. Che i valori 18 siano due non cambia niente: basta che ce ne sia almeno uno.
  6. getOrDefault("Paolo", -1): Paolo non c'è, quindi esce la riserva -1.
  7. getOrDefault("Giulia", -1): Giulia c'è, quindi esce il suo valore vero, 18. La riserva si usa solo se la chiave manca.
  8. get("Luca") + get("Marco"): due Integer, il + somma: 20 + 18 = 38.
  9. "Somma: " + get("Luca") + get("Marco"): si va da sinistra a destra. "Somma: " + 20 è già testo, poi si attacca 18: "Somma: 2018". Per sommare servono le parentesi: "Somma: " + (eta.get("Luca") + eta.get("Marco")).
Il valore di riserva va scelto beneQui -1 funziona perché nessuno ha età negativa: se vedo -1, so che la persona non c'era. Se avessi scelto 0 come riserva per un registro di punteggi, non potrei distinguere "ha fatto 0 punti" da "non c'è".
07Trova l'errore: lo spoglio che si blocca medio

Consegna. Per eleggere il rappresentante di classe, ogni scheda contiene un nome. Questo programma dovrebbe contare i voti di ogni candidato, ma si ferma subito con un errore:

import java.util.HashMap;

public class ElezioniRotto {
    public static void main(String[] args) {
        String[] schede = {"Sara", "Luca", "Sara", "Elia", "Sara", "Luca"};
        HashMap<String, Integer> voti = new HashMap<>();

        for (String nome : schede) {
            voti.put(nome, voti.get(nome) + 1);
        }
        System.out.println(voti);
    }
}
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "java.lang.Integer.intValue()" because the return value of "java.util.HashMap.get(Object)" is null
	at ...

1) Spiega perché si ferma, e proprio al primo giro. 2) Correggilo usando getOrDefault. 3) Alla fine stampa quanti voti hanno preso Sara, Luca, Elia e Marta (che non ha preso voti) in quest'ordine, e quanti candidati sono stati votati almeno una volta.

Output atteso dopo la correzione:

Sara: 3
Luca: 2
Elia: 1
Marta: 0
Candidati votati almeno una volta: 3
Soluzione spiegata

1 · Perché si blocca

  1. Al primo giro nome è "Sara" e la mappa è vuota.
  2. voti.get("Sara") restituisce quindi null.
  3. null + 1: per fare la somma Java deve trasformare l'Integer in int (unboxing, cioè chiamare intValue()), ma null non è un numero. Risultato: NullPointerException. Il messaggio lo dice in chiaro: "because the return value of HashMap.get(Object) is null".

Il problema è sempre la prima volta che si incontra un nome: lì la chiave non esiste ancora.

2 · La correzione

Con getOrDefault(nome, 0) la prima volta ottengo 0 invece di null: 0 + 1 = 1. Dalla seconda volta in poi ottengo il valore vero e aggiungo 1. Una riga sola fa entrambe le cose.

import java.util.HashMap;

public class Elezioni {
    public static void main(String[] args) {
        String[] schede = {"Sara", "Luca", "Sara", "Elia", "Sara", "Luca"};
        HashMap<String, Integer> voti = new HashMap<>();

        for (String nome : schede) {
            voti.put(nome, voti.getOrDefault(nome, 0) + 1);
        }

        String[] candidati = {"Sara", "Luca", "Elia", "Marta"};
        for (String c : candidati) {
            System.out.println(c + ": " + voti.getOrDefault(c, 0));
        }
        System.out.println("Candidati votati almeno una volta: " + voti.size());
    }
}

Perché funziona

  • Lo stesso getOrDefault(c, 0) serve anche nella stampa: Marta non è mai stata votata, quindi non è una chiave della mappa, e senza riserva stamperebbe "Marta: null".
  • voti.size() vale 3 e non 4: Marta non è mai entrata nella mappa. Le schede invece sono 6: size conta le chiavi diverse.
  • Stampo seguendo l'array candidati e non la mappa: così l'ordine è quello che decido io.

Da ricordare

Lo schema "contatore con una mappa" è uno dei più usati in assoluto: m.put(k, m.getOrDefault(k, 0) + 1);. Versione equivalente con l'if: se containsKey(k) allora put(k, get(k) + 1), altrimenti put(k, 1).

Rimuovere, svuotare e contare

Ripasso lamporemove(chiave) toglie la coppia (chiave e valore insieme); se la chiave non c'è non fa niente, senza errori. clear() svuota tutto ma la mappa continua a esistere. size() conta le coppie; isEmpty() equivale a size() == 0. Teoria: Rimuovere, svuotare e contare.
08Cosa stampa? Lo zaino facile

Consegna. La mappa associa ogni tasca dello zaino all'oggetto che contiene. Scrivi cosa stampa il frammento. Una delle due remove non fa quello che il programmatore sperava: quale, e perché?

Perché

  • clear() non distrugge la mappa: la svuota. La stampa di una mappa vuota è {}, e subito dopo ci si può rimettere dentro una coppia.

Consegna. Questo programma vuole togliere dalla mappa gli studenti con voto insufficiente (sotto 6). Compila, ma quando lo esegui si ferma:

Soluzione spiegata

1 · Che cosa succede

  1. ConcurrentModificationException vuol dire "modifica concorrente": la mappa è stata cambiata mentre la stavi scorrendo. È la stessa eccezione che hai visto con le liste quando togli elementi dentro un for-each.
  2. Il for-each su keySet() usa dietro le quinte un segnalibro (un iterator) che sa a che punto è arrivato. Quando chiami voti.remove(nome) la mappa cambia, ma il segnalibro non lo sa. Al giro successivo se ne accorge e, invece di rischiare di saltare o ripetere elementi, si ferma con l'eccezione.
  3. Nota che l'eccezione arriva al giro dopo la rimozione, non sulla riga del remove. Per questo, con dati diversi (per esempio se l'insufficiente fosse l'ultimo elemento del giro), a volte sembra funzionare: è un errore che non si vede sempre, quindi va evitato sempre.

2 · La correzione: prima segno, poi tolgo

Divido il lavoro in due giri. Nel primo scorro la mappa e mi segno in una ArrayList le chiavi da togliere, senza toccare la mappa. Nel secondo scorro la lista (non la mappa) e faccio i remove: ora la mappa non è sotto scorrimento, quindi si può modificare.

import java.util.ArrayList;
import java.util.HashMap;
import java.util.Map;

public class TogliGiusto {
    public static void main(String[] args) {
        HashMap<String, Integer> voti = new HashMap<>();
        voti.put("Anna", 7);
        voti.put("Bruno", 5);
        voti.put("Carla", 8);
        voti.put("Dario", 4);
        voti.put("Elisa", 6);

        // 1) mentre scorro, mi segno solo chi togliere
        ArrayList<String> daTogliere = new ArrayList<>();
        for (Map.Entry<String, Integer> e : voti.entrySet()) {
            if (e.getValue() < 6) {
                daTogliere.add(e.getKey());
            }
        }

        // 2) finito il giro, tolgo
        for (String nome : daTogliere) {
            voti.remove(nome);
        }

        System.out.println("Tolti: " + daTogliere.size());
        System.out.println("Rimasti: " + voti.size());
        System.out.println("Bruno c'è ancora? " + voti.containsKey("Bruno"));
        System.out.println(voti);
    }
}

Iterator<Map.Entry<String, Integer>> it = voti.entrySet().iterator();

    if (it.next().getValue() < 6) {

  • Fare put su una chiave già esistente mentre scorri (per esempio alzare tutti i voti di 1) invece è permesso: cambia un valore, non il numero di coppie.

Come funziona dentro: hash e cassetti

Ripasso lampoDentro la HashMap c'è un array di cassetti (bucket). Con hashCode() Java ricava un numero dalla chiave e da quel numero sceglie il cassetto: la stessa chiave dà sempre lo stesso numero, quindi get va dritto al cassetto giusto (O(1)). Due chiavi diverse nello stesso cassetto sono una collisione, risolta con equals(). Teoria: Come funziona dentro.
13Hash, cassetti e collisioni medio

Consegna. Esegui il programma e rispondi alle domande.

  1. Perché le prime due righe danno lo stesso numero? Perché è indispensabile per una HashMap?
  2. "Anna" e "anna" hanno hash diversi. Che conseguenza ha sulle chiavi?
  3. "Aa" e "BB" hanno lo stesso hash. Come si chiama questa situazione? Perché la mappa non le confonde?
  4. Perché tutto questo spiega che una HashMap non ha un ordine?
Soluzione spiegata

1 · Stessa chiave, stesso numero

hashCode() è un calcolo fatto sui caratteri della stringa: con gli stessi caratteri dà sempre lo stesso risultato. È indispensabile perché put("Anna", 17) mette la coppia nel cassetto ricavato da quel numero, e più tardi get("Anna") rifà lo stesso calcolo per sapere in quale cassetto guardare. Se il numero cambiasse, get guarderebbe nel cassetto sbagliato e non troverebbe niente.

2 · Maiuscole e minuscole

'A' e 'a' sono caratteri diversi, quindi il calcolo dà numeri diversi e, in generale, cassetti diversi. Per la mappa "Anna" e "anna" sono due chiavi diverse: get("anna") non trova Anna e restituisce null.

3 · Una collisione

Due chiavi diverse con lo stesso hash finiscono nello stesso cassetto: è una collisione. Per le stringhe il calcolo è "codice del primo carattere × 31 + codice del secondo": per "Aa" è 65 × 31 + 97 = 2112, per "BB" è 66 × 31 + 66 = 2112. Stesso risultato per caso!

Non è un problema: il cassetto può contenere più coppie. Quando fai get("BB"), Java va nel cassetto e confronta la chiave cercata con quelle presenti usando equals(): "BB" non è uguale ad "Aa", quindi prende la coppia giusta. Infatti l'ultima riga stampa 1 2 2: valori corretti e due coppie distinte.

4 · Perché non c'è ordine

Ogni coppia va nel cassetto deciso dal numero della sua chiave, non in fondo a una fila. Quando scorri la mappa, Java visita i cassetti dal primo all'ultimo: l'ordine di uscita dipende quindi dagli hash, non da quando hai fatto put. Per questo, nei programmi, non bisogna mai contare sull'ordine di una HashMap.

Da ricordareHash uguale non vuol dire chiavi uguali (collisione). Chiavi uguali invece devono sempre avere hash uguale: è la regola che rende possibile trovare le cose.

cHashMap<String, Integer>è un contatore per nome: studente → numero di interrogazioni.
dArrayList<Integer>conta l'ordine e i voti si ripetono (due 7 sono due voti diversi): in una mappa non saprei che chiave usare.
eHashMap<String, Integer>prodotto → quantità; se aggiungo di nuovo lo stesso prodotto non voglio una riga doppia ma aumentare la quantità.
fLinkedList<String> (o ArrayList)serve l'ordine di visita e si torna indietro dall'ultima: è una pila, e la stessa pagina può comparire più volte.

Da ricordare

  • Indizi di lista: "in ordine", "il primo", "l'ultimo", "la cronologia", duplicati che vanno tenuti tutti.
  • Indizi di mappa: "ogni X ha il suo Y", "quante volte compare", "cerca per codice/nome".
  • Spesso nello stesso programma servono entrambe: lo vedrai nell'esercizio completo, dove un registro delle operazioni (lista) affianca il magazzino (mappa).
16Dalle liste parallele alla mappa medio

Consegna. Una rubrica è salvata in due array paralleli: n[i] è il nome e t[i] il numero della stessa persona.

String[] n = {"Anna", "Bruno", "Carla", "Dario"};
String[] t = {"333 1111", "347 2222", "320 3333", "339 4444"};

Copia i dati sia in due ArrayList parallele sia in una HashMap. Scrivi un metodo cercaLista che trova il numero scorrendo le liste, e confrontalo con la ricerca nella mappa cercando "Carla", "Zoe" e "Anna". Quale versione è più semplice? Quale più veloce con 100.000 contatti?

Output atteso:

Carla (lista): 320 3333
Carla (mappa): 320 3333
Zoe (lista): non trovato
Zoe (mappa): non trovato
Anna (lista): 333 1111
Anna (mappa): 333 1111
Soluzione spiegata

Ragionamento

  1. Con le liste il legame nome–numero esiste solo perché stanno alla stessa posizione: per trovare il numero di Carla devo prima scoprire a che indice sta Carla (scorrendo) e poi leggere quell'indice nell'altra lista.
  2. Con la mappa il legame è dentro la coppia: chiedo direttamente rubrica.get("Carla").
  3. Per riempire le tre strutture basta un solo for sull'indice i.
  4. Per il "non trovato" nella mappa uso getOrDefault; nella lista è il return dopo il ciclo, che si raggiunge solo se nessun nome è uguale.

Codice

import java.util.ArrayList;
import java.util.HashMap;

public class Contatti {

    // versione con due liste parallele: devo scorrere
    static String cercaLista(ArrayList<String> nomi, ArrayList<String> numeri, String chi) {
        for (int i = 0; i < nomi.size(); i++) {
            if (nomi.get(i).equals(chi)) {
                return numeri.get(i);
            }
        }
        return "non trovato";
    }

    public static void main(String[] args) {
        String[] n = {"Anna", "Bruno", "Carla", "Dario"};
        String[] t = {"333 1111", "347 2222", "320 3333", "339 4444"};

        ArrayList<String> nomi = new ArrayList<>();
        ArrayList<String> numeri = new ArrayList<>();
        HashMap<String, String> rubrica = new HashMap<>();
        for (int i = 0; i < n.length; i++) {
            nomi.add(n[i]);
            numeri.add(t[i]);
            rubrica.put(n[i], t[i]);
        }

        String[] ricerche = {"Carla", "Zoe", "Anna"};
        for (String chi : ricerche) {
            System.out.println(chi + " (lista): " + cercaLista(nomi, numeri, chi));
            System.out.println(chi + " (mappa): " + rubrica.getOrDefault(chi, "non trovato"));
        }
    }
}

  • prezzi: titolo → prezzo (Double);
  • scorte: titolo → copie in negozio (Integer);
  • vendute: titolo → copie vendute oggi (Integer);
  • registro: l'elenco delle operazioni fatte, nell'ordine in cui sono avvenute (scegli tu la struttura giusta);
  • incasso: il totale incassato oggi.

E con questi metodi, ognuno dei quali scrive nel registro cosa ha fatto oppure un messaggio ERRORE: ...:

  1. nuovo(titolo, prezzo, copie): aggiunge un titolo, ma solo se non c'è già;
  2. vendi(titolo, copie): vende se il titolo esiste e ci sono abbastanza copie; aggiorna scorte, vendute e incasso;
  3. carica(titolo, copie): aggiunge copie a un titolo esistente;
  4. cambiaPrezzo(titolo, nuovo): sostituisce il prezzo;
  5. togli(titolo): toglie il titolo dal catalogo;
  6. esegui(comando): riceve un comando di testo come "VENDI Tex 2", lo divide con split(" ") e chiama il metodo giusto; se un numero non è valido (per esempio "tre") scrive un errore senza fermare il programma;
  7. report(): stampa il registro numerato, il magazzino (con il valore della merce e un avviso se c'è almeno un titolo esaurito) e le vendite (copie totali, titolo più venduto, incasso).

Soluzione spiegata

Passo 1 · Progettare prima di scrivere

Prima di scrivere codice decido le strutture. Per ognuna mi chiedo: cercherò per chiave, o mi serve l'ordine?

AttributoStrutturaChiave → valorePerché

venduteHashMap<String, Integer>titolo → copie venduteè un contatore per titolo

E per ogni metodo, quali operazioni della mappa servono:

MetodoOperazioni

Passo 2 · Aggiungere senza sovrascrivere

In nuovo il controllo con containsKey è fondamentale: l'ultimo comando, NUOVO Tex 4.0 3, senza controllo farebbe put su una chiave esistente e sostituirebbe in silenzio prezzo e scorte di Tex (riga 17 del registro: invece viene rifiutato). Ogni titolo nuovo entra in prezzi e in scorte con la stessa chiave: le due mappe vanno tenute "allineate".

Passo 3 · Vendere: tre controlli e tre aggiornamenti

  1. Il titolo esiste? Se no (Dylan), errore. Questo controllo evita anche che scorte.get restituisca null.
  2. Ci sono abbastanza copie? Diabolik ne ha 4 e ne chiedono 9: errore.
  3. Se è tutto a posto: scorte.put(titolo, disponibili - copie) sostituisce il valore; vendute.put(titolo, vendute.getOrDefault(titolo, 0) + copie) è lo schema del contatore (la prima vendita di un titolo parte da 0); l'incasso aumenta di copie × prezzo attuale.

Per questo Tex vende 2 copie a 4.5 (9.0) e, dopo il cambio di prezzo, 4 copie a 5.5 (22.0). Incasso totale: 9.0 + 15.0 (Naruto) + 22.0 + 12.0 (OnePiece) + 3.0 (Topolino) = 61.0.

Passo 4 · Leggere i comandi

split(" ") trasforma "VENDI Tex 2" nell'array {"VENDI", "Tex", "2"}: p[0] è il comando, p[1] il titolo, p[2] il numero, da convertire con Integer.parseInt (o Double.parseDouble per i prezzi). parseInt("tre") lancia NumberFormatException: il try-catch dentro esegui la cattura, scrive l'errore nel registro e il ciclo del main passa al comando successivo. I titoli sono di una parola sola (OnePiece) proprio perché lo spazio separa i pezzi del comando.

Passo 5 · Il report: tre modi di scorrere

  • Registro: è una lista, quindi lo scorro con l'indice e lo stampo numerato, nell'ordine giusto.
  • Magazzino: per ogni titolo servono nome e copie, quindi entrySet(); il prezzo lo prendo da un'altra mappa con prezzi.get(titolo), usando la stessa chiave. Qui l'ordine di uscita è quello dei cassetti, non quello di inserimento. Il valore della merce non dipende dall'ordine: 14 × 3.0 + 6 × 6.0 = 78.0 (Tex e Naruto hanno 0 copie).
  • Esauriti: "c'è almeno un titolo con 0 copie?" è una domanda sui valori: scorte.containsValue(0).
  • Copie vendute: servono solo i numeri, quindi values(): 6 + 3 + 2 + 1 = 12.
  • Più venduto: serve sapere chi, quindi keySet() e il confronto con get. Tex vince con 6 copie, senza pareggi, quindi il risultato non dipende dall'ordine.

Passo 6 · Le ricerche e la chiusura

Diabolik è stato tolto dal catalogo con remove, quindi containsKey dà false. Non ha mai venduto copie, quindi non è nemmeno una chiave di vendute: getOrDefault("Diabolik", 0) dà 0 invece di null. A fine giornata vendute.clear() svuota il contatore (la mappa resta, pronta per domani), mentre prezzi e scorte restano com'erano.

Codice completo

import java.util.ArrayList;
import java.util.HashMap;
import java.util.Map;

class Negozio {
    public HashMap<String, Double> prezzi = new HashMap<>();    // titolo -> prezzo
    public HashMap<String, Integer> scorte = new HashMap<>();   // titolo -> copie in negozio
    public HashMap<String, Integer> vendute = new HashMap<>();  // titolo -> copie vendute oggi
    public ArrayList<String> registro = new ArrayList<>();      // operazioni, in ordine
    public double incasso = 0;

    public void nuovo(String titolo, double prezzo, int copie) {
        if (prezzi.containsKey(titolo)) {
            registro.add("ERRORE: " + titolo + " è già in catalogo");
            return;
        }
        prezzi.put(titolo, prezzo);
        scorte.put(titolo, copie);
        registro.add("nuovo titolo " + titolo + " (" + copie + " copie a " + prezzo + ")");
    }

    public void vendi(String titolo, int copie) {
        if (!scorte.containsKey(titolo)) {
            registro.add("ERRORE: " + titolo + " non è in catalogo");
            return;
        }
        int disponibili = scorte.get(titolo);
        if (copie > disponibili) {
            registro.add("ERRORE: di " + titolo + " ci sono solo " + disponibili + " copie");
            return;
        }
        scorte.put(titolo, disponibili - copie);
        vendute.put(titolo, vendute.getOrDefault(titolo, 0) + copie);
        incasso += copie * prezzi.get(titolo);
        registro.add("venduti " + copie + " " + titolo);
    }

    public void carica(String titolo, int copie) {
        if (!scorte.containsKey(titolo)) {
            registro.add("ERRORE: " + titolo + " non è in catalogo");
            return;
        }
        scorte.put(titolo, scorte.get(titolo) + copie);
        registro.add("arrivate " + copie + " copie di " + titolo);
    }

    public void cambiaPrezzo(String titolo, double nuovo) {
        if (!prezzi.containsKey(titolo)) {
            registro.add("ERRORE: " + titolo + " non è in catalogo");
            return;
        }
        double vecchio = prezzi.get(titolo);
        prezzi.put(titolo, nuovo);
        registro.add("prezzo di " + titolo + ": " + vecchio + " -> " + nuovo);
    }

    public void togli(String titolo) {
        if (!prezzi.containsKey(titolo)) {
            registro.add("ERRORE: " + titolo + " non è in catalogo");
            return;
        }
        prezzi.remove(titolo);
        scorte.remove(titolo);
        registro.add("tolto dal catalogo " + titolo);
    }

    public void esegui(String comando) {
        String[] p = comando.split(" ");
        try {
            if (p[0].equals("NUOVO")) {
                nuovo(p[1], Double.parseDouble(p[2]), Integer.parseInt(p[3]));
            } else if (p[0].equals("VENDI")) {
                vendi(p[1], Integer.parseInt(p[2]));
            } else if (p[0].equals("CARICA")) {
                carica(p[1], Integer.parseInt(p[2]));
            } else if (p[0].equals("PREZZO")) {
                cambiaPrezzo(p[1], Double.parseDouble(p[2]));
            } else if (p[0].equals("TOGLI")) {
                togli(p[1]);
            } else {
                registro.add("ERRORE: comando sconosciuto " + p[0]);
            }
        } catch (NumberFormatException e) {
            registro.add("ERRORE: numero non valido in '" + comando + "'");
        }
    }

    public void report() {
        System.out.println("=== Registro (in ordine) ===");
        for (int i = 0; i < registro.size(); i++) {
            System.out.println((i + 1) + ". " + registro.get(i));
        }

        System.out.println("=== Magazzino ===");
        System.out.println("Titoli in catalogo: " + prezzi.size());
        double valore = 0;
        for (Map.Entry<String, Integer> e : scorte.entrySet()) {
            String titolo = e.getKey();
            int copie = e.getValue();
            String nota = "";
            if (copie == 0) {
                nota = "  ESAURITO";
            }
            System.out.println(titolo + ": " + copie + " copie a " + prezzi.get(titolo) + nota);
            valore += copie * prezzi.get(titolo);
        }
        System.out.println("Valore della merce: " + valore);
        if (scorte.containsValue(0)) {
            System.out.println("Attenzione: almeno un titolo è esaurito, da riordinare!");
        }

        System.out.println("=== Vendite ===");
        int copieTotali = 0;
        for (int c : vendute.values()) {
            copieTotali += c;
        }
        String best = null;
        for (String titolo : vendute.keySet()) {
            if (best == null || vendute.get(titolo) > vendute.get(best)) {
                best = titolo;
            }
        }
        System.out.println("Copie vendute: " + copieTotali);
        System.out.println("Più venduto: " + best + " (" + vendute.get(best) + " copie)");
        System.out.println("Incasso: " + incasso);
    }
}

Controlla di aver capito

  • Perché il registro è una ArrayList e non una mappa? (Serve l'ordine, e una mappa non lo garantisce; inoltre non c'è una chiave naturale per un'operazione.)
  • Perché le righe del magazzino non escono nell'ordine Topolino, Tex, Naruto, OnePiece? (Ogni coppia sta nel cassetto deciso dall'hash del titolo; scorrendo, Java visita i cassetti in fila. Se ti serve l'ordine di inserimento c'è LinkedHashMap, se ti serve l'ordine alfabetico TreeMap.)
  • Cosa succederebbe se in vendi scrivessi vendute.put(titolo, vendute.get(titolo) + copie)? (Alla prima vendita di ogni titolo get darebbe null e il programma si fermerebbe con NullPointerException.)
  • Dopo TOGLI Diabolik, quanto vale prezzi.size()? E perché il report dice 4 titoli anche se ne abbiamo creati 5? (4: Topolino, Tex, Naruto, OnePiece. Diabolik è stato rimosso.)
  • Perché scorte.containsValue(0) è più lento di scorte.containsKey("Tex")? (Il primo deve guardare tutte le coppie, O(n); il secondo va dritto al cassetto, O(1).)
