Java: gestione dei file

Fino a ora i dati dei tuoi programmi sono vissuti solo nella memoria: appena il programma finisce, spariscono. Un file invece resta sul disco. In questo capitolo impari a creare, leggere, scrivere ed eliminare file di testo con le classi classiche di Java: File, FileWriter e FileReader.

Prima di cominciareLe operazioni sui file possono fallire (file mancante, disco pieno), perciò in Java si usano sempre dentro un try-catch: lo rivediamo da vicino più sotto. In questo capitolo vedi il modo classico di lavorare con i file, che si basa su un carattere alla volta; esiste anche un modo più moderno e più breve (Path e Files), che trovi accennato in fondo. Conoscere quello classico ti serve per leggere il codice di chiunque.

Perché servono i file

Una variabile vive nella RAM, la memoria veloce ma temporanea del computer: quando il programma termina, il suo contenuto viene perso. Per far sopravvivere un dato (un punteggio, un elenco di studenti, un'impostazione) bisogna salvarlo su un supporto permanente: il disco. Lì i dati si organizzano in file.

VariabileFile

A cosa servecalcoli durante l'esecuzionesalvare e riprendere i dati

In questo capitolo lavoriamo con i file di testo: contengono lettere, cifre e simboli che puoi aprire con il Blocco note. (I file di immagini, audio o PDF sono binari e si trattano in altro modo.)

La classe File

Il punto di partenza è la classe java.io.File. Un oggetto File rappresenta un file o una cartella del computer, ma attenzione a cosa non fa:

Cosa è un oggetto File Un oggetto File è soltanto un indirizzo con tanti metodi. Non apre il file, non legge il contenuto e non lo crea. Serve per fare domande (esiste? dove sta?) e per compiere operazioni sul file stesso (eliminarlo).
Un paragoneUn oggetto File è come il biglietto con l'indirizzo di una casa. Con il biglietto puoi chiederti "la casa esiste?" o "in che via è?", ma finché non ci entri (con un FileReader o un FileWriter) non sai cosa c'è dentro. E scrivere un indirizzo su un biglietto non costruisce la casa.

Come si crea

import java.io.File;

File documento = new File("prova.txt");

Il costruttore riceve il nome (o il percorso) del file come stringa. Se il file prova.txt non c'è, nessun errore e nessun file creato: la variabile documento punta semplicemente a un indirizzo, che per ora potrebbe essere vuoto.

Percorso relativo e percorso assoluto

Relativo

Solo il nome, o un percorso che parte dalla cartella di lavoro del programma.

new File("prova.txt");
new File("dati/prova.txt");

Il file si cerca accanto al progetto (la working directory, cioè la cartella da cui parte il programma).

Assoluto

Il percorso completo, dalla radice del disco.

new File("/Users/daniele/Desktop/prova.txt");
new File("C:\\Users\\daniele\\prova.txt");

Punta a un file preciso del computer, ovunque sia il programma.

Le barre su WindowsIn una stringa Java il carattere \ è speciale (\n è l'a capo). Per scrivere un percorso Windows servono quindi due barre: "C:\\Users\\prova.txt". Oppure usa la barra normale /, che Java capisce su tutti i sistemi: "C:/Users/prova.txt".

Per i tuoi programmi di scuola conviene il percorso relativo: funziona su qualunque computer, senza dover sapere come si chiama la cartella dell'utente.

Verificare se un file esiste

Prima di leggere o eliminare un file è buona norma controllare che ci sia, con il metodo exists().

File documento = new File("prova.txt");

if (documento.exists()) {
    System.out.println("Il file esiste");
} else {
    System.out.println("Il file non esiste");
}

exists() restituisce true se il file (o la cartella) è presente, false altrimenti. Nota che non lancia mai un'eccezione: risponde solo sì o no.

Perché è importante

  • Evita errori: aprire con FileReader un file che non c'è lancia una FileNotFoundException.
  • Permette di scegliere: il programma decide cosa fare in base a cosa trova (chiedere un altro nome, creare il file, avvisare l'utente).
  • Protegge i dati: sai se stai per sovrascrivere un file già pieno.
Controllare non bastaexists() dice com'era il disco un attimo fa. Tra il controllo e l'apertura un altro programma potrebbe cancellare il file, o i permessi potrebbero impedirti di leggerlo. Per questo il controllo si affianca al try-catch, non lo sostituisce.

L'output di getAbsolutePath() dipende dal tuo computer: Java prende la cartella di lavoro e le attacca davanti il nome. È utile quando non trovi il file che il programma ha creato: stampi il percorso assoluto e sai esattamente dove guardare.

Scrivere in un file con FileWriter

FileWriter è la classe che permette di scrivere caratteri in un file di testo. Se il file non esiste, lo crea.

import java.io.FileWriter;
import java.io.IOException;

try {
    FileWriter scrittore = new FileWriter("prova.txt");

    scrittore.write("Ciao sono Daniele Gravina\n");
    scrittore.write("Sono il vostro professore\n");
    scrittore.append("Insegno anche Sistemi e Reti");

    scrittore.close();
} catch (IOException e) {
    e.printStackTrace();
}

Cosa succede, riga per riga

  1. new FileWriter("prova.txt") apre il file in scrittura. Se non c'è lo crea; se c'è già, lo svuota (vedi più sotto).
  2. write("...") scrive la stringa nel file. Il \n alla fine manda a capo: senza, la frase successiva si attacca alla precedente.
  3. append("...") scrive il testo dopo quello già scritto. Qui è l'ultima riga, quindi senza \n.
  4. close() chiude il file e libera le risorse.

Il file prova.txt contiene alla fine:

Ciao sono Daniele Gravina
Sono il vostro professore
Insegno anche Sistemi e Reti

I tre metodi principali

MetodoCosa fa
write(String s)scrive la stringa nel file
append(String s)scrive la stringa subito dopo quello che hai già scritto
close()chiude il file: sempre obbligatorio

Sovrascrivere o aggiungere?

Questo è il punto che crea più confusione. Per aggiungere in fondo a un file che esiste già, senza cancellarlo, bisogna dirlo quando si apre il file, con un secondo argomento:

new FileWriter("prova.txt");          // sovrascrive: il vecchio contenuto sparisce
new FileWriter("prova.txt", true);    // aggiunge in fondo: il vecchio contenuto resta
CostruttoreModalitàSe il file esiste già
new FileWriter("a.txt")sovrascritturaviene svuotato appena lo apri
new FileWriter("a.txt", true)appendsi scrive dopo il contenuto che c'è già
Attenzione: il metodo append() ingannaNelle slide si legge che append() "aggiunge testo alla fine del file senza cancellare il contenuto precedente". In realtà append(s) fa la stessa cosa di write(s): scrive dopo ciò che hai già scritto in quella apertura. Se il file esisteva già, con new FileWriter("a.txt") il vecchio contenuto è già sparito prima ancora di chiamare append(). Per conservarlo serve il true nel costruttore. Esempio: dopo new FileWriter("prova.txt") + write("NUOVO") il file contiene solo NUOVO; con new FileWriter("prova.txt", true) + write("+AGGIUNTO") contiene NUOVO+AGGIUNTO.

Perché close() è obbligatorio

Per essere veloce, FileWriter non scrive sul disco ogni carattere appena lo ricevi: li tiene in una memoria temporanea (buffer) e li scarica sul disco a blocchi. Con close() il buffer viene scaricato e il file viene rilasciato.

  • Se dimentichi close(), parte del testo (o tutto!) può non finire mai sul disco. In una prova, un write("testo") senza close() ha lasciato il file con 0 byte.
  • Un file lasciato aperto può restare bloccato e non si riesce a eliminarlo o aprirlo con un altro programma.
Un paragoneÈ come scrivere una lettera: write è scrivere sul foglio, close è mettere la lettera nella busta e imbucarla. Se non la imbuchi, resta sulla tua scrivania e nessuno la riceve.

Approfondimento: try-with-resources

Per non dimenticare mai il close(), si può dichiarare il FileWriter tra parentesi dopo try: Java lo chiude da solo, anche se c'è un errore.

try (FileWriter scrittore = new FileWriter("prova.txt")) {
    scrittore.write("Ciao!");
    // il file viene chiuso automaticamente alla fine del blocco
} catch (IOException e) {
    e.printStackTrace();
}

Questa forma è un'aggiunta alle slide. Funziona allo stesso modo anche con FileReader.

Leggere un file con FileReader

FileReader legge il contenuto di un file di testo un carattere alla volta.

import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.IOException;

try {
    FileReader lettore = new FileReader("prova.txt");
    int data = lettore.read();               // legge il primo carattere (come numero)

    while (data != -1) {                     // -1 = fine del file
        System.out.print((char) data);       // lo converte in carattere leggibile
        data = lettore.read();               // legge il carattere successivo
    }

    lettore.close();
} catch (FileNotFoundException e) {
    e.printStackTrace();
} catch (IOException e) {
    e.printStackTrace();
}

Il ciclo di lettura, passo per passo

  1. new FileReader("prova.txt") apre il file. Se non esiste lancia FileNotFoundException.
  2. lettore.read() legge un solo carattere e lo restituisce come int. La prima volta è il primo carattere del file.
  3. Il while controlla: la lettura ha dato -1? Se sì, il file è finito. Altrimenti si entra nel ciclo.
  4. (char) data trasforma il numero in carattere, e print lo stampa.
  5. read() viene chiamato di nuovo in fondo al ciclo per prendere il carattere successivo, e si torna al punto 3.
  6. Quando read() restituisce -1, il ciclo termina e close() chiude il file.

Perché read() restituisce un int?

Ogni carattere è memorizzato come un numero (il suo codice: 'C' è 67, 'a' è 97). read() restituisce proprio quel numero, per questo il tipo è int e per leggerlo come lettera serve il cast (char).

int data = lettore.read();            // 67
System.out.println(data);             // 67
System.out.println((char) data);      // C

Ma perché non char? Perché serve un valore che non sia nessun carattere per dire "il file è finito": quel valore è -1, e un char non può essere negativo. Il tipo int ha lo spazio per tutti i caratteri più il -1.

EOFEOF significa End Of File, fine del file. In Java read() lo segnala restituendo -1. Il ciclo di lettura è sempre lo stesso schema: leggi, controlla se è -1, usa il dato, leggi di nuovo.
Errore classico: due read() per giroNon scrivere while (lettore.read() != -1) { System.out.print((char) lettore.read()); }. Ogni chiamata a read() consuma un carattere: la condizione ne legge uno (e lo butta) e il print ne legge un altro, quindi stampi solo un carattere su due. Il carattere va letto una volta sola, salvato in una variabile (data) e usato da lì.

Due catch, in che ordine?

Il codice ha due catch: FileNotFoundException (file mancante) e IOException (qualsiasi altro problema di lettura). FileNotFoundException è figlia di IOException, quindi va scritta per prima: se mettessi IOException davanti, la seconda non sarebbe mai raggiungibile e il codice non compilerebbe (regola dei catch dal più specifico al più generale).

Puoi anche usarne uno soloSe non vuoi trattare diversamente "file mancante" e "altro errore", basta un solo catch (IOException e): copre anche FileNotFoundException.

Leggere per righe: BufferedReader

Aggiunta alle slide. Leggere carattere per carattere è semplice ma lento e scomodo. La classe BufferedReader avvolge il FileReader e permette di leggere una riga intera con readLine(), che restituisce null alla fine del file.

import java.io.BufferedReader;

try (BufferedReader lettore = new BufferedReader(new FileReader("prova.txt"))) {
    String riga = lettore.readLine();
    while (riga != null) {
        System.out.println(riga);
        riga = lettore.readLine();
    }
} catch (IOException e) {
    e.printStackTrace();
}

Lo schema è identico: la sentinella di fine file è null invece di -1. Per ora ti basta riconoscerlo: il capitolo si basa su FileReader e read().

Eliminare un file con delete()

Il metodo delete() della classe File rimuove il file dal disco. Restituisce true se l'eliminazione riesce, false altrimenti.

File documento2 = new File("prova2.txt");

if (documento2.exists()) {
    if (documento2.delete()) {
        System.out.println("File eliminato!");
    } else {
        System.out.println("Errore nell'eliminazione");
    }
} else {
    System.out.println("Il file non esiste");
}

Ci sono tre possibili esiti, e il programma li distingue tutti:

SituazioneCosa stampa
Il file esiste e viene eliminatoFile eliminato!
Il file esiste ma delete() fallisce (aperto altrove, niente permessi)Errore nell'eliminazione
Il file non esisteIl file non esiste

Regole importanti

  • Verifica prima con exists(), come nell'esempio. (Senza il controllo, delete() su un file inesistente restituisce semplicemente false, senza errori: non puoi distinguere "non c'era" da "non ci sono riuscito".)
  • Controlla il risultato: delete() non lancia eccezioni, restituisce solo true o false. Se non guardi il valore, non sai se ha funzionato.
  • Un file aperto da un altro programma (o da un tuo FileWriter non chiuso) può non essere eliminabile, soprattutto su Windows.
  • Una cartella si elimina con delete() solo se è vuota.
L'eliminazione è permanenteI file eliminati con delete() non vanno nel cestino: spariscono subito e non c'è modo di recuperarli. Scrivi con attenzione il nome del file, specialmente se lo prendi da tastiera.

Gestione delle eccezioni: try-catch

Le operazioni sui file sono rischiose: il file potrebbe non esistere, i permessi potrebbero essere insufficienti, il disco potrebbe essere pieno, la cartella potrebbe non esserci. Non è colpa del tuo codice, è il mondo esterno. Per questo FileWriter e FileReader lanciano eccezioni checked e Java ti obbliga a gestirle.

Blocco try

Contiene il codice rischioso: apertura, lettura, scrittura e chiusura del file.

Blocco catch

Cattura l'eccezione se si verifica e la gestisce, senza far crollare il programma.

try {
    // codice rischioso
    FileWriter scrittore = new FileWriter("prova.txt");
    scrittore.write("Ciao!");
    scrittore.close();
} catch (IOException e) {
    e.printStackTrace();   // stampa l'errore completo sulla console
}

printStackTrace() stampa il percorso completo dell'errore, dalla causa fino al punto del programma in cui si è verificato. È utile per capire cosa è andato storto mentre scrivi il programma.

Quali eccezioni lanciano

IstruzioneQuando lanciaEccezione
new FileReader(nome)il file non esiste (o è una cartella)FileNotFoundException
new FileWriter(nome)la cartella non esiste, o non hai i permessiFileNotFoundException (o altra IOException)
read(), write(), close()errore durante l'operazione (disco pieno…)IOException
exists(), delete(), isFile(), getPath()mainessuna: restituiscono true/false o una stringa

Per questo i metodi di File (exists, delete…) si possono usare anche fuori da un try, mentre FileReader e FileWriter no. Una prova: new FileReader("nonc.txt") lancia java.io.FileNotFoundException: nonc.txt (No such file or directory) (il testo tra parentesi dipende dal sistema operativo).

La chiusura è parte del rischio

Anche close() può lanciare IOException, ed è per questo che sta dentro il try. C'è però un limite del codice delle slide: se un errore avviene prima del close() (per esempio in una write), il close() viene saltato e il file resta aperto. Le due soluzioni sono il blocco finally (che viene eseguito sempre, anche dopo un errore, e quindi è il posto giusto per chiudere il file) oppure, più semplice, il try-with-resources visto prima.

Un programma completo: il diario

Mettiamo insieme tutto. Il programma chiede una frase, la aggiunge in fondo a diario.txt e poi stampa tutto il diario. Ogni volta che lo esegui il diario si allunga.

import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;
import java.util.Scanner;

public class Diario {
    public static void main(String[] args) {
        Scanner tastiera = new Scanner(System.in);
        System.out.print("Cosa vuoi scrivere oggi? ");
        String riga = tastiera.nextLine();

        // 1) scrittura in modalità append
        try {
            FileWriter scrittore = new FileWriter("diario.txt", true);
            scrittore.write(riga + "\n");
            scrittore.close();
        } catch (IOException e) {
            System.out.println("Impossibile scrivere il diario: " + e.getMessage());
            return;
        }

        // 2) lettura di tutto il file
        System.out.println("--- Il tuo diario ---");
        try {
            FileReader lettore = new FileReader("diario.txt");
            int c = lettore.read();
            while (c != -1) {
                System.out.print((char) c);
                c = lettore.read();
            }
            lettore.close();
        } catch (IOException e) {
            System.out.println("Impossibile leggere il diario: " + e.getMessage());
        }

        tastiera.close();
    }
}

Eseguito due volte (scrivendo prima Oggi ho studiato Java e poi Domani verifica), la seconda volta stampa:

Cosa vuoi scrivere oggi? Domani verifica
--- Il tuo diario ---
Oggi ho studiato Java
Domani verifica
  • Il true in new FileWriter("diario.txt", true) è ciò che fa crescere il diario invece di ripartire da zero.
  • Scrittura e lettura hanno due try-catch separati: se uno fallisce, l'altro non ne risente. Il return nel primo evita di leggere un diario che non è stato aggiornato.
  • Il "\n" dopo riga serve a far andare a capo la frase successiva.

Un cenno al modo moderno: Path e Files

Da Java 11 esiste un modo più breve di fare le stesse cose, con le classi Path e Files (del package java.nio.file). Non lo studiamo qui, ma è utile vedere come si traduce ciò che hai imparato:

OperazioneModo classico (questo capitolo)Modo moderno (Path / Files)

Esiste?f.exists()Files.exists(p)
ScrivereFileWriter + write() + close()Files.writeString(p, testo)

Il modo moderno è più breve perché legge e scrive tutto il file in una sola istruzione; il modo classico ti fa vedere cosa succede davvero (apri, leggi un carattere alla volta, chiudi) ed è ancora ovunque nel codice già scritto e nei libri di testo.

Mappa riassuntiva

  • I file conservano i dati sul disco; le variabili spariscono a fine programma.
  • File è solo un indirizzo con metodi: non apre, non legge, non crea. Percorso relativo ("prova.txt") o assoluto (completo).
  • exists() controlla la presenza; getPath() dà il percorso come scritto, getAbsolutePath() quello completo; isFile() distingue file e cartelle.
  • FileWriter: write scrive, close è obbligatorio. new FileWriter(nome) sovrascrive; new FileWriter(nome, true) aggiunge in fondo.
  • FileReader: read() restituisce un carattere come int; -1 = fine file; si converte con (char). Schema: leggi, controlla -1, usa, leggi di nuovo.
  • delete() restituisce true/false, non lancia eccezioni, è permanente (niente cestino).
  • FileReader e FileWriter lanciano IOException (checked): vanno in un try-catch. FileNotFoundException è figlia di IOException e va prima.

Esercizi

01Cosa stampa? facile
File f = new File("misterioso.txt");   // il file NON esiste sul disco
System.out.println(f.exists());
System.out.println(f.getPath());
System.out.println(f.isFile());

Cosa stampa? Il programma si ferma con un errore?

Soluzione

Stampa, una per riga: false, misterioso.txt, false. Nessun errore.

Creare un oggetto File non crea né apre il file: è solo un indirizzo. exists() e isFile() rispondono false perché sul disco non c'è niente, e getPath() restituisce il nome così come è stato scritto nel costruttore, anche se il file non c'è. Nessuno di questi metodi lancia eccezioni.

02Cosa contiene il file? medio
// Esecuzione 1
FileWriter w1 = new FileWriter("x.txt");
w1.write("uno ");
w1.close();

// Esecuzione 2
FileWriter w2 = new FileWriter("x.txt");
w2.write("due");
w2.close();

Cosa contiene x.txt alla fine? Come cambia se nell'Esecuzione 2 si scrive new FileWriter("x.txt", true)? E se la seconda volta si usasse w2.append("due") con il costruttore senza true?

Soluzione
  • Così com'è: due. Il secondo new FileWriter("x.txt") svuota il file, quindi uno sparisce.
  • Con new FileWriter("x.txt", true): uno due. Il true attiva la modalità append e il vecchio contenuto resta.
  • Con append("due") senza true: ancora due. Il file era già stato svuotato all'apertura, e append scrive solo dopo ciò che hai scritto in quella apertura.

La modalità si sceglie quando si apre il file, non con il metodo write o append. (Il codice va messo in un try-catch.)

03Mancano delle lettere medio
FileReader lettore = new FileReader("a.txt");   // a.txt contiene: abcdef
while (lettore.read() != -1) {
    System.out.print((char) lettore.read());
}
lettore.close();

Cosa stampa? Perché? Correggi il codice perché stampi abcdef.

Soluzione

Stampa bdf. Ogni chiamata a read() avanza di un carattere: la condizione del while legge a e lo scarta, il print legge e stampa b; poi la condizione scarta c, il print stampa d; e così via. Si stampa un carattere su due.

Il carattere va letto una volta sola e salvato in una variabile:

int data = lettore.read();
while (data != -1) {
    System.out.print((char) data);
    data = lettore.read();
}

(Oppure, in forma compatta: while ((data = lettore.read()) != -1) { ... }.)

04Elimina in sicurezza facile

Scrivi un metodo static void elimina(String nome) che elimina il file con quel nome e stampa uno tra tre messaggi: "File eliminato!", "Errore nell'eliminazione" oppure "Il file non esiste".

Soluzione
static void elimina(String nome) {
    File f = new File(nome);
    if (!f.exists()) {
        System.out.println("Il file non esiste");
    } else if (f.delete()) {
        System.out.println("File eliminato!");
    } else {
        System.out.println("Errore nell'eliminazione");
    }
}

Chiamandolo due volte di fila con lo stesso file esistente, la prima stampa File eliminato! e la seconda Il file non esiste. Non serve alcun try-catch: né exists() né delete() lanciano eccezioni. L'else if (f.delete()) esegue l'eliminazione e ne controlla il risultato nello stesso passaggio.

05Copia un file medio

Scrivi un metodo static void copia(String da, String a) che copia il contenuto del file da in un nuovo file a, carattere per carattere. Se il file di origine non esiste, stampa un messaggio e non fa altro.

Soluzione
static void copia(String da, String a) {
    File origine = new File(da);
    if (!origine.exists()) {
        System.out.println("Il file di origine non esiste.");
        return;
    }
    try {
        FileReader lettore = new FileReader(origine);
        FileWriter scrittore = new FileWriter(a);

        int c = lettore.read();
        while (c != -1) {
            scrittore.write(c);       // write accetta anche il codice del carattere
            c = lettore.read();
        }

        lettore.close();
        scrittore.close();
        System.out.println("Copiato.");
    } catch (IOException e) {
        System.out.println("Errore: " + e.getMessage());
    }
}
  • Si aprono due file insieme: uno in lettura e uno in scrittura, e vanno chiusi entrambi.
  • FileWriter.write(int) scrive direttamente il carattere con quel codice, quindi non serve nessun cast.
  • Il costruttore new FileReader(origine) accetta anche un oggetto File, non solo una stringa.
  • Basta un solo catch (IOException e), perché FileNotFoundException è una sua figlia.
  • Se a esiste già, new FileWriter(a) lo sovrascrive.
06Statistiche di un file medio

Scrivi un metodo static void statistiche(String nome) che legge un file di testo e stampa quanti caratteri, quante righe (cioè quanti \n) e quante vocali contiene. Se il file contiene Ciao a tutti e buona giornata su due righe, il risultato è 28 caratteri, 2 righe, 13 vocali.

Soluzione
static void statistiche(String nome) {
    int caratteri = 0, righe = 0, vocali = 0;
    try (FileReader lettore = new FileReader(nome)) {
        int c;
        while ((c = lettore.read()) != -1) {
            caratteri++;
            char ch = Character.toLowerCase((char) c);
            if (ch == '\n') {
                righe++;
            }
            if ("aeiou".indexOf(ch) != -1) {
                vocali++;
            }
        }
        System.out.println(caratteri + " caratteri, " + righe + " righe, " + vocali + " vocali");
    } catch (IOException e) {
        System.out.println("Errore: " + e.getMessage());
    }
}
  • Il ciclo si ripete una volta per carattere: è il punto in cui si aggiornano i contatori.
  • Anche l'a capo \n è un carattere e viene contato in caratteri (28 = 12 + 1 + 14 + 1).
  • Character.toLowerCase trasforma in minuscolo, così A e a contano allo stesso modo.
  • "aeiou".indexOf(ch) dà la posizione della lettera nella stringa, o -1 se non c'è: diverso da -1 significa "è una vocale".
  • Se l'ultima riga non finisce con \n non viene contata come riga: le righe contate sono i \n.
07Il diario con la data completo

Modifica il programma Diario in modo che, prima di aggiungere la frase, controlli se diario.txt esiste già. Se non esiste, stampi "Creo un nuovo diario."; se esiste, stampi "Aggiungo al diario esistente (N byte).", dove N è la dimensione del file.

Soluzione
File diario = new File("diario.txt");
if (diario.exists()) {
    System.out.println("Aggiungo al diario esistente (" + diario.length() + " byte).");
} else {
    System.out.println("Creo un nuovo diario.");
}

try {
    FileWriter scrittore = new FileWriter(diario, true);
    scrittore.write(riga + "\n");
    scrittore.close();
} catch (IOException e) {
    System.out.println("Impossibile scrivere il diario: " + e.getMessage());
    return;
}
  • Il controllo con exists() va fatto prima di aprire il FileWriter: aprendolo, il file verrebbe creato e risulterebbe sempre esistente.
  • length() restituisce la dimensione in byte; con testo senza accenti 1 carattere = 1 byte.
  • Anche FileWriter accetta un oggetto File nel costruttore, con lo stesso secondo argomento true per la modalità append.
  • Il resto del programma (la lettura e la stampa) non cambia.
