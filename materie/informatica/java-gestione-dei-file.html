Java: gestione dei file

Finora i dati dei programmi vivevano solo nella memoria e sparivano alla chiusura. Un file invece resta sul disco: con Java si può controllare se esiste, scriverci dentro, leggerlo ed eliminarlo.

Prima di cominciareServono le basi di Java (variabili, if, while) e un'idea di cos'è un oggetto: se ti manca, vedi Java: programmazione a oggetti. Qui useremo solo file di testo (come prova.txt), che si possono aprire con il Blocco note.

Perché servono i file

Le variabili stanno nella memoria (RAM) e si perdono quando il programma termina. Per conservare dei dati (i voti degli studenti, una classifica, le impostazioni) bisogna salvarli su un file, che rimane sul disco e può essere riletto la volta dopo, anche da un altro programma.

Con Java si possono fare cinque operazioni fondamentali, che sono anche i paragrafi di questo capitolo:

  1. Verificare che un file esista;
  2. Esplorare il suo percorso (dove si trova);
  3. Scrivere dati dentro un file;
  4. Leggere il contenuto di un file;
  5. Eliminare un file.
Un paragonePensa a un quaderno: la classe File è il quaderno visto da fuori (c'è? come si chiama? dov'è sullo scaffale? lo butto?), mentre FileWriter e FileReader sono la penna e gli occhi con cui scrivi e leggi quello che c'è dentro.

La classe File

Il punto di partenza è la classe java.io.File. Un oggetto File rappresenta un file o una cartella del file system, ma attenzione: non apre e non legge il contenuto. Serve solo per avere informazioni sul file e per fare operazioni "sul file stesso" (controllare se c'è, eliminarlo…).

import java.io.File;

File documento = new File("prova.txt");
In una fraseLa classe File è il ponte tra il programma Java e il file system del computer: sa indicare un file, ma per scriverci o leggerci servono altre classi.

Creare l'oggetto new File("prova.txt") non crea il file sul disco: è come scrivere un indirizzo su un foglietto, la casa può anche non esistere. Per questo esiste il metodo exists() (paragrafo seguente).

Percorso relativo e percorso assoluto

Percorso relativo

new File("prova.txt");

Il nome è relativo alla cartella del progetto (la cartella da cui parte il programma): il file viene cercato lì.

"Il file è qui, in questa cartella."

Percorso assoluto

new File("/Users/daniele/Desktop/prova.txt");

Il percorso completo, dalla radice del disco: punta a un file preciso, ovunque si trovi.

"Il file è esattamente in questo indirizzo."

Attenzione ai percorsiSu Windows un percorso è fatto così: C:\Users\Mario\Desktop\prova.txt. In Java il simbolo \ dentro una stringa è speciale (\n è "a capo"), quindi va raddoppiato: "C:\\Users\\Mario\\Desktop\\prova.txt". In alternativa si può usare la barra normale /, che Java accetta anche su Windows. (Aggiunta alle slide.)

Verificare se un file esiste

Prima di leggere o scrivere è buona norma controllare che il file esista con il metodo exists(): restituisce true se il file (o la cartella) c'è, false altrimenti.

File documento = new File("prova.txt");

if (documento.exists()) {
    System.out.println("Il file esiste");
} else {
    System.out.println("Il file non esiste");
}
Evita le eccezioni

Leggere un file inesistente genera una FileNotFoundException.

Controllo preventivo

Il programma decide cosa fare in base alla presenza del file.

Best practice

Verificare sempre prima di operare su risorse esterne.

Non è una garanzia assolutaexists() fotografa la situazione in quel momento: tra il controllo e l'uso il file potrebbe sparire o essere bloccato. Per questo il controllo non sostituisce il try-catch (ultimo paragrafo): i due si usano insieme. (Aggiunta alle slide.)

Informazioni sul file: getPath, getAbsolutePath, isFile

La classe File offre altri metodi per sapere di più sul file.

MetodoCosa restituisceEsempio di output
getPath()il percorso relativo, cioè quello scritto nel costruttoreprova.txt
getAbsolutePath()il percorso assoluto completo, dalla radice del disco/Users/daniele/…/prova.txt
isFile()true se il percorso punta a un file regolare (non a una cartella)true
 
File documento = new File("prova.txt");

System.out.println(documento.getPath());          // prova.txt
System.out.println(documento.getAbsolutePath());  // /Users/.../prova.txt
System.out.println(documento.isFile());           // true

getPath() restituisce esattamente ciò che hai scritto tra le virgolette; getAbsolutePath() ci aggiunge davanti la cartella da cui sta girando il programma. È utile per scoprire dove Java sta davvero cercando il tuo file: se il file "non si trova", spesso è perché si trova in un'altra cartella.

Altri metodi utiliNon sono nelle slide, ma completano il quadro: isDirectory() (è una cartella?), length() (dimensione in byte), getName() (solo il nome, senza cartelle), createNewFile() (crea un file vuoto) e mkdir() (crea una cartella). Come exists() e delete(), anche isFile() e isDirectory() danno una risposta true/false.

Scrivere in un file con FileWriter

FileWriter è la classe che permette di scrivere caratteri in un file di testo. Se il file non esiste, viene creato.

import java.io.FileWriter;
import java.io.IOException;

try {
    FileWriter scrittore = new FileWriter("prova.txt");

    scrittore.write("Ciao sono Daniele Gravina\n");
    scrittore.write("Sono il vostro professore\n");

    scrittore.append("Insegno anche Sistemi e Reti");

    scrittore.close();
} catch (IOException e) {
    e.printStackTrace();
}

Dopo l'esecuzione, prova.txt contiene tre righe. Passo per passo:

  1. new FileWriter("prova.txt") apre il file in scrittura (e lo crea, se serve);
  2. write(...) scrive il testo; \n significa "vai a capo";
  3. append(...) aggiunge altro testo in coda;
  4. close() chiude il file.

I metodi principali

MetodoCosa fa
write(String s)Scrive una stringa nel file. Se il file esiste già, ne sovrascrive il contenuto.
append(String s)Aggiunge testo alla fine del file, senza cancellare quello precedente.
close()Chiude il file e libera le risorse. Sempre obbligatorio!
Sovrascrivere o aggiungere? Dipende da come apri il file La slide dice che write() sovrascrive e append() aggiunge. Il dettaglio da capire è quando avviene la cancellazione: nel momento in cui scrivi new FileWriter("prova.txt") il vecchio contenuto viene svuotato subito, e da lì in poi tutto ciò che scrivi (sia con write sia con append) viene messo di seguito. Quindi, dentro uno stesso FileWriter, due write di fila si accodano benissimo, come nell'esempio sopra.
Per non perdere il contenuto già presente quando riapri il file (per esempio la volta dopo che esegui il programma) si passa true come secondo argomento: new FileWriter("prova.txt", true) è la modalità append. (Chiarimento aggiunto alle slide.) 
new FileWriter("diario.txt");          // svuota diario.txt e ricomincia da zero
new FileWriter("diario.txt", true);    // mantiene il contenuto e scrive in fondo

Perché close() è obbligatorio

Per velocità Java non scrive subito ogni carattere sul disco: li tiene in un buffer (una piccola memoria d'appoggio) e li "versa" nel file in blocco. close() svuota il buffer e libera il file. Se te ne dimentichi, il file può restare vuoto o incompleto, e su alcuni sistemi risulta ancora "occupato" e non si può eliminare.

Versione moderna: try-with-resourcesDichiarando il FileWriter tra parentesi dopo try, Java chiama close() da solo, anche se c'è un errore: 
try (FileWriter scrittore = new FileWriter("prova.txt")) {
    scrittore.write("Ciao!");
} catch (IOException e) {
    e.printStackTrace();
}   // close() chiamato automaticamente
Nelle slide si usa la forma con close() scritto a mano, ed è quella da conoscere per prima; poi puoi passare a questa, che è più sicura.

Leggere un file con FileReader

FileReader legge il contenuto di un file di testo un carattere alla volta. Il metodo read() restituisce ogni carattere come numero intero (il suo codice ASCII/Unicode), quindi per vederlo come lettera bisogna convertirlo in char.

import java.io.FileReader;
import java.io.FileNotFoundException;
import java.io.IOException;

try {
    FileReader lettore = new FileReader("prova.txt");
    int data = lettore.read();          // legge il primo carattere (codice ASCII)

    while (data != -1) {                // -1 = fine del file
        System.out.print((char) data);  // converte in carattere leggibile
        data = lettore.read();          // legge il carattere successivo
    }
    lettore.close();
} catch (FileNotFoundException e) {
    e.printStackTrace();
} catch (IOException e) {
    e.printStackTrace();
}

Il ciclo continua finché read() restituisce un valore diverso da -1, che indica la fine del file (EOF, End Of File).

  1. Crea il FileReader: apre il file in lettura.
  2. Cicla e stampa: legge e stampa finché read() non restituisce -1.
  3. Chiudi il lettore con close().

Perché read() restituisce un int e non un char

Un char può valere qualunque carattere, quindi non resterebbe nessun valore "libero" per dire "il file è finito". Un int ha molto più spazio: i caratteri usano i valori da 0 in su e il segnale di fine file è -1, che non può essere un carattere.

Se il file contieneread() restituisce, nell'ordine
Ciao67 (C), 105 (i), 97 (a), 111 (o), poi -1

Senza la conversione (char) data, il programma stamperebbe i numeri 67 105 97 111 invece della parola.

Gli errori più comuni
  • Chiamare read() una volta sola per ciclo ma due volte nel corpo: salta un carattere sì e uno no. Si legge una volta prima del ciclo e una volta alla fine di ogni giro, come nell'esempio.
  • Dimenticare l'ultima data = lettore.read();: il ciclo non avanza mai e ristampa all'infinito la stessa lettera.
  • Leggere un file che non c'è: new FileReader(...) lancia FileNotFoundException (a differenza di FileWriter, che il file lo crea).

Eliminare un file con delete

Il metodo delete() della classe File rimuove un file dal disco. Restituisce true se l'eliminazione va a buon fine, false altrimenti.

File documento2 = new File("prova2.txt");

if (documento2.exists()) {
    if (documento2.delete()) {
        System.out.println("File eliminato!");
    } else {
        System.out.println("Errore nell'eliminazione");
    }
} else {
    System.out.println("Il file non esiste");
}
Verifica prima

Usa sempre exists() prima di chiamare delete().

Controlla il risultato

delete() restituisce un booleano: controllalo per confermare l'operazione.

File aperto?

Un file aperto da un altro programma non può essere eliminato.

L'eliminazione è permanenteI file eliminati con delete() non vanno nel cestino: spariscono subito e non si recuperano. Fai molta attenzione al nome del file che passi a new File(...).

Due note in più rispetto alle slide: se hai ancora aperto il file nel tuo stesso programma (hai dimenticato close()), delete() può restituire false; e se il percorso è una cartella, delete() funziona solo se è vuota.

Gestione delle eccezioni: try-catch

Le operazioni sui file sono rischiose: il file potrebbe non esistere, i permessi potrebbero essere insufficienti, il disco potrebbe essere pieno. Java obbliga a gestire questi errori: se non lo fai, il programma non compila. Lo si fa con il blocco try-catch.

Blocco try

Contiene il codice "rischioso" che potrebbe generare un errore (apertura del file, lettura, scrittura).

Blocco catch

Cattura l'eccezione, se si verifica, e permette di gestirla senza far crashare il programma.

try {
    // codice rischioso
    FileWriter scrittore = new FileWriter("prova.txt");
    scrittore.write("Ciao!");
    scrittore.close();
} catch (IOException e) {
    e.printStackTrace();   // stampa l'errore completo su console
}

printStackTrace() stampa in console il percorso completo dell'errore, dalla causa fino al punto del programma in cui si è verificato: è lo strumento principale per capire cosa è andato storto.

Come funziona, in ordine

  1. Java esegue le righe del try una dopo l'altra.
  2. Se va tutto bene, il catch viene saltato.
  3. Se una riga fallisce, le righe successive del try non vengono eseguite e il programma salta subito al catch giusto.
  4. Terminato il catch, il programma continua normalmente dopo il blocco.

Eccezioni diverse: FileNotFoundException e IOException

Nell'esempio di FileReader ci sono due catch. Le due eccezioni sono parenti: FileNotFoundException (file non trovato) è un caso particolare di IOException (qualunque problema di input/output). Per questo, con più catch, va messo prima il più specifico e poi quello generale:

} catch (FileNotFoundException e) {   // prima il caso particolare
    System.out.println("Il file non esiste");
} catch (IOException e) {             // poi il caso generale
    System.out.println("Problema nella lettura");
}
L'ordine contaSe scrivi catch (IOException e) prima di catch (FileNotFoundException e), il codice non compila: il primo catch prenderebbe già tutto e il secondo non verrebbe mai raggiunto.
Cosa metto nel catch?Nelle slide c'è sempre e.printStackTrace(), perfetto per studiare e fare prove. In un programma "vero" nel catch si dà di solito un messaggio comprensibile all'utente (System.out.println("Impossibile aprire il file")). Il catch vuoto (catch (IOException e) { }) è da evitare: l'errore sparirebbe senza che nessuno se ne accorga.

Esercizi

01Quale metodo uso? facile

Per ogni richiesta scrivi classe e metodo: a) sapere se voti.txt è presente; b) aggiungere una riga in fondo a un file; c) leggere un carattere; d) scoprire in quale cartella Java sta cercando voti.txt; e) cancellare il file.

Soluzione

a) File → exists(). b) FileWriter → append() (con new FileWriter(nome, true) se il file ha già del contenuto da non perdere). c) FileReader → read(). d) File → getAbsolutePath(). e) File → delete().

02Cosa c'è nel file? facile
FileWriter f = new FileWriter("a.txt");
f.write("Uno\n");
f.write("Due\n");
f.append("Tre");
f.close();

Cosa contiene a.txt dopo l'esecuzione? E se prima del codice a.txt conteneva già "Ciao"?

Soluzione

Il file contiene tre righe: Uno, Due, Tre (l'ultima senza \n, quindi senza "a capo" finale).

Se conteneva già "Ciao", il risultato è lo stesso: new FileWriter("a.txt") senza true svuota il file all'apertura, quindi "Ciao" scompare. Per conservarlo bisognava scrivere new FileWriter("a.txt", true).

03Trova gli errori medio
FileReader lettore = new FileReader("testo.txt");
int data = lettore.read();
while (data != -1) {
    System.out.print((char) data);
}
lettore.close();

Il programma ha almeno due problemi. Quali? Come si correggono?

Soluzione

1) Dentro il while manca data = lettore.read();: la variabile non cambia mai, quindi il ciclo stampa all'infinito il primo carattere.

2) Manca il try-catch: new FileReader e read() possono lanciare eccezioni (FileNotFoundException, IOException) e Java non compila se non vengono gestite.

try {
    FileReader lettore = new FileReader("testo.txt");
    int data = lettore.read();
    while (data != -1) {
        System.out.print((char) data);
        data = lettore.read();
    }
    lettore.close();
} catch (FileNotFoundException e) {
    e.printStackTrace();
} catch (IOException e) {
    e.printStackTrace();
}
04Cancella solo se c'è medio

Scrivi un programma che elimina il file vecchio.txt e stampa uno di questi tre messaggi: "File eliminato!", "Errore nell'eliminazione", "Il file non esiste".

Soluzione
import java.io.File;

public class Main {
    public static void main(String[] args) {
        File f = new File("vecchio.txt");

        if (f.exists()) {
            if (f.delete()) {
                System.out.println("File eliminato!");
            } else {
                System.out.println("Errore nell'eliminazione");
            }
        } else {
            System.out.println("Il file non esiste");
        }
    }
}

Qui non serve try-catch: i metodi della classe File usati (exists, delete) non lanciano eccezioni controllate, ma restituiscono true/false. Le eccezioni da gestire arrivano da FileWriter e FileReader.

05Scrivi e rileggi completo

Scrivi un programma con tre passi:

  1. scrive nel file saluto.txt le due righe "Ciao mondo" e "Sto imparando Java";
  2. aggiunge in fondo, senza cancellare, la riga "Fine";
  3. rilegge il file e lo stampa a schermo.

Prima di scrivere, stampa il percorso assoluto del file.

Soluzione
import java.io.File;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class Main {
    public static void main(String[] args) {
        File f = new File("saluto.txt");
        System.out.println("Percorso: " + f.getAbsolutePath());

        try {
            // 1) scrittura (svuota e ricomincia)
            FileWriter scrittore = new FileWriter(f);
            scrittore.write("Ciao mondo\n");
            scrittore.write("Sto imparando Java\n");
            scrittore.close();

            // 2) riapro in modalità append: true = non cancellare
            FileWriter aggiunta = new FileWriter(f, true);
            aggiunta.append("Fine\n");
            aggiunta.close();

            // 3) lettura carattere per carattere
            FileReader lettore = new FileReader(f);
            int data = lettore.read();
            while (data != -1) {
                System.out.print((char) data);
                data = lettore.read();
            }
            lettore.close();
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

Output (dopo la riga del percorso):

Ciao mondo
Sto imparando Java
Fine
  • Basta un solo catch (IOException e): FileNotFoundException ne è un caso particolare, quindi è già coperto.
  • Il secondo FileWriter usa true: senza, "Fine" cancellerebbe le prime due righe.
  • Il costruttore accetta direttamente un oggetto File (new FileWriter(f)), oltre al nome come stringa.
  • Ogni file aperto viene chiuso con close() prima di aprirne un altro.
