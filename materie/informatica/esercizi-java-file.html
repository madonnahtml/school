Esercizi: gestione dei file

Consegne ed esercizi per allenarti su tutto il capitolo Java: gestione dei file. Ogni soluzione spiega il ragionamento, mostra il codice completo, l'output vero del programma e, quando serve, il contenuto vero del file creato.

Come usare questa paginaLeggi la consegna, prova a scrivere il programma da solo (su carta o al computer) e solo dopo apri la soluzione spiegata. Gli esercizi vanno dal più facile al più difficile; l'ultimo li mette insieme tutti. Ogni programma è stato compilato ed eseguito in una cartella di prova: l'output e il contenuto dei file che vedi sono quelli veri.

La classe File e i percorsi

Ripasso lampoUn oggetto File è solo un indirizzo: new File("prova.txt") non crea niente sul disco. Un percorso relativo ("prova.txt") viene cercato nella cartella da cui parte il programma; uno assoluto parte dalla radice del disco. Su Windows la \ dentro una stringa va raddoppiata. Teoria: La classe File.
01Dove sta cercando Java? facile

Consegna. Marco ha creato il file impostazioni.txt sul Desktop, ma il suo programma (che usa new File("impostazioni.txt")) continua a dire che il file non c'è. Scrivi un programma che:

  • se impostazioni.txt esiste, stampa Trovato: impostazioni.txt;
  • altrimenti stampa che non lo trova e dove lo ha cercato, cioè il percorso completo.

Poi spiega a Marco perché il suo file "non si trova".

Output atteso quando il file non c'è (il percorso è un esempio: sul tuo computer sarà diverso):

Non trovo impostazioni.txt
L'ho cercato qui: C:\Users\Marco\IdeaProjects\Gioco\impostazioni.txt
Soluzione spiegata

Ragionamento

  1. Creo l'oggetto File con il percorso relativo "impostazioni.txt": è solo un indirizzo, il file non viene creato né aperto.
  2. Con exists() chiedo se a quell'indirizzo c'è davvero qualcosa. Restituisce un boolean, quindi lo metto direttamente nell'if.
  3. Se non c'è, getPath() mi ridà il nome come l'ho scritto, mentre getAbsolutePath() ci mette davanti la cartella da cui sta girando il programma: è proprio il posto in cui Java ha cercato.

Codice

import java.io.File;

public class DoveCerca {
    public static void main(String[] args) {
        File impostazioni = new File("impostazioni.txt");

        if (impostazioni.exists()) {
            System.out.println("Trovato: " + impostazioni.getPath());
        } else {
            System.out.println("Non trovo " + impostazioni.getPath());
            System.out.println("L'ho cercato qui: " + impostazioni.getAbsolutePath());
        }
    }
}

Perché il file di Marco "non c'è"

Un percorso relativo viene cercato nella cartella del progetto (quella da cui parte il programma), non sul Desktop e nemmeno nella cartella src dove sta il codice. L'output glielo dice chiaramente: Java ha cercato in ...\IdeaProjects\Gioco\. Le soluzioni sono due: spostare il file in quella cartella, oppure scrivere nel programma il percorso assoluto del Desktop.

Da ricordare

  • Quando un file "non si trova", la prima cosa da fare è stampare getAbsolutePath(): dice dove Java sta guardando davvero.
  • Il percorso stampato dipende dal computer e dalla cartella da cui lanci il programma: per questo qui l'output è un esempio e non quello di una esecuzione vera.
02Trova l'errore: il percorso di Windows medio

Consegna. Questo programma vuole controllare un file sul Desktop di Windows, ma non compila. Trova l'errore, spiega il messaggio del compilatore e scrivi due correzioni diverse.

import java.io.File;

public class PercorsoWindows {
    public static void main(String[] args) {
        File voti = new File("C:\Users\Mario\Desktop\voti.txt");
        System.out.println(voti.exists());
    }
}

Domanda bonus. Questa riga invece compila senza errori. Cosa stampa, e perché è comunque sbagliata se volevi il file totali.txt nella cartella nuovi?

System.out.println("C:\nuovi\totali.txt");
Soluzione spiegata

L'errore

riga 5: error: illegal escape character

Dentro una stringa Java la barra rovesciata \ è un carattere speciale: insieme alla lettera che la segue forma una sequenza di escape (\n = a capo, \t = tabulazione, \" = virgolette…). \U non esiste, quindi il compilatore protesta: "illegal escape character" significa proprio "carattere di escape non valido".

Ragionamento per correggere

  1. Se voglio una \ vera nel testo, devo scriverla doppia: \\ diventa una sola barra.
  2. In alternativa uso la barra normale /, che Java accetta come separatore anche su Windows e non ha significati speciali.
File voti = new File("C:\\Users\\Mario\\Desktop\\voti.txt");   // correzione 1: barre doppie
File voti = new File("C:/Users/Mario/Desktop/voti.txt");       // correzione 2: barre normali

Bonus: cosa stampa

C:
uovi	otali.txt

Qui il compilatore non si accorge di nulla, perché \n e \t sono escape validi: \n va a capo e si "mangia" la n di nuovi, \t mette una tabulazione e si mangia la t di totali. Il percorso che arriva a Java è un'altra cosa, e il file non verrebbe mai trovato. È un errore più subdolo del primo, proprio perché compila.

Regola praticaNei percorsi dentro il codice usa sempre / oppure \\. Mai una \ da sola.

Verificare se un file esiste

Ripasso lampoexists() restituisce true se a quel percorso c'è un file (o una cartella), false altrimenti. Si usa prima di operare sul file, per decidere cosa fare. Teoria: Verificare se un file esiste.
03La lista di controllo facile

Consegna. Un programma di registro ha bisogno di quattro file: voti.txt, assenze.txt, orario.txt e note.txt. Metti i nomi in un array di String e, per ognuno, stampa [OK] se il file esiste o [MANCA] se non c'è. Alla fine stampa Tutto pronto! oppure quanti file mancano.

Output atteso, nella cartella in cui ci sono solo voti.txt e orario.txt:

[OK]    voti.txt
[MANCA] assenze.txt
[OK]    orario.txt
[MANCA] note.txt
File mancanti: 2 su 4
Soluzione spiegata

Ragionamento

  1. I nomi sono tanti e devo fare la stessa cosa per ognuno: li metto in un array e uso un foreach (mi serve solo il valore, non la posizione).
  2. A ogni giro creo un oggetto File con quel nome e chiedo exists().
  3. Per sapere alla fine se manca qualcosa uso un contatore dichiarato prima del ciclo, che aumento nel ramo else.

Codice

import java.io.File;

public class ListaControllo {
    public static void main(String[] args) {
        String[] necessari = {"voti.txt", "assenze.txt", "orario.txt", "note.txt"};

        int mancanti = 0;
        for (String nome : necessari) {
            File f = new File(nome);
            if (f.exists()) {
                System.out.println("[OK]    " + nome);
            } else {
                System.out.println("[MANCA] " + nome);
                mancanti++;
            }
        }

        if (mancanti == 0) {
            System.out.println("Tutto pronto!");
        } else {
            System.out.println("File mancanti: " + mancanti + " su " + necessari.length);
        }
    }
}

Da notare

  • Non serve nessun try-catch: new File(...) ed exists() non lanciano eccezioni, rispondono semplicemente true o false.
  • Creare 4 oggetti File non crea 4 file: dopo l'esecuzione assenze.txt e note.txt continuano a non esistere.
  • Gli spazi dopo [OK] servono solo ad allineare i nomi in colonna.
04Il primo nome libero medio

Consegna. Un programma salva una copia dei dati ogni giorno in file chiamati backup1.txt, backup2.txt, backup3.txt… e non deve mai sovrascrivere un backup vecchio. Scrivi il metodo

static String primoNomeLibero(String base)

che restituisce il primo nome della forma base + numero + .txt che non esiste ancora. Provalo nella cartella in cui ci sono già backup1.txt, backup2.txt e backup3.txt (e nessun file foto).

Output atteso:

Prossimo backup: backup4.txt
Prossima foto: foto1.txt
Soluzione spiegata

Ragionamento

  1. Non so in anticipo quanti backup ci sono, quindi non posso usare un for con un numero fisso di giri: uso un while che continua finché il nome è occupato.
  2. Parto da n = 1 e costruisco il nome con la concatenazione: "backup" + 1 + ".txt" diventa "backup1.txt" (c'è una stringa all'inizio, quindi il + unisce).
  3. A ogni giro aumento n e creo un nuovo oggetto File: quello vecchio indica ancora il nome precedente.
  4. Quando exists() dà false il ciclo finisce e f indica proprio il primo nome libero: restituisco f.getName().

Codice

import java.io.File;

public class NomeLibero {

    static String primoNomeLibero(String base) {
        int n = 1;
        File f = new File(base + n + ".txt");
        while (f.exists()) {
            n++;
            f = new File(base + n + ".txt");
        }
        return f.getName();
    }

    public static void main(String[] args) {
        System.out.println("Prossimo backup: " + primoNomeLibero("backup"));
        System.out.println("Prossima foto: " + primoNomeLibero("foto"));
    }
}

Prova a mano

Con "backup": backup1.txt esiste → n = 2; backup2.txt esiste → n = 3; backup3.txt esiste → n = 4; backup4.txt non esiste → esco. Con "foto" il primo controllo dà già false: il ciclo non gira neanche una volta e restituisce foto1.txt.

Errori da evitare

  • Dimenticare f = new File(...) dentro il ciclo: f indicherebbe sempre backup1.txt, che esiste, e il ciclo non finirebbe più.
  • Pensare che il metodo crei il file: restituisce solo il nome. Il file verrà creato da un FileWriter, quando ci si scrive.

Informazioni sul file: getPath, getAbsolutePath, isFile

Ripasso lampogetPath() restituisce il percorso così come l'hai scritto, getAbsolutePath() quello completo dalla radice del disco, getName() solo il nome. isFile() è true solo se il percorso punta a un file vero (non a una cartella). Teoria: Informazioni sul file.
05File, cartella o niente? medio

Consegna. Nella cartella del programma c'è il file voti.txt, mentre pagelle.txt non esiste. Il percorso "." (un punto) indica la cartella corrente, cioè proprio la cartella del programma.

1) Senza eseguirlo, scrivi cosa stampa questo frammento.

File[] elenco = {new File("voti.txt"), new File("pagelle.txt"), new File(".")};
for (File f : elenco) {
    System.out.println(f.getPath() + " -> esiste: " + f.exists() + ", file: " + f.isFile());
}

2) Guardando le risposte di isFile(), si può capire se pagelle.txt è una cartella? Scrivi un metodo static String tipo(File f) che restituisca "file", "cartella" oppure "non esiste".

Soluzione spiegata

1 · Output

voti.txt -> esiste: true, file: true
pagelle.txt -> esiste: false, file: false
. -> esiste: true, file: false

Riga per riga

  1. voti.txt c'è ed è un file normale: true e true.
  2. pagelle.txt non c'è: exists() è false e anche isFile() è false, perché non si può essere un file se non si esiste. Nota che l'oggetto File è stato creato senza problemi: è solo un indirizzo.
  3. . esiste (è la cartella in cui gira il programma) ma non è un file: true e false.

getPath() stampa esattamente quello che c'è tra le virgolette, anche il punto.

2 · Ragionamento

No: isFile() dà false sia per pagelle.txt (che non esiste) sia per . (che è una cartella). Da solo non basta, va combinato con exists():

  1. Se il percorso non esiste → "non esiste". Lo controllo per primo.
  2. Se esiste ed è un file → "file".
  3. Se esiste ma non è un file, l'unica possibilità rimasta è che sia una "cartella".

Codice

import java.io.File;

public class TipoFile {

    static String tipo(File f) {
        if (!f.exists()) {
            return "non esiste";
        }
        if (f.isFile()) {
            return "file";
        }
        return "cartella";
    }

    public static void main(String[] args) {
        File[] elenco = {new File("voti.txt"), new File("pagelle.txt"), new File(".")};
        for (File f : elenco) {
            System.out.println(f.getPath() + ": " + tipo(f));
        }
    }
}

Output

voti.txt: file
pagelle.txt: non esiste
.: cartella

Da notare

  • Il ! davanti a f.exists() significa "non": l'if entra quando il file non esiste.
  • Dopo ogni return il metodo finisce, per questo non servono gli else.
  • La classe File ha anche isDirectory(), che risponde direttamente "è una cartella?". Con exists() e isFile(), però, si arriva allo stesso risultato.
  • File[] è un array di oggetti, come un array di String: ogni casella contiene un oggetto File.

Scrivere in un file con FileWriter

Ripasso lamponew FileWriter("f.txt") apre il file in scrittura, lo crea se non c'è e lo svuota se c'era. new FileWriter("f.txt", true) invece mantiene il contenuto e scrive in fondo (modalità append). write e append mettono il testo di seguito; close() è obbligatorio. Teoria: Scrivere in un file con FileWriter.
06La lista della spesa facile

Consegna. Dato l'array String[] prodotti = {"latte", "pane", "mele", "pasta"}; scrivi nel file spesa.txt un titolo e poi i prodotti numerati, uno per riga. A schermo stampa solo un messaggio di conferma. Se la scrittura fallisce, stampa un messaggio chiaro.

Output atteso:

Salvati 4 prodotti in spesa.txt

Contenuto atteso di spesa.txt:

LISTA DELLA SPESA
1. latte
2. pane
3. mele
4. pasta
Soluzione spiegata

Ragionamento

  1. Per scrivere in un file serve un FileWriter. Se spesa.txt non esiste, lo crea lui.
  2. write non va a capo da solo (non è un println): alla fine di ogni riga devo aggiungere io "\n".
  3. Per numerare i prodotti da 1 mi serve l'indice, quindi uso il for classico e scrivo (i + 1).
  4. Finito il ciclo, close(): solo così il testo arriva davvero sul disco.
  5. Il costruttore e i metodi di FileWriter possono lanciare IOException: Java mi obbliga a metterli in un try-catch.

Codice

import java.io.FileWriter;
import java.io.IOException;

public class Spesa {
    public static void main(String[] args) {
        String[] prodotti = {"latte", "pane", "mele", "pasta"};

        try {
            FileWriter scrittore = new FileWriter("spesa.txt");
            scrittore.write("LISTA DELLA SPESA\n");
            for (int i = 0; i < prodotti.length; i++) {
                scrittore.write((i + 1) + ". " + prodotti[i] + "\n");
            }
            scrittore.close();
            System.out.println("Salvati " + prodotti.length + " prodotti in spesa.txt");
        } catch (IOException e) {
            System.out.println("Impossibile scrivere spesa.txt");
        }
    }
}

Errori da evitare

  • Mettere new FileWriter(...) dentro il ciclo: a ogni giro il file verrebbe riaperto e svuotato, e alla fine conterrebbe solo 4. pasta.
  • Mettere close() dentro il ciclo: al secondo giro si scriverebbe su un file già chiuso e write lancerebbe una IOException ("Stream closed").
  • Scrivere (i + 1) senza parentesi: i + 1 + ". " qui funzionerebbe (prima somma, poi unisce), ma l'abitudine di usare le parentesi evita sorprese.
07Cosa contiene log.txt? medio

Consegna. Prima dell'esecuzione il file log.txt contiene una sola riga: zero. Il codice (dentro un try-catch) apre il file tre volte, in modi diversi. Scrivi cosa contiene log.txt alla fine e spiega il ruolo di true, write e append.

FileWriter a = new FileWriter("log.txt", true);
a.write("uno\n");
a.close();

FileWriter b = new FileWriter("log.txt");
b.write("due\n");
b.append("tre\n");
b.close();

FileWriter c = new FileWriter("log.txt", true);
c.append("quattro\n");
c.write("cinque\n");
c.close();
Soluzione spiegata

Ragionamento: il file dopo ogni blocco

Il trucco è guardare come viene aperto il file, non se si usa write o append. La cancellazione avviene solo nel momento in cui si apre un FileWriter senza true.

BloccoCome si apreCosa succedeContenuto dopo
prima——zero
a("log.txt", true)tiene il contenuto, scrive in fondozero, uno
b("log.txt")svuota subito, poi write e append si accodanodue, tre
c("log.txt", true)tiene il contenuto; anche write scrive in fondodue, tre, quattro, cinque

Contenuto finale di log.txt

due
tre
quattro
cinque

Perché

  • Nel blocco b il file viene svuotato all'apertura: "zero" e "uno" spariscono anche se dopo si usa append. append non può salvare quello che è già stato cancellato.
  • Nel blocco c il file è aperto con true: anche write aggiunge in fondo e non cancella niente.
  • Dentro uno stesso FileWriter aperto, write e append fanno la stessa cosa: mettono il testo dopo quello scritto prima.
Da ricordareVuoi ricominciare da zero? new FileWriter(nome). Vuoi aggiungere senza perdere niente (un diario, un registro, un log)? new FileWriter(nome, true).
08Trova l'errore: due salvataggi che non funzionano difficile

Consegna. Questi due frammenti compilano e partono senza errori, ma il file che producono è sbagliato. Per ognuno spiega cosa succede e correggilo.

A · Il programma dice di aver salvato la classifica, ma il controllo subito dopo trova il file vuoto.

FileWriter w = new FileWriter("classifica.txt");
w.write("Anna 120\n");
w.write("Bruno 95\n");
System.out.println("Classifica salvata!");

// controllo: quanti caratteri ci sono davvero nel file?
FileReader r = new FileReader("classifica.txt");
int quanti = 0;
while (r.read() != -1) {
    quanti++;
}
r.close();
System.out.println("Caratteri nel file: " + quanti);

Output:

Classifica salvata!
Caratteri nel file: 0

B · Si volevano salvare i punteggi 72, 105 e 33, uno per riga.

int[] punti = {72, 105, 33};
FileWriter w = new FileWriter("punti.txt");
for (int p : punti) {
    w.write(p);
}
w.close();

Contenuto di punti.txt:

Hi!
Soluzione spiegata

A · manca close()

Il FileWriter non viene mai chiuso. Per essere veloce, Java non scrive subito ogni carattere sul disco: lo tiene in un buffer, una piccola memoria d'appoggio, e lo versa nel file tutto insieme. Il buffer viene svuotato nel file quando si chiama close(). Qui nessuno lo chiama: il file è stato creato (lo fa il costruttore), ma è rimasto vuoto, e il FileReader conta 0 caratteri. Anche quando il programma finisce, il testo rimasto nel buffer va perso.

Correzione: aggiungere w.close(); subito dopo l'ultima write, prima di stampare "Classifica salvata!" e prima di rileggere il file. Con la correzione il controllo stampa Caratteri nel file: 18 (9 caratteri per riga, contando l'a capo).

B · write con un int

Il ragionamento da fare è: che tipo sto passando a write?

  1. p è un int, non una String.
  2. write(int) esiste, ma non scrive il numero: scrive il carattere che ha quel codice. È il contrario di (char) data che si usa con read().
  3. 72 è il codice di H, 105 di i, 33 di !: nel file finisce la parola Hi!, tutta attaccata perché nessuno ha scritto "\n".

Correzione: trasformare il numero in testo prima di scriverlo, con Integer.toString(p) (oppure "" + p), e aggiungere l'a capo:

int[] punti = {72, 105, 33};
FileWriter w = new FileWriter("punti.txt");
for (int p : punti) {
    w.write(Integer.toString(p) + "\n");
}
w.close();

Contenuto di punti.txt dopo la correzione:

72
105
33

Da ricordare

  • Niente close(), niente dati: il file può restare vuoto o a metà.
  • A write passa sempre una String. Un int viene preso come codice di un carattere.

Leggere un file con FileReader

Ripasso lamporead() legge un carattere alla volta e lo restituisce come int (il suo codice); a fine file restituisce -1. Per vederlo come lettera serve il cast (char). Schema: leggo prima del ciclo, while (data != -1), uso il carattere, leggo il successivo alla fine del giro. Teoria: Leggere un file con FileReader.
09Caratteri, righe e vocali facile

Consegna. Il file poesia.txt contiene la poesia più corta di Ungaretti, su due righe (ognuna termina con un a capo):

M'illumino
d'immenso

Leggi il file con FileReader e conta quanti caratteri contiene in tutto, quante righe e quante vocali minuscole. Gestisci il caso in cui il file non esiste.

Output atteso:

Caratteri: 21
Righe: 2
Vocali: 7
Soluzione spiegata

Ragionamento

  1. Lo schema di lettura è sempre lo stesso: read() prima del ciclo, while (data != -1), nuovo read() come ultima istruzione del giro.
  2. A ogni giro converto data in char e lo salvo in c: così i confronti si leggono meglio (c == 'a' invece di data == 97).
  3. Tre contatori: caratteri aumenta a ogni giro; righe solo quando trovo un a capo '\n'; vocali quando il carattere è una delle cinque vocali.
  4. Due catch: prima FileNotFoundException (il caso particolare: il file non c'è), poi IOException (qualunque altro problema).

Codice

import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.IOException;

public class Contatore {
    public static void main(String[] args) {
        int caratteri = 0;
        int righe = 0;
        int vocali = 0;

        try {
            FileReader lettore = new FileReader("poesia.txt");
            int data = lettore.read();
            while (data != -1) {
                char c = (char) data;
                caratteri++;
                if (c == '\n') {
                    righe++;
                }
                if (c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u') {
                    vocali++;
                }
                data = lettore.read();
            }
            lettore.close();

            System.out.println("Caratteri: " + caratteri);
            System.out.println("Righe: " + righe);
            System.out.println("Vocali: " + vocali);
        } catch (FileNotFoundException e) {
            System.out.println("Il file poesia.txt non esiste");
        } catch (IOException e) {
            System.out.println("Errore durante la lettura");
        }
    }
}

Controlliamo i conti

  • Caratteri: M'illumino sono 10 caratteri (l'apostrofo conta!) più l'a capo = 11; d'immenso sono 9 più l'a capo = 10. Totale 21: anche '\n' è un carattere del file.
  • Righe: due a capo, quindi 2.
  • Vocali: i, u, i, o in "illumino" e i, e, o in "immenso": 7.

Da notare

I caratteri si confrontano con == e gli apici singoli: 'a' è un char, "a" sarebbe una String. La M maiuscola non è contata come vocale perché è una consonante, ma anche una A maiuscola non verrebbe contata: 'A' e 'a' sono caratteri diversi.

10Il ciclo che salta le lettere medio

Consegna. Il file parola.txt contiene PIZZA! (6 caratteri, senza a capo). Uno studente ha scritto questo ciclo "più corto" per stamparlo. Cosa stampa davvero? Perché? Correggilo.

FileReader r = new FileReader("parola.txt");
while (r.read() != -1) {
    System.out.print((char) r.read());
}
r.close();
Soluzione spiegata

Output

IZ!

Ragionamento: contare le chiamate a read()

Ogni chiamata a read() consuma un carattere: la volta dopo restituisce il successivo. Qui in ogni giro ci sono due chiamate: una nella condizione del while (il carattere viene confrontato con -1 e poi buttato via) e una nella stampa.

Giroread() nella condizioneread() nella stampaStampato
1P (buttata)II
2Z (buttata)ZZ
3A (buttata)!!
—-1 → esce

Si stampa un carattere sì e uno no, a partire dal secondo: IZ!. Con un numero dispari di caratteri andrebbe anche peggio: all'ultimo giro la stampa riceverebbe -1 e (char) -1 stamperebbe un simbolo strano.

Correzione

Il carattere letto va salvato in una variabile, così lo si può sia controllare sia stampare con una sola lettura:

FileReader r = new FileReader("parola.txt");
int data = r.read();
while (data != -1) {

11Leggere riga per riga difficile

Consegna. Il file nomi.txt contiene un nome per riga. Attenzione: l'ultima riga non termina con un a capo.

Anna
Bruno
Carlotta
Dario

FileReader legge solo un carattere alla volta, ma a noi servono le righe. Scrivi un metodo

static int leggiRighe(String nomeFile, String[] righe)

che mette ogni riga del file in una casella dell'array righe e restituisce quante righe ha letto. Nel main stampa i nomi numerati e il nome più lungo.

Output atteso:

1) Anna
2) Bruno
3) Carlotta
4) Dario
Righe lette: 4
Nome più lungo: Carlotta
Soluzione spiegata

Ragionamento

  1. Una riga è "tutti i caratteri fino al prossimo '\n'". Quindi tengo una String riga in cui accumulo i caratteri letti: riga = riga + c, come un accumulatore per le somme, ma con il testo.
  2. Quando leggo '\n' la riga è completa: la salvo nella casella righe[n], aumento n e riparto da una riga vuota "". L'a capo non va aggiunto alla riga.
  3. Quando read() restituisce -1 il ciclo finisce. Ma se l'ultima riga non ha l'a capo (come "Dario"), i suoi caratteri sono ancora in riga e nessuno li ha salvati: dopo il ciclo, se riga non è vuota, la salvo.
  4. Il metodo riceve l'array e lo riempie: l'array è passato per riferimento, quindi le modifiche si vedono nel main. Il valore restituito dice quante caselle sono state usate (le altre restano null).
  5. Il nome più lungo si trova come un massimo: parto da "" (lunghezza 0) e lo sostituisco quando trovo un nome con più caratteri.

Codice

import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.IOException;

public class RigaPerRiga {

    // legge il file e mette ogni riga in una casella di righe; restituisce quante righe ha letto
    static int leggiRighe(String nomeFile, String[] righe) {
        int n = 0;
        String riga = "";
        try {
            FileReader lettore = new FileReader(nomeFile);
            int data = lettore.read();
            while (data != -1) {
                char c = (char) data;
                if (c == '\n') {
                    righe[n] = riga;      // riga finita: la salvo
                    n++;
                    riga = "";            // e ne comincio una nuova
                } else if (c != '\r') {
                    riga = riga + c;      // aggiungo il carattere alla riga
                }
                data = lettore.read();
            }
            lettore.close();
            if (riga.length() > 0) {      // ultima riga senza a capo
                righe[n] = riga;
                n++;
            }
        } catch (FileNotFoundException e) {
            System.out.println("Non trovo " + nomeFile);
        } catch (IOException e) {
            System.out.println("Errore durante la lettura di " + nomeFile);
        }
        return n;
    }

    public static void main(String[] args) {
        String[] nomi = new String[100];
        int quanti = leggiRighe("nomi.txt", nomi);

        String piuLungo = "";
        for (int i = 0; i < quanti; i++) {
            System.out.println((i + 1) + ") " + nomi[i]);
            if (nomi[i].length() > piuLungo.length()) {
                piuLungo = nomi[i];
            }
        }
        System.out.println("Righe lette: " + quanti);
        System.out.println("Nome più lungo: " + piuLungo);
    }
}

Perché c'è quel '\r'

I file di testo creati con il Blocco note di Windows terminano ogni riga con due caratteri: '\r' e '\n'. Su Mac e Linux c'è solo '\n'. Ignorando '\r' il metodo funziona con entrambi; senza quel controllo, su Windows ogni nome avrebbe un carattere invisibile in fondo e "Anna" sarebbe lunga 5 invece di 4.

Errori da evitare

  • Dimenticare il controllo dopo il ciclo: si perderebbe "Dario" e si leggerebbero solo 3 righe.
  • Nel main ciclare fino a nomi.length (100) invece che fino a quanti: dalla casella 4 in poi ci sono null e nomi[i].length() lancerebbe una NullPointerException.
  • Usare riga = riga + data invece di riga + c: si attaccherebbero i codici dei caratteri ("6511011097" invece di "Anna").

13Spostare un file "a mano" difficile

Consegna. Java non ha (nel nostro capitolo) un comando per spostare un file, ma possiamo costruirlo: copiare il contenuto in un nuovo file e poi eliminare l'originale. Scrivi il metodo

static boolean sposta(String da, String a)

che sposta il file da nel file a e restituisce true se ci riesce. Regole di sicurezza:

  • se da non esiste, non fa niente;
  • se a esiste già, si ferma (non deve sovrascrivere niente);
  • l'originale va eliminato solo se la copia è riuscita.

Nel main chiama due volte sposta("bozza.txt", "tema.txt"). All'inizio c'è solo bozza.txt, con questo testo (che dopo lo spostamento dovrà ritrovarsi identico in tema.txt):

Tema di italiano
La mia estate al mare.

Output atteso:

Copiati 40 caratteri in tema.txt
bozza.txt eliminato
Primo tentativo: true
Non c'è niente da spostare: bozza.txt non esiste
Secondo tentativo: false
bozza.txt esiste? false
Soluzione spiegata

Ragionamento

  1. Controlli prima di tutto, con la classe File: exists() sull'origine (se non c'è, mi fermo) e sulla destinazione (se c'è, mi fermo per non cancellarla: new FileWriter la svuoterebbe).
  2. Copia: apro un FileReader sull'origine e un FileWriter sulla destinazione. Lo schema di lettura è il solito; per ogni carattere letto lo scrivo. Uso write((char) data): il cast rende chiaro che sto scrivendo un carattere (e dall'esercizio sui punteggi sappiamo che write con un numero scrive proprio il carattere con quel codice).
  3. Chiudo entrambi: senza close() sullo scrittore la copia resterebbe nel buffer, e senza close() sul lettore su alcuni sistemi l'originale risulterebbe "occupato" e non si potrebbe eliminare.
  4. Elimino solo dopo il try-catch: se qualcosa è andato storto, il catch fa return false e non si arriva mai al delete(). Così nel caso peggiore ho due copie, mai zero.
  5. Controllo il valore restituito da delete() per dire la verità all'utente.

Codice

import java.io.File;
import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class Sposta {

    static boolean sposta(String da, String a) {
        File origine = new File(da);
        File destinazione = new File(a);

        if (!origine.exists()) {
            System.out.println("Non c'è niente da spostare: " + da + " non esiste");
            return false;
        }
        if (destinazione.exists()) {
            System.out.println("Mi fermo: " + a + " esiste già e non voglio sovrascriverlo");
            return false;
        }

        try {
            // 1) copia carattere per carattere
            FileReader lettore = new FileReader(origine);
            FileWriter scrittore = new FileWriter(destinazione);
            int data = lettore.read();
            int copiati = 0;
            while (data != -1) {
                scrittore.write((char) data);
                copiati++;
                data = lettore.read();
            }
            lettore.close();
            scrittore.close();
            System.out.println("Copiati " + copiati + " caratteri in " + a);
        } catch (FileNotFoundException e) {
            System.out.println("File non trovato durante la copia");
            return false;
        } catch (IOException e) {
            System.out.println("Copia non riuscita: l'originale resta dov'è");
            return false;
        }

        // 2) solo se la copia è andata bene, elimino l'originale
        if (origine.delete()) {
            System.out.println(da + " eliminato");
            return true;
        } else {
            System.out.println("Copia fatta, ma non riesco a eliminare " + da);
            return false;
        }
    }

    public static void main(String[] args) {
        System.out.println("Primo tentativo: " + sposta("bozza.txt", "tema.txt"));
        System.out.println("Secondo tentativo: " + sposta("bozza.txt", "tema.txt"));
        System.out.println("bozza.txt esiste? " + new File("bozza.txt").exists());
    }
}

Come leggere l'output

  • Primo tentativo: la bozza esiste, il tema no. Copia 40 caratteri (16 + 1 a capo della prima riga, 22 + 1 della seconda), chiude, elimina: true.
  • Secondo tentativo: bozza.txt non esiste più, quindi il primo controllo ferma tutto: false.
  • Il main lo conferma: bozza.txt non esiste. E tema.txt contiene esattamente il testo mostrato nella consegna: il testo mostrato lì è proprio quello letto da tema.txt dopo l'esecuzione.

Errori da evitare

  • Eliminare prima di copiare, o dentro il try prima delle close(): se la copia fallisce a metà il testo è perso per sempre (delete() non usa il cestino).
  • Saltare il controllo sulla destinazione: new FileWriter("tema.txt") svuoterebbe un tema già scritto.

Gestione delle eccezioni: try-catch

Ripasso lampoLe operazioni di FileWriter e FileReader possono fallire e Java obbliga a gestirle con try-catch. Se una riga del try fallisce, le successive vengono saltate e si va al catch giusto. Con più catch va prima FileNotFoundException (caso particolare) e poi IOException (caso generale). Il try-with-resources chiude il file da solo. Teoria: Gestione delle eccezioni: try-catch.

    }

Soluzione spiegata

A · i catch sono nell'ordine sbagliato

riga 13: error: exception FileNotFoundException has already been caught

"has already been caught" significa "è già stata catturata". FileNotFoundException è un caso particolare di IOException: ogni "file non trovato" è anche un "errore di input/output". Il primo catch quindi prende già tutto, e il secondo non potrebbe mai essere raggiunto. Java considera codice irraggiungibile un errore.

Correzione: scambiare i due catch, prima il più specifico e poi il più generale.

} catch (FileNotFoundException e) {
    System.out.println("Il file non esiste");
} catch (IOException e) {
    System.out.println("Errore di lettura");
}

Un trucco per ricordarlo: è come un filtro con i buchi dal più piccolo al più grande. Se metti per primo il buco grande, passa tutto da lì.

B · manca il try-catch

riga 5: error: unreported exception IOException; must be caught or declared to be thrown

"unreported exception IOException; must be caught or declared to be thrown" vuol dire: "questa riga può lanciare una IOException e tu non l'hai gestita: devi catturarla (catch) oppure dichiarare che il metodo la lancia" (con throws, che vedrai nel capitolo Java: eccezioni). Il compilatore segnala la prima riga a rischio, ma anche write e close lo sono.

Correzione: mettere le tre righe in un try.

try {
    FileWriter w = new FileWriter("note.txt");
    w.write("Ricordati il compito\n");
    w.close();
} catch (IOException e) {
    System.out.println("Impossibile salvare le note");
}

(E aggiungere import java.io.IOException; in cima.)

16Due metodi sicuri con try-with-resources difficile

Consegna. Scrivi due metodi che non fanno mai fermare il programma e chiudono sempre il file, usando il try-with-resources:

  • static boolean salva(String nome, String testo): scrive testo nel file e restituisce true; se non ci riesce stampa il motivo e restituisce false;
  • static int contaCaratteri(String nome): restituisce quanti caratteri contiene il file, -1 se il file non esiste, -2 per un altro errore di lettura.

Provali anche con un file dentro una cartella che non esiste.

Output atteso (su Linux o Mac; su Windows il testo tra parentesi è in italiano, vedi sotto):

true
Non riesco a salvare: cartella-che-non-esiste/promemoria.txt (No such file or directory)
false
17
-1
Soluzione spiegata

Ragionamento

  1. Nel try-with-resources il FileWriter si dichiara tra parentesi subito dopo try. Quando il blocco finisce, in qualunque modo (normalmente, con un return o con un'eccezione), Java chiama close() da solo.
  2. Per questo posso scrivere return true; dentro il try senza preoccuparmi: il file viene chiuso comunque, e il testo arriva sul disco.
  3. Se il file non si può creare, new FileWriter lancia un'eccezione e si va nel catch, che stampa il motivo e restituisce false. Chi chiama il metodo decide cosa fare in base al boolean.
  4. In contaCaratteri i due tipi di errore danno due risposte diverse, quindi servono due catch: prima FileNotFoundException, poi IOException.

Codice

import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class SalvaSicuro {

    static boolean salva(String nome, String testo) {
        try (FileWriter w = new FileWriter(nome)) {
            w.write(testo);
            return true;
        } catch (IOException e) {
            System.out.println("Non riesco a salvare: " + e.getMessage());
            return false;
        }
    }

    static int contaCaratteri(String nome) {
        try (FileReader r = new FileReader(nome)) {
            int n = 0;
            while (r.read() != -1) {
                n++;
            }
            return n;
        } catch (FileNotFoundException e) {
            return -1;
        } catch (IOException e) {
            return -2;
        }
    }

    public static void main(String[] args) {
        System.out.println(salva("promemoria.txt", "Ripassare i file\n"));
        System.out.println(salva("cartella-che-non-esiste/promemoria.txt", "Ciao\n"));
        System.out.println(contaCaratteri("promemoria.txt"));
        System.out.println(contaCaratteri("sparito.txt"));
    }
}

Come leggere l'output

  • true: promemoria.txt è stato creato e chiuso automaticamente.
  • La cartella cartella-che-non-esiste non esiste e FileWriter crea i file, non le cartelle: lancia una FileNotFoundException (che è una IOException, quindi la prende l'unico catch). e.getMessage() restituisce la descrizione dell'errore: il percorso e, tra parentesi, il motivo dato dal sistema operativo ("No such file or directory" = file o cartella inesistente). Su un Windows in italiano tra parentesi leggeresti qualcosa come "Impossibile trovare il percorso specificato". Poi il metodo restituisce false.
  • 17: "Ripassare i file" sono 16 caratteri più l'a capo.
  • -1: sparito.txt non esiste.

Da notare

  • FileWriter può lanciare FileNotFoundException anche se "crea il file": succede quando non può crearlo (cartella inesistente, permessi mancanti).
  • Qui il messaggio nel catch è chiaro per l'utente, senza printStackTrace(), e il catch non è mai vuoto.
  • Confronta con la versione "classica": senza try-with-resources, per essere sicuri di chiudere il file anche in caso di errore servirebbe molto più codice.

Se il testo non è un numero ("otto"), parseInt lancia NumberFormatException: il try-catch è dentro il ciclo, così si salta solo quella riga, che viene segnalata e aggiunta a scarti.txt.

Passo 7 · Scrivere e rileggere la pagella

scriviPagella usa il try-with-resources: il FileWriter viene chiuso da solo, anche con il return true dentro il try. È aperto senza true, quindi ogni esecuzione riscrive la pagella da zero, ed è giusto così. media e posizioneMassimo lavorano solo sulle prime n caselle. Media: (7 + 5 + 8 + 9 + 7) / 5 = 36 / 5 = 7.2. Il voto migliore si cerca per posizione, così con lo stesso indice recupero anche la materia (array paralleli). Infine stampaFile rilegge pagella.txt: quello che vedi dopo la riga --- pagella.txt --- è il contenuto vero del file.

Codice completo

import java.io.File;
import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class RegistroFile {

    // ---------- 1. controllo: classe File ----------
    static boolean controlla(File f) {
        System.out.println("Registro: " + f.getName() + " (percorso " + f.getPath() + ")");
        if (!f.exists()) {
            System.out.println("  non esiste! L'ho cercato in " + f.getAbsolutePath());
            return false;
        }
        if (!f.isFile()) {
            System.out.println("  è una cartella, non un file!");
            return false;
        }
        System.out.println("  trovato");
        return true;
    }

    // ---------- 2. pulizia: delete ----------
    static void eliminaVecchio(File f) {
        if (f.exists()) {
            if (f.delete()) {
                System.out.println("Eliminato il vecchio " + f.getName());
            } else {
                System.out.println("Non riesco a eliminare " + f.getName());
            }
        }
    }

    // ---------- 3. aggiungere in fondo: FileWriter in modalità append ----------
    static void aggiungiRiga(File f, String riga) {
        try {
            FileWriter w = new FileWriter(f, true);
            w.write(riga + "\n");
            w.close();
        } catch (IOException e) {
            System.out.println("Impossibile scrivere in " + f.getName());
        }
    }

    // ---------- 4. leggere: FileReader carattere per carattere ----------
    // ogni riga è "materia;voto": separa le due parti e le mette negli array
    static int leggiRegistro(File f, String[] materie, String[] votiTesto) {
        int n = 0;
        String materia = "";
        String voto = "";
        boolean dopoPuntoEVirgola = false;
        try {
            FileReader r = new FileReader(f);
            int data = r.read();
            while (data != -1) {
                char c = (char) data;
                if (c == '\n') {                 // fine riga: salvo
                    materie[n] = materia;
                    votiTesto[n] = voto;
                    n++;
                    materia = "";
                    voto = "";
                    dopoPuntoEVirgola = false;
                } else if (c == ';') {           // da qui in poi è il voto
                    dopoPuntoEVirgola = true;
                } else if (c != '\r') {
                    if (dopoPuntoEVirgola) {
                        voto = voto + c;
                    } else {
                        materia = materia + c;
                    }
                }
                data = r.read();
            }
            r.close();
        } catch (FileNotFoundException e) {
            System.out.println("Il registro non esiste");
            return -1;
        } catch (IOException e) {
            System.out.println("Errore durante la lettura del registro");
            return -1;
        }
        return n;
    }

    // ---------- 5. calcoli ----------
    static double media(int[] voti, int n) {
        int somma = 0;
        for (int i = 0; i < n; i++) {
            somma += voti[i];
        }
        return (double) somma / n;
    }

    static int posizioneMassimo(int[] voti, int n) {
        int pos = 0;
        for (int i = 1; i < n; i++) {
            if (voti[i] > voti[pos]) {
                pos = i;
            }
        }
        return pos;
    }

    // ---------- 6. scrivere la pagella: try-with-resources ----------
    static boolean scriviPagella(File f, String[] materie, int[] voti, int n) {
        try (FileWriter w = new FileWriter(f)) {
            w.write("PAGELLA\n");
            for (int i = 0; i < n; i++) {
                w.write(materie[i] + ": " + voti[i] + "\n");
            }
            int max = posizioneMassimo(voti, n);
            w.append("Media: " + media(voti, n) + "\n");
            w.append("Voto migliore: " + voti[max] + " (" + materie[max] + ")\n");
            return true;
        } catch (IOException e) {
            System.out.println("Impossibile scrivere la pagella");
            return false;
        }
    }

    // ---------- 7. stampare un file a schermo ----------
    static void stampaFile(File f) {
        try (FileReader r = new FileReader(f)) {
            int data = r.read();
            while (data != -1) {
                System.out.print((char) data);
                data = r.read();
            }
        } catch (FileNotFoundException e) {
            System.out.println(f.getName() + " non esiste");
        } catch (IOException e) {
            System.out.println("Errore durante la lettura di " + f.getName());
        }
    }

    public static void main(String[] args) {
        File registro = new File("voti.txt");
        File scarti = new File("scarti.txt");
        File pagella = new File("pagella.txt");

        if (!controlla(registro)) {
            return;
        }
        eliminaVecchio(scarti);

        aggiungiRiga(registro, "Informatica;9");
        aggiungiRiga(registro, "Matematica;7");

        String[] materie = new String[50];
        String[] votiTesto = new String[50];
        int righe = leggiRegistro(registro, materie, votiTesto);
        if (righe == -1) {
            return;
        }
        System.out.println("Righe lette: " + righe);

        // conversione con parseInt: le righe sbagliate finiscono in scarti.txt
        String[] materieOk = new String[righe];
        int[] voti = new int[righe];
        int validi = 0;
        for (int i = 0; i < righe; i++) {
            try {
                voti[validi] = Integer.parseInt(votiTesto[i]);
                materieOk[validi] = materie[i];
                validi++;
            } catch (NumberFormatException e) {
                System.out.println("Voto non valido: " + materie[i] + ";" + votiTesto[i]);
                aggiungiRiga(scarti, materie[i] + ";" + votiTesto[i]);
            }
        }
        System.out.println("Voti validi: " + validi + ", scartati: " + (righe - validi));

        if (scriviPagella(pagella, materieOk, voti, validi)) {
            System.out.println("--- " + pagella.getName() + " ---");
            stampaFile(pagella);
        }
    }
}
