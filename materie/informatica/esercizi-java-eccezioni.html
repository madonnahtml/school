Esercizi: eccezioni

Consegne ed esercizi per allenarti su tutto il capitolo Java: eccezioni. Ogni soluzione spiega il ragionamento, mostra il codice completo e l'output vero del programma.

Come usare questa paginaLeggi la consegna, prova a risolverla da solo (su carta o al computer) e solo dopo apri la soluzione spiegata. Negli esercizi "cosa stampa?" scrivi l'output riga per riga prima di guardare: è proprio così che arrivano nelle verifiche. Gli esercizi vanno dal più facile al più difficile; l'ultimo li mette insieme tutti. Ogni programma è stato compilato ed eseguito: l'output che vedi è quello vero.

Cosa sono le eccezioni

Ripasso lampoUn'eccezione è un evento imprevisto durante l'esecuzione che interrompe il flusso normale del programma. Se nessuno la gestisce, il programma si ferma in quella riga e stampa il tipo di errore e il motivo. L'eccezione è un oggetto: ogni tipo di errore ha la sua classe (ArithmeticException, NumberFormatException…). Teoria: Cosa sono le eccezioni.
01Il programma che si ferma a metà facile

Consegna. Questo programma controlla i posti liberi nelle file di un teatro. Compila senza problemi, ma quando lo esegui qualcosa va storto.

public class Fermata {
    public static void main(String[] args) {
        int[] posti = {12, 7, 0};
        System.out.println("Inizio controllo");
        for (int i = 0; i <= posti.length; i++) {
            System.out.println("Fila " + i + ": " + posti[i] + " posti liberi");
        }
        System.out.println("Controllo finito");
    }
}
  1. Quali righe vengono stampate prima dell'errore?
  2. La scritta "Controllo finito" compare? Perché?
  3. Leggi il messaggio d'errore: qual è il tipo di eccezione e qual è il motivo?
  4. Correggi il programma.
Soluzione spiegata

Ragionamento

  1. L'array ha 3 elementi, quindi gli indici validi sono 0, 1 e 2.
  2. La condizione del ciclo è i <= posti.length, cioè i <= 3: il ciclo fa i giri con i = 0, 1, 2 e 3.
  3. I primi tre giri vanno bene e stampano le tre file. Al quarto giro Java prova a leggere posti[3], che non esiste: lancia un'ArrayIndexOutOfBoundsException.
  4. Nessuno la gestisce (non c'è un try-catch), quindi il programma si ferma in quella riga. Tutto quello che viene dopo non viene mai eseguito.

Output

Inizio controllo
Fila 0: 12 posti liberi
Fila 1: 7 posti liberi
Fila 2: 0 posti liberi
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
	at ...

(La riga at ... è l'inizio dello stack trace, che indica la riga del programma dove è nato l'errore: qui l'abbiamo accorciata.)

Le risposte

  1. Vengono stampate "Inizio controllo" e le tre file (0, 1, 2).
  2. "Controllo finito" non compare: l'eccezione ha interrotto il programma prima di arrivarci.
  3. Il messaggio si legge così: Exception in thread "main" = è successo un errore nel main; java.lang.ArrayIndexOutOfBoundsException = il tipo (la classe dell'eccezione); Index 3 out of bounds for length 3 = il motivo: "indice 3 fuori dai limiti per lunghezza 3".
  4. Correzione: i < posti.length. Con < l'ultimo giro è i = 2 e "Controllo finito" viene stampato.
Da ricordareUn'eccezione non gestita non "salta" una riga: ferma tutto il programma. Per questo si dice che interrompe il flusso normale. Qui però la soluzione giusta non è un try-catch: è correggere il ciclo, perché l'errore è nostro.
02Riconosci l'eccezione (o la sorpresa) medio

Consegna. Ognuno dei sei blocchi prova un'operazione. Se va bene stampa ok e il risultato; se fallisce stampa l'oggetto eccezione e. Per ogni blocco prevedi: va tutto bene oppure si verifica un'eccezione? E se sì, di quale classe? Attenzione: due blocchi nascondono una sorpresa.

try {
    int n = Integer.parseInt(" 7");
    System.out.println("1) ok: " + n);
} catch (Exception e) {
    System.out.println("1) " + e);
}

try {

    v[0] = 5;

} catch (Exception e) {

}

    System.out.println("3) ok: " + resto);
} catch (Exception e) {
    System.out.println("3) " + e);
}

    double d = 7.0 / 0;
    System.out.println("4) ok: " + d);
} catch (Exception e) {
    System.out.println("4) " + e);
}

try {
    int n = Integer.parseInt("3.5");
    System.out.println("5) ok: " + n);
} catch (Exception e) {
    System.out.println("5) " + e);
}

    double d = Double.parseDouble("3.5");
    System.out.println("6) ok: " + d);
} catch (Exception e) {
    System.out.println("6) " + e);
}
Soluzione spiegata

Output

1) java.lang.NumberFormatException: For input string: " 7"
2) java.lang.ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0
3) java.lang.ArithmeticException: / by zero
4) ok: Infinity
5) java.lang.NumberFormatException: For input string: "3.5"
6) ok: 3.5

Blocco per blocco

  1. Sorpresa n. 1. " 7" ha uno spazio prima del 7. Per parseInt lo spazio non è una cifra, quindi il testo non è un numero: NumberFormatException. Succede davvero quando l'utente scrive uno spazio di troppo.
  2. new int[0] crea un array con zero caselle: non esiste nemmeno l'indice 0. ArrayIndexOutOfBoundsException, "Index 0 out of bounds for length 0".
  3. Anche il resto (%) è una divisione: con gli int dividere per zero è impossibile. ArithmeticException: / by zero.
  4. Sorpresa n. 2. Con i double la divisione per zero non lancia eccezioni: il risultato è il valore speciale Infinity (infinito). Solo la divisione tra interi lancia ArithmeticException.
  5. "3.5" non è un numero intero, quindi Integer.parseInt lo rifiuta: NumberFormatException.
  6. Lo stesso testo con Double.parseDouble va benissimo: 3.5 è un double valido.

Cosa c'entra "l'eccezione è un oggetto"

Quando scrivi System.out.println(e), Java stampa l'oggetto eccezione: prima il nome completo della sua classe (java.lang.NumberFormatException) e poi, dopo i due punti, il suo messaggio. È proprio la classe che ti dice "che tipo di errore" è successo. Il catch (Exception e) qui li prende tutti perché Exception è la classe "madre" di quasi tutte le eccezioni.

try, catch e finally

Ripasso lampoNel try va il codice rischioso. Se una riga lancia un'eccezione, le righe successive del try vengono saltate e si passa al catch compatibile. Il finally si esegue sempre: con o senza errore, e anche se nel try c'è un return. Dopo, il programma prosegue normalmente. Teoria: try, catch e finally.
03Dividere il conto in pizzeria facile

Consegna. Un conto di 60 euro va diviso tra gli amici di tre tavoli diversi: int[] persone = {4, 0, 7}; (al secondo tavolo, per sbaglio, è stato scritto 0). Per ogni tavolo calcola con la divisione intera quanto paga ognuno e quanti euro avanzano. Se il calcolo è impossibile stampa un messaggio, senza far fermare il programma. Dopo ogni tavolo, che il calcolo sia riuscito o no, stampa -- tavolo controllato. Alla fine stampa Fine serata.

Output atteso:

4 persone: 15 euro a testa, avanzano 0 euro
-- tavolo controllato
0 persone: impossibile dividere il conto
-- tavolo controllato
7 persone: 8 euro a testa, avanzano 4 euro
-- tavolo controllato
Fine serata
Soluzione spiegata

Ragionamento

  1. La divisione tra int per zero lancia ArithmeticException: metto i calcoli nel try e nel catch (ArithmeticException e) stampo il messaggio.
  2. "Che il calcolo sia riuscito o no" è la descrizione esatta del finally: ci metto la stampa -- tavolo controllato.
  3. Il try-catch-finally sta dentro il ciclo: così l'errore del secondo tavolo riguarda solo quel giro e il ciclo arriva al terzo tavolo.

Codice

public class DividiConto {
    public static void main(String[] args) {
        int conto = 60;
        int[] persone = {4, 0, 7};

        for (int p : persone) {
            try {
                int quota = conto / p;
                int avanzo = conto % p;
                System.out.println(p + " persone: " + quota + " euro a testa, avanzano " + avanzo + " euro");
            } catch (ArithmeticException e) {
                System.out.println(p + " persone: impossibile dividere il conto");
            } finally {
                System.out.println("-- tavolo controllato");
            }
        }
        System.out.println("Fine serata");
    }
}

Perché funziona

  • Con p = 0 l'errore nasce già in conto / p: le due righe dopo (avanzo e la stampa) vengono saltate e si va dritti al catch.
  • Il finally stampa la sua riga tre volte: due volte dopo un try andato bene, una volta dopo il catch.
  • "Fine serata" compare perché l'eccezione è stata gestita: dopo il catch e il finally il programma riprende normalmente.

Errori da evitare

  • Usare double per conto e persone: 60.0 / 0 non lancia nessuna eccezione (dà Infinity) e il catch non scatterebbe mai.
  • Mettere avanzo fuori dal try: anche conto % p è una divisione per zero e farebbe fermare il programma.
04try dentro o fuori dal ciclo? medio

Consegna. I due frammenti sommano gli stessi dati. L'unica differenza è dove sta il try. Scrivi l'output di entrambi e spiega perché le somme sono diverse.

A · try dentro il ciclo

String[] dati = {"12", "7b", "30"};
int somma = 0;
for (String s : dati) {
    try {
        somma += Integer.parseInt(s);
        System.out.println("aggiunto " + s);
    } catch (NumberFormatException e) {
        System.out.println("scartato " + s);
    }
}
System.out.println("somma = " + somma);

B · try fuori dal ciclo

String[] dati = {"12", "7b", "30"};

try {
    for (String s : dati) {
        somma += Integer.parseInt(s);
        System.out.println("aggiunto " + s);
    }
} catch (NumberFormatException e) {
    System.out.println("dato non valido, mi fermo");
}
System.out.println("somma = " + somma);
Soluzione spiegata

Ragionamento

La regola da applicare è una sola: quando una riga del try lancia un'eccezione, si esce da tutto il blocco try e si va al catch. La domanda quindi è: cosa c'è dentro il try?

  • In A il try contiene un solo giro: uscire dal try vuol dire finire quel giro. Poi il ciclo continua con il dato successivo.
  • In B il try contiene tutto il ciclo: uscire dal try vuol dire abbandonare il ciclo. I dati rimasti non vengono mai letti.

Output di A

aggiunto 12
scartato 7b
aggiunto 30
somma = 42

Output di B

aggiunto 12
dato non valido, mi fermo
somma = 12

Perché le somme sono diverse

  • In A: 12 viene sommato, "7b" viene scartato, il ciclo prosegue e somma anche 30. Totale 42.
  • In B: 12 viene sommato, "7b" lancia l'eccezione, si salta al catch e il ciclo è finito. 30 non viene mai letto: totale 12.
  • In entrambi i casi la riga somma = ... viene stampata: l'eccezione è gestita, quindi dopo il catch il programma prosegue.
Quale scegliere?Dipende da cosa vuoi: A se un dato sbagliato va saltato e gli altri vanno elaborati comunque; B se un dato sbagliato rende inutile tutto il resto (per esempio un file rovinato) e conviene fermarsi subito.
05Il finally batte anche il return difficile

Consegna. Prevedi l'output, riga per riga. Due domande guida: il finally viene eseguito anche quando nel try c'è un return? E la scritta risultato: compare prima o dopo le stampe del metodo?

public class FinallyReturn {

    static int prova(int x) {
        System.out.println("entro con " + x);
        try {
            int r = 100 / x;
            System.out.println("calcolato " + r);
            return r;
        } catch (ArithmeticException e) {
            System.out.println("catch");
            return -1;
        } finally {
            System.out.println("finally");
        }
    }

    public static void main(String[] args) {
        System.out.println("risultato: " + prova(4));
        System.out.println("risultato: " + prova(0));
    }
}
Soluzione spiegata

Ragionamento

  1. Nel main, per stampare "risultato: " + prova(4) Java deve prima conoscere il valore di prova(4). Quindi esegue tutto il metodo e solo alla fine stampa la riga del main.
  2. prova(4): stampa "entro con 4", calcola 100 / 4 = 25, stampa "calcolato 25" e incontra return r. Prima di uscire davvero dal metodo, però, Java esegue il finally: stampa "finally". Poi il valore 25 torna al main, che stampa "risultato: 25".
  3. prova(0): stampa "entro con 0"; 100 / 0 lancia ArithmeticException, quindi "calcolato" e il primo return vengono saltati. Nel catch stampa "catch" e arriva a return -1; di nuovo, prima di uscire, il finally stampa "finally". Il main riceve -1.

Output

entro con 4
calcolato 25
finally
risultato: 25
entro con 0
catch
finally
risultato: -1

Da ricordare

  • Il finally si esegue sempre, anche se il try o il catch stanno uscendo dal metodo con un return. Per questo è il posto giusto per chiudere un file: qualunque strada prenda il metodo, il file viene chiuso.
  • Il return "prenota" il valore da restituire, poi gira il finally, poi il metodo finisce davvero.
  • L'unica eccezione alla regola è fermare tutto il programma (per esempio System.exit(0)).

L'oggetto Exception e più catch

Ripasso lampoNel catch (TipoEccezione e) la variabile e contiene l'oggetto eccezione: println(e) stampa tipo e messaggio, e.getMessage() solo il messaggio. Un try può avere più catch: Java sceglie il primo compatibile, quindi vanno messi dal più specifico al più generico, con Exception in fondo. Teoria: L'oggetto Exception e più catch.
06e, getMessage o un messaggio tuo? facile

try {

    System.out.println(n);
} catch (NumberFormatException e) {
    System.out.println(e);
    System.out.println(e.getMessage());
    System.out.println("Scrivi un numero intero, senza virgola");
}

int[] voti = {7, 8, 6};
try {
    System.out.println(voti[3]);

    System.out.println(e.getMessage());
}

07Il quiz che non si lascia ingannare medio

Consegna. Scrivi un quiz con tre risposte possibili, memorizzate in String[] risposte = {"Roma", "Milano", "Napoli"};. Il programma mostra la domanda e le risposte numerate da 1 a 3, poi legge da tastiera (con Scanner e nextLine()) il numero scelto e dice se è giusto. Deve continuare a chiedere finché la scelta non è valida, distinguendo due errori con due catch diversi:

  • l'utente scrive qualcosa che non è un numero → "due" non è un numero;
  • l'utente scrive un numero che non corrisponde a nessuna risposta → Il numero deve essere tra 1 e 3.

Vincolo: non controllare l'intervallo con un if: lascia che sia l'array a lanciare l'eccezione.

Se l'utente scrive, una riga alla volta, due, 5, 0 e infine 1, l'output atteso è:

Qual è la capitale d'Italia?
1) Roma
2) Milano
3) Napoli
Scegli il numero:
"due" non è un numero
Scegli il numero:
Il numero deve essere tra 1 e 3
Scegli il numero:
Il numero deve essere tra 1 e 3
Scegli il numero:
Roma: giusto!

(Nella console vera vedresti anche quello che scrive l'utente, sotto ogni "Scegli il numero:".)

Soluzione spiegata

Ragionamento

  1. Leggo la risposta come testo con nextLine() e la converto con Integer.parseInt: se non è un numero lancia NumberFormatException.
  2. L'utente conta da 1, l'array da 0: la risposta scelta è risposte[scelta - 1]. Se scelta è 5 l'indice è 4, se è 0 l'indice è -1: in tutti e due i casi l'indice non esiste e Java lancia ArrayIndexOutOfBoundsException.
  3. Due errori diversi, due reazioni diverse: quindi due catch, uno per tipo.
  4. Per ripetere la domanda uso un while con una variabile fatto. La riga fatto = true sta in fondo al try: si arriva lì solo se le righe prima non hanno lanciato eccezioni.

Codice

import java.util.Scanner;

public class Quiz {
    public static void main(String[] args) {
        String[] risposte = {"Roma", "Milano", "Napoli"};
        Scanner in = new Scanner(System.in);

        System.out.println("Qual è la capitale d'Italia?");
        for (int i = 0; i < risposte.length; i++) {
            System.out.println((i + 1) + ") " + risposte[i]);
        }

        boolean fatto = false;
        while (!fatto) {
            System.out.println("Scegli il numero:");
            String testo = in.nextLine();
            try {
                int scelta = Integer.parseInt(testo);
                String r = risposte[scelta - 1];
                if (scelta == 1) {
                    System.out.println(r + ": giusto!");
                } else {
                    System.out.println(r + ": sbagliato!");
                }
                fatto = true;
            } catch (NumberFormatException e) {
                System.out.println("\"" + testo + "\" non è un numero");
            } catch (ArrayIndexOutOfBoundsException e) {
                System.out.println("Il numero deve essere tra 1 e " + risposte.length);
            }
        }
        in.close();
    }
}

Prova a mano con l'input dell'esempio

dueparseInt("due") fallisceNumberFormatException
5parse ok, ma risposte[4] non esisteArrayIndexOutOfBoundsException
0parse ok, ma risposte[-1] non esisteArrayIndexOutOfBoundsException
1risposte[0] è "Roma": giusto, fatto = truenessuno

Da notare

  • Con più catch, Java prova il primo; se il tipo non corrisponde passa al successivo. Viene eseguito un solo catch.
  • testo è dichiarata prima del try: così si può usare anche nel catch per ripetere all'utente cosa ha scritto. Una variabile dichiarata dentro il try nel catch non esiste.
  • Il vincolo serve per esercitarsi: in un programma vero un if (scelta < 1 || scelta > risposte.length) sarebbe altrettanto valido (ne parliamo più avanti, in "prevenire invece di catturare").
08Quale catch scatta? medio

Consegna. Il metodo prova viene chiamato con i casi 0, 1, 2 e 3. Per ogni caso di' se si verifica un'eccezione, di quale tipo, e quale catch (A, B o C) viene eseguito. Poi scrivi l'output completo.

public class QualeCatch {

    static void prova(int caso) {
        int[] v = {10, 20};
        String s = null;
        try {
            System.out.print("caso " + caso + ": ");
            if (caso == 1) {
                System.out.println(v[0] / 0);
            }
            if (caso == 2) {
                System.out.println(v[2]);
            }
            if (caso == 3) {
                System.out.println(s.length());
            }
            System.out.println("nessun errore");
        } catch (ArithmeticException e) {
            System.out.println("A");
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("B");
        } catch (Exception e) {
            System.out.println("C");
        } finally {
            System.out.println("   fine caso " + caso);
        }
    }

    public static void main(String[] args) {
        for (int c = 0; c <= 3; c++) {
            prova(c);
        }
    }
}

Perché le righe sono fatte così

  • "caso " + caso + ": " è stampata con print (senza andare a capo) prima dell'istruzione rischiosa, quindi compare sempre. La lettera del catch finisce sulla stessa riga.
  • Quando c'è un'eccezione, "nessun errore" viene saltato: dopo l'errore il resto del try non si esegue.
  • Il finally gira in tutti e quattro i casi.
  • Il catch con Exception è la rete di sicurezza: prende gli errori che non avevamo previsto, come il null del caso 3. Deve stare per ultimo.
09Trova l'errore: due catch che non compilano difficile

Consegna. Nessuno dei due programmi compila, anche se a prima vista sembrano corretti. Trova l'errore, spiega il messaggio del compilatore e correggi.

A (indizio: NumberFormatException è "figlia" di IllegalArgumentException)

public class OrdineCatch {
    public static void main(String[] args) {
        try {
            int n = Integer.parseInt("dieci");
            System.out.println(n);
        } catch (IllegalArgumentException e) {
            System.out.println("Argomento non valido");
        } catch (NumberFormatException e) {
            System.out.println("Non è un numero");
        }
    }
}

B

import java.io.IOException;

public class CatchInutile {
    public static void main(String[] args) {
        try {
            int[] v = {1, 2, 3};
            System.out.println(v[1]);

            System.out.println("Problema con il file");

Soluzione spiegata

A · il catch generico sta prima di quello specifico

riga 8: error: exception NumberFormatException has already been caught

Le eccezioni sono organizzate a famiglie: NumberFormatException è un caso particolare di IllegalArgumentException ("argomento non valido": il testo passato a parseInt è un argomento sbagliato). Quindi il primo catch prende già anche le NumberFormatException, e il secondo non potrebbe mai essere raggiunto. Il compilatore lo dice: "exception NumberFormatException has already been caught" (è già stata catturata).

Correzione: dal più specifico al più generico.

public class OrdineCatchOk {
    public static void main(String[] args) {
        try {
            int n = Integer.parseInt("dieci");
            System.out.println(n);
        } catch (NumberFormatException e) {
            System.out.println("Non è un numero");
        } catch (IllegalArgumentException e) {
            System.out.println("Argomento non valido");
        }
    }
}
Non è un numero

B · un catch per un'eccezione impossibile

riga 8: error: exception IOException is never thrown in body of corresponding try statement

IOException è un'eccezione checked (lo vediamo nella prossima sezione): per queste il compilatore sa esattamente quali istruzioni possono lanciarle. Nel try c'è solo un array, niente file: un'IOException lì dentro non può mai nascere, e il compilatore considera quel catch un errore ("is never thrown in body of corresponding try statement" = non viene mai lanciata nel corpo del try).

Correzione: catturare l'eccezione che può davvero succedere, cioè ArrayIndexOutOfBoundsException (oppure togliere il try-catch, visto che v[1] esiste).

Da ricordare

  • Ordine dei catch: figlia prima, madre dopo. Altri esempi di coppie: FileNotFoundException prima di IOException; qualunque eccezione prima di Exception.
  • Con le eccezioni checked il compilatore controlla in tutte e due le direzioni: ti obbliga a catturarle quando possono succedere e ti vieta di catturarle quando non possono succedere.

Checked e unchecked exceptions

Ripasso lampoLe unchecked (figlie di RuntimeException: ArithmeticException, NullPointerException, ArrayIndexOutOfBoundsException, NumberFormatException…) di solito sono errori di programmazione e il compilatore non obbliga a gestirle. Le checked (IOException, FileNotFoundException…) vengono dal mondo esterno: il compilatore obbliga a gestirle con try-catch o a dichiararle con throws. Teoria: Checked e unchecked exceptions.

11Il diario che non compila medio

Consegna. Questo programma dovrebbe aggiungere una pagina al file diario.txt, ma non compila.

import java.io.FileWriter;

public class Diario {
    static void scriviPagina(String testo) {
        FileWriter w = new FileWriter("diario.txt", true);
        w.write(testo + "\n");
        w.close();
    }

    public static void main(String[] args) {
        scriviPagina("Oggi verifica di Java");
    }
}
  1. Qual è l'errore e perché il compilatore lo segnala?
  2. Correggilo in due modi diversi: (1) il metodo dichiara l'eccezione e la gestisce il main; (2) il metodo la gestisce da solo e restituisce true se è riuscito a scrivere, false altrimenti.
Soluzione spiegata

1 · L'errore

riga 5: error: unreported exception IOException; must be caught or declared to be thrown

new FileWriter(...) (ma anche write e close) può lanciare IOException: il disco potrebbe essere pieno, la cartella protetta… È un'eccezione checked, quindi il compilatore pretende una scelta: o la catturi (try-catch) o la dichiari (throws). Il metodo non fa nessuna delle due, e il compilatore si ferma alla prima riga che la può lanciare (la 5).

2 · Correzione 1: throws, gestisce il main

  1. Aggiungo throws IOException nella firma di scriviPagina: il metodo avvisa "posso fallire, ci pensa chi mi chiama".
  2. Ora è il main a chiamare un metodo che lancia una checked: tocca a lui scegliere. Lo metto in un try-catch.
  3. Serve anche import java.io.IOException;.
import java.io.FileWriter;
import java.io.IOException;

public class DiarioThrows {
    static void scriviPagina(String testo) throws IOException {
        FileWriter w = new FileWriter("diario.txt", true);
        w.write(testo + "\n");
        w.close();
    }

    public static void main(String[] args) {
        try {
            scriviPagina("Lunedì: verifica di Java");
            scriviPagina("Martedì: interrogazione di storia");
            System.out.println("Pagine salvate");
        } catch (IOException e) {
            System.out.println("Impossibile scrivere il diario: " + e.getMessage());
        }
    }
}
Pagine salvate

Contenuto di diario.txt alla fine:

Lunedì: verifica di Java
Martedì: interrogazione di storia

3 · Correzione 2: il metodo gestisce da solo

  1. Il try-catch va dentro scriviPagina, quindi non serve più throws e chi chiama non è obbligato a fare nulla.
  2. Però chi chiama vuole sapere se la scrittura è riuscita: il metodo restituisce un boolean. Il return true sta in fondo al try (ci si arriva solo se tutto è andato bene), il return false nel catch.
import java.io.FileWriter;
import java.io.IOException;

public class DiarioCatch {
    static boolean scriviPagina(String testo) {
        try {
            FileWriter w = new FileWriter("diario.txt", true);
            w.write(testo + "\n");
            w.close();
            return true;
        } catch (IOException e) {
            System.out.println("Pagina non salvata: " + e.getMessage());
            return false;
        }
    }

    public static void main(String[] args) {
        if (scriviPagina("Mercoledì: gita")) {
            System.out.println("Pagina salvata");
        }
    }
}
Pagina salvata

Quale scegliere?

Chiediti: chi sa cosa fare se la scrittura fallisce? Se la risposta dipende da chi usa il metodo (mostrare un errore, riprovare, chiudere il programma), meglio throws. Se il metodo può decidere da solo, meglio il try-catch interno. Esiste anche una terza via, la più sbrigativa: public static void main(String[] args) throws IOException. Compila, ma se il file non si può scrivere il programma si ferma con lo stack trace: va bene per le prove, non per un programma da consegnare.

12Prevenire invece di catturare medio

Consegna. Questo programma funziona, ma usa try-catch per errori che si possono evitare con un semplice controllo. Riscrivilo senza nessun try-catch, usando degli if, in modo che produca esattamente lo stesso output.

public class Catturare {

    static void mostra(int[] v, int pos) {
        try {
            System.out.println("Elemento " + pos + ": " + v[pos]);
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Posizione " + pos + " inesistente");
        }
    }

    static void media(int[] v) {
        try {
            int somma = 0;
            for (int x : v) {
                somma += x;
            }
            System.out.println("Media intera: " + somma / v.length);
        } catch (ArithmeticException e) {
            System.out.println("Array vuoto, niente media");
        }
    }

    public static void main(String[] args) {
        int[] voti = {6, 8, 7};
        int[] vuoto = {};
        mostra(voti, 1);
        mostra(voti, 3);
        mostra(voti, -1);
        media(voti);
        media(vuoto);
    }
}

Output (uguale per le due versioni):

Posizione -1 inesistente
Media intera: 7
Array vuoto, niente media
Soluzione spiegata

Ragionamento

  1. Le due eccezioni sono ArrayIndexOutOfBoundsException e ArithmeticException: entrambe unchecked, cioè errori che dipendono dal nostro codice. Per ognuna mi chiedo: in quale situazione precisa nasce?
  2. v[pos] fallisce quando pos è fuori da 0…length - 1. La condizione "posizione valida" è quindi pos >= 0 && pos < v.length. Servono tutte e due le parti: -1 è minore di 3 ma non è valido.
  3. somma / v.length fallisce solo quando v.length è 0. Lo controllo all'inizio del metodo e, se l'array è vuoto, stampo il messaggio ed esco con return (in un metodo void si può usare return; senza valore per uscire subito).

Codice

public class Prevenire {

    static void mostra(int[] v, int pos) {
        if (pos >= 0 && pos < v.length) {
            System.out.println("Elemento " + pos + ": " + v[pos]);
        } else {
            System.out.println("Posizione " + pos + " inesistente");
        }
    }

    static void media(int[] v) {
        if (v.length == 0) {
            System.out.println("Array vuoto, niente media");
            return;
        }
        int somma = 0;
        for (int x : v) {
            somma += x;
        }
        System.out.println("Media intera: " + somma / v.length);
    }

    public static void main(String[] args) {
        int[] voti = {6, 8, 7};
        int[] vuoto = {};
        mostra(voti, 1);
        mostra(voti, 3);
        mostra(voti, -1);
        media(voti);
        media(vuoto);
    }
}

Output

Elemento 1: 8
Posizione 3 inesistente
Posizione -1 inesistente
Media intera: 7
Array vuoto, niente media

Perché è meglio così

  • Si legge meglio: l'if dice chiaramente quale situazione stai controllando.
  • È la regola del capitolo: le unchecked "si prevengono scrivendo codice corretto", per esempio con if (b != 0).
  • Con i file invece non funziona allo stesso modo: anche se controlli con exists() che il file c'è, un attimo dopo qualcuno può cancellarlo o il disco può riempirsi. Per questo le checked vanno comunque gestite con try-catch o throws.

throw e throws

Ripasso lampothrow new TipoEccezione("messaggio") lancia un'eccezione adesso: il metodo si interrompe subito. throws TipoEccezione nella firma dichiara che il metodo può lanciarla e lascia il problema a chi lo chiama. L'eccezione "risale" la catena delle chiamate finché qualcuno la cattura; se arriva oltre il main, il programma si ferma. Teoria: throw e throws.
13Il registro che rifiuta i voti impossibili facile

Consegna. Scrivi il metodo static void registra(int voto): se il voto non è tra 1 e 10 deve lanciare una IllegalArgumentException con un messaggio che contiene il voto sbagliato; altrimenti stampa Registrato: e il voto. Nel main prova a registrare i voti {7, 11, 9, 0, 6}, stampa i messaggi dei voti rifiutati e alla fine quanti voti sono stati registrati.

Output atteso:

Registrato: 7
Rifiutato: il voto 11 non è tra 1 e 10
Registrato: 9
Rifiutato: il voto 0 non è tra 1 e 10
Registrato: 6
Voti registrati: 3 su 5
Soluzione spiegata

Ragionamento

  1. Il controllo va all'inizio del metodo: se il dato è sbagliato non ha senso fare altro. throw interrompe il metodo, quindi la riga Registrato non viene eseguita e non serve un else.
  2. throw new IllegalArgumentException(...): new crea l'oggetto eccezione (con il suo messaggio), throw lo lancia.
  3. Nel main catturo l'eccezione dentro il ciclo, così un voto sbagliato non blocca i successivi. Il messaggio scritto nel throw lo recupero con e.getMessage().
  4. Il contatore registrati++ sta nel try dopo registra(v): se il voto è rifiutato, l'eccezione lo fa saltare.

Codice

public class RegistraVoto {

    static void registra(int voto) {
        if (voto < 1 || voto > 10) {
            throw new IllegalArgumentException("il voto " + voto + " non è tra 1 e 10");
        }
        System.out.println("Registrato: " + voto);
    }

    public static void main(String[] args) {
        int[] voti = {7, 11, 9, 0, 6};
        int registrati = 0;
        for (int v : voti) {
            try {
                registra(v);
                registrati++;
            } catch (IllegalArgumentException e) {
                System.out.println("Rifiutato: " + e.getMessage());
            }
        }
        System.out.println("Voti registrati: " + registrati + " su " + voti.length);
    }
}

Da notare

  • registra non ha throws nella firma: IllegalArgumentException è unchecked, quindi non è obbligatorio dichiararla.
  • Il messaggio scritto nel throw è quello che getMessage() restituisce: chi lancia l'eccezione decide cosa c'è scritto, chi la cattura lo legge.
  • Perché lanciare un'eccezione invece di stampare "voto sbagliato" dentro il metodo? Perché così chi chiama sa che qualcosa è andato storto e può reagire (qui: non contare il voto).
14L'eccezione che risale medio

Consegna. Il main chiama a, che chiama b, che chiama c. Solo c può lanciare l'eccezione e solo a ha un try-catch. Prevedi l'output.

public class Risale {

    static void c(int n) {
        System.out.println("  c inizia");
        if (n < 0) {
            throw new IllegalArgumentException("n negativo: " + n);
        }
        System.out.println("  c finisce");
    }

    static void b(int n) {
        System.out.println(" b inizia");
        c(n);
        System.out.println(" b finisce");
    }

    static void a(int n) {
        System.out.println("a inizia");
        try {
            b(n);
            System.out.println("a: tutto ok");
        } catch (IllegalArgumentException e) {
            System.out.println("a ha catturato: " + e.getMessage());
        }
        System.out.println("a finisce");
    }

    public static void main(String[] args) {
        a(5);
        System.out.println("---");
        a(-2);
        System.out.println("main finisce");
    }
}

Domanda in più: cosa cambierebbe se a non avesse il try-catch?

Soluzione spiegata

Ragionamento

  1. a(5): nessun errore. Ogni metodo stampa "inizia", chiama il successivo e, quando quello ha finito, stampa "finisce". Le chiamate si chiudono in ordine inverso: prima finisce c, poi b, poi a.
  2. a(-2): a, b e c stampano "inizia". In c la condizione n < 0 è vera e parte il throw: c si interrompe ("c finisce" saltato).
  3. c non ha un catch, quindi l'eccezione risale a chi l'ha chiamato, cioè b. Nemmeno b ce l'ha: anche b si interrompe ("b finisce" saltato) e l'eccezione risale ad a.
  4. a aveva chiamato b dentro un try: l'eccezione viene catturata, "a: tutto ok" viene saltato e si esegue il catch. Da lì in poi tutto è normale: "a finisce" e "main finisce".

  c inizia
  c finisce

a finisce
---

  c inizia

E senza il try-catch in a?

L'eccezione salirebbe ancora: da a al main, e dal main fuori dal programma. Il programma si fermerebbe con Exception in thread "main" java.lang.IllegalArgumentException: n negativo: -2, e né "a finisce" né "main finisce" verrebbero stampati per la seconda chiamata.

Un paragoneL'eccezione è come un reclamo in un'azienda: l'impiegato (c) non sa risolverlo e lo passa al suo capo (b), che lo passa al direttore (a). Il primo che ha un catch per quel tipo di problema lo risolve, e gli altri tornano al lavoro.
15throws con i file: contare le righe difficile

Consegna. Nella cartella del programma ci sono poesia.txt (quattro righe, ognuna chiusa da un "a capo") e vuoto.txt (vuoto); assente.txt invece non esiste. Scrivi:

  • static int contaRighe(String nomeFile): legge il file carattere per carattere con FileReader e restituisce quanti '\n' contiene;
  • static void salvaRisultato(String riga): aggiunge la riga in fondo al file report.txt.

Vincolo: i due metodi non devono contenere try-catch: gli errori li gestisce il main, che prova i tre file e distingue "file che non esiste" da "altro errore di input/output".

Output atteso:

poesia.txt fatto
assente.txt non esiste, lo salto
vuoto.txt fatto

Contenuto di report.txt alla fine:

poesia.txt: 4 righe
vuoto.txt: 0 righe
Soluzione spiegata

Ragionamento

  1. new FileReader, read, close, new FileWriter, write possono lanciare eccezioni checked. Visto che i metodi non devono avere try-catch, l'unica alternativa è dichiararle: throws IOException.
  2. Basta dichiarare IOException, anche se new FileReader lancia FileNotFoundException: la seconda è un caso particolare della prima, quindi è già "compresa".
  3. Per contare le righe uso lo schema di lettura del capitolo sui file: leggo un carattere prima del ciclo, ripeto finché non trovo -1 e rileggo alla fine di ogni giro. Ogni volta che il carattere è '\n' (l'a capo) aumento il contatore. Si può confrontare un int con un char: Java usa il codice del carattere.
  4. Nel main tutti e due i metodi stanno nello stesso try, con due catch: prima FileNotFoundException (specifica), poi IOException (generale). Al contrario non compilerebbe.

Codice

import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class ContaRighe {

    static int contaRighe(String nomeFile) throws IOException {
        FileReader lettore = new FileReader(nomeFile);
        int righe = 0;
        int c = lettore.read();
        while (c != -1) {
            if (c == '\n') {
                righe++;
            }
            c = lettore.read();
        }
        lettore.close();
        return righe;
    }

    static void salvaRisultato(String riga) throws IOException {
        FileWriter scrittore = new FileWriter("report.txt", true);
        scrittore.write(riga + "\n");
        scrittore.close();
    }

    public static void main(String[] args) {
        String[] nomi = {"poesia.txt", "assente.txt", "vuoto.txt"};
        for (String nome : nomi) {
            try {
                int n = contaRighe(nome);
                salvaRisultato(nome + ": " + n + " righe");
                System.out.println(nome + " fatto");
            } catch (FileNotFoundException e) {
                System.out.println(nome + " non esiste, lo salto");
            } catch (IOException e) {
                System.out.println(nome + ": errore di lettura o scrittura");
            }
        }
    }
}

Perché l'output è così

  • poesia.txt: 4 "a capo", quindi 4 righe. Il risultato viene scritto nel report.
  • assente.txt: new FileReader lancia FileNotFoundException già nella prima riga di contaRighe. L'eccezione risale al main: salvaRisultato e "fatto" vengono saltati, quindi nel report non c'è nessuna riga per questo file.
  • vuoto.txt: esiste ma è vuoto. Il primo read() restituisce subito -1, il ciclo non parte e il metodo restituisce 0. Non è un errore!

Per migliorare

Se un errore capitasse durante la lettura (dopo l'apertura), lettore.close() verrebbe saltato e il file resterebbe aperto. La versione più sicura mette la chiusura in un finally:

FileReader lettore = new FileReader(nomeFile);
try {
    // ... ciclo di lettura ...
} finally {
    lettore.close();   // eseguito sempre
}

Il try-finally senza catch è permesso: l'eccezione non viene catturata (continua a risalire grazie al throws), ma prima il file viene chiuso. Lo useremo nell'esercizio completo.

Passo 2 · La classe Prodotto e il throw

Il costruttore è il posto perfetto per i controlli: se i dati sono sbagliati l'oggetto non deve nemmeno nascere. I controlli stanno all'inizio; il throw interrompe il costruttore, quindi le assegnazioni con this non vengono eseguite e new Prodotto(...) non restituisce nessun oggetto. Il messaggio contiene il nome del prodotto e il valore sbagliato, così chi lo legge capisce subito cosa correggere.

Passo 3 · leggiRiga: lasciar risalire le unchecked

leggiRiga fa tre cose rischiose: legge riga[2] (la riga potrebbe essere corta), converte i testi in numeri (potrebbero non essere numeri) e crea il prodotto (il costruttore potrebbe rifiutarlo). Non sa però cosa fare in caso di errore: decide il main. Non mette quindi nessun try-catch, e siccome sono tutte unchecked non serve nemmeno throws: risalgono da sole.

Passo 4 · Il ciclo degli ordini: quattro catch nell'ordine giusto

Riga per riga, ecco cosa succede:

2Pizzetta, 1.25, treparseInt("tre") fallisceNumberFormatException

L'ordine dei catch è la parte delicata: NumberFormatException è figlia di IllegalArgumentException, quindi deve stare prima (altrimenti non compila, come nell'esercizio 09). Exception sta in fondo come rete di sicurezza per gli errori non previsti, come la riga null. Il finally conta le righe controllate: gira sia per quelle valide sia per quelle scartate, quindi alla fine vale 8.

Un dettaglio furbo: scrivo carrello[n] = leggiRiga(...) e dopo n++. Se leggiRiga lancia un'eccezione, l'assegnazione non avviene e n++ viene saltato: la casella resta libera per il prossimo prodotto valido. Così nel carrello i 3 prodotti validi stanno nelle caselle 0, 1, 2, senza buchi.

Passo 5 · I metodi sui file: throws e try-finally

salvaScontrino e stampaFile usano FileWriter e FileReader, che lanciano eccezioni checked: la consegna dice che non le gestiscono, quindi le dichiarano con throws IOException. Però devono chiudere il file in ogni caso: apro il file, poi metto il lavoro in un try e la close() nel finally. Non c'è nessun catch: se qualcosa va storto, il finally chiude il file e poi l'eccezione continua a risalire verso il main.

Perché l'apertura sta prima del try? Se fallisse proprio l'apertura, non ci sarebbe nessun file da chiudere: il metodo si interrompe e basta.

Passo 6 · La parte finale del main

Il salvataggio e la prima stampa vanno bene. La seconda chiamata a stampaFile prova ad aprire scontrino_di_ieri.txt: new FileReader lancia FileNotFoundException, che risale fino al main. "Tutto fatto" viene saltato, scatta il primo catch e infine il finally stampa "Cassa chiusa.". Anche qui il catch specifico (FileNotFoundException) sta prima di quello generale (IOException).

I conti dello scontrino: 2 × 2.5 = 5.0, 4 × 0.75 = 3.0, 1 × 2.25 = 2.25, totale 10.25. (I prezzi sono stati scelti "tondi" in binario, come 0.25 e 0.75, apposta per evitare risultati tipo 10.250000000000002 che a volte capitano con i double.)

Codice completo

import java.io.FileNotFoundException;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

class Prodotto {
    String nome;
    double prezzo;
    int quantita;

    Prodotto(String nome, double prezzo, int quantita) {
        if (prezzo <= 0) {
            throw new IllegalArgumentException("prezzo non valido per " + nome + ": " + prezzo);
        }
        if (quantita < 1) {
            throw new IllegalArgumentException("quantità non valida per " + nome + ": " + quantita);
        }
        this.nome = nome;
        this.prezzo = prezzo;
        this.quantita = quantita;
    }

    double totale() {
        return prezzo * quantita;
    }
}

public class Cassa {

    // unchecked: niente throws, le eccezioni risalgono da sole a chi chiama
    static Prodotto leggiRiga(String[] riga) {
        String nome = riga[0];
        double prezzo = Double.parseDouble(riga[1]);
        int quantita = Integer.parseInt(riga[2]);
        return new Prodotto(nome, prezzo, quantita);
    }

    // checked: FileWriter può lanciare IOException, la dichiaro con throws
    static void salvaScontrino(String nomeFile, Prodotto[] carrello, int n) throws IOException {
        FileWriter scrittore = new FileWriter(nomeFile);
        try {
            double totale = 0;
            for (int i = 0; i < n; i++) {
                Prodotto p = carrello[i];
                scrittore.write(p.quantita + " x " + p.nome + " = " + p.totale() + " euro\n");
                totale += p.totale();
            }
            scrittore.write("TOTALE: " + totale + " euro\n");
        } finally {
            scrittore.close();
        }
    }

    static void stampaFile(String nomeFile) throws IOException {
        FileReader lettore = new FileReader(nomeFile);
        try {
            int c = lettore.read();
            while (c != -1) {
                System.out.print((char) c);
                c = lettore.read();
            }
        } finally {
            lettore.close();
        }
    }

    public static void main(String[] args) {
        String[][] ordini = {
            {"Panino", "2.50", "2"},
            {"Pizzetta", "1.25", "tre"},
            {"Succo", "1.50"},
            {"Acqua", "0.75", "4"},
            {"Brioche", "-1.00", "1"},
            {"Cioccolata", "1.50", "0"},
            null,
            {"Toast", "2.25", "1"},
        };

        // ---------- parte 1: controllo degli ordini ----------
        Prodotto[] carrello = new Prodotto[ordini.length];
        int n = 0;
        int controllate = 0;
        for (int i = 0; i < ordini.length; i++) {
            try {
                carrello[n] = leggiRiga(ordini[i]);
                n++;
            } catch (NumberFormatException e) {
                System.out.println("Riga " + (i + 1) + ": numero non valido (" + e.getMessage() + ")");
            } catch (IllegalArgumentException e) {
                System.out.println("Riga " + (i + 1) + ": " + e.getMessage());
            } catch (ArrayIndexOutOfBoundsException e) {
                System.out.println("Riga " + (i + 1) + ": manca un dato");
            } catch (Exception e) {
                System.out.println("Riga " + (i + 1) + ": errore imprevisto, riga saltata");
            } finally {
                controllate++;
            }
        }
        System.out.println("Righe controllate: " + controllate + ", prodotti validi: " + n);

        // ---------- parte 2: scontrino su file ----------
        try {
            salvaScontrino("scontrino.txt", carrello, n);
            System.out.println("Scontrino salvato:");
            stampaFile("scontrino.txt");
            stampaFile("scontrino_di_ieri.txt");
            System.out.println("Tutto fatto");
        } catch (FileNotFoundException e) {
            System.out.println("Lo scontrino di ieri non esiste");
        } catch (IOException e) {
            System.out.println("Errore con i file: " + e.getMessage());
        } finally {
            System.out.println("Cassa chiusa.");
        }
    }
}

Il file scontrino.txt creato dal programma:

2 x Panino = 5.0 euro
4 x Acqua = 3.0 euro
1 x Toast = 2.25 euro
TOTALE: 10.25 euro

Controlla di aver capito

  • Perché leggiRiga non ha throws e stampaFile sì? (Le eccezioni di leggiRiga sono tutte unchecked; quelle dei file sono checked e il compilatore obbliga a gestirle o dichiararle.)
  • Cosa succede se scambi i catch di NumberFormatException e IllegalArgumentException? (Non compila: "exception NumberFormatException has already been caught".)
  • Se tolgo il catch (Exception e), cosa succede alla riga 7? (La NullPointerException non viene catturata da nessuno, risale oltre il main e il programma si ferma: il Toast non viene mai letto. Il finally però viene eseguito comunque prima della fine.)
  • Perché "Tutto fatto" non compare ma "Cassa chiusa." sì? (Dopo l'eccezione il resto del try viene saltato; il finally invece si esegue sempre.)
  • Se il carrello fosse vuoto (n = 0), lo scontrino avrebbe solo la riga del totale. Come faresti a rifiutarlo con un throw? (Per esempio all'inizio di salvaScontrino: if (n == 0) throw new IllegalArgumentException("carrello vuoto");.)
